# Аппаратная индикация HC7000

Блок `boards/hc7000/uj11_diagnostics.v` подключён к MMU-конфигурации
HC7000. Он читает состояние CPU и сигнал выбора SD, не использует EBR,
микрокод или прошивку SERV. HC1200 и HC7000/MMU-less не изменены.

## Электрическое подключение

На установленной плате отсутствуют токоограничивающие резисторы.
Реализован обходной режим: **во всём индикаторе одновременно светится
не больше одного сегмента**, включая обе точки. Это исключает сложение
токов нескольких сегментов на общем аноде. Заполнение каждого сегмента
фиксировано на 1/64 и не зависит от количества сегментов в букве.

В MMU-сборке с `HC7000_DIAGNOSTICS=1` все 18 выводов индикаторов получают
`DRIVE=4 SLEWRATE=SLOW`. Для LVCMOS33 значение 4 — минимальная настройка
нагрузочной способности, согласно [Lattice sysIO, таблица 3.2](https://www.latticesemi.com/view_document?document_id=39083).
Она не является ограничителем тока 4 мА. Посегментное сканирование и
малое заполнение также не ограничивают пиковый ток отдельного LED;
электрическая допустимость на этой плате пока не подтверждена измерением.

По умолчанию сохраняется `HC7000_DIAGNOSTICS=0`: оба общих вывода выключены,
катоды A–G/DP выставлены в единицу. Включение явно выбирает экспериментальный
посегментный режим. Для гарантированного ограничения тока нужны резисторы
или внешний драйвер. Общая разводка HC7000 и ограничения других портов
не меняются; DRIVE/SLEWRATE добавляются только в генерируемый LPF этой сборки.

Разводка соответствует `Z-pdaXrom-TV/hardware-lcd`: в каждом из портов
`seg_led_h/l[8:0]` бит 8 — активный высокий общий анод, бит 7 — DP,
биты 6…0 — активные низкие G…A. Сканер обходит левый A…DP, затем правый
A…DP, включая пустые позиции. У невыбранного разряда все катоды высокие
и анод выключен. Для каждого сегмента выполняются четыре фазы:
гашение обоих анодов, установка одного катода, импульс анода, гашение.
Катоды меняются только при уже выключенных общих выводах; между сменой
катода и включением анода выдерживается отдельный интервал.

## Коды и приоритет

| Код | Условие |
|---|---|
| `r5` | Аппаратный reset, включая начальную очистку SRAM |
| `HL` | ODT после исполнения HALT в kernel mode |
| `0d` | ODT по кнопке, STEP или аварийному входу |
| `--` | WAIT; также зарезервированный режим PSW=2 |
| `SY` | Kernel, PSW[15:14]=0 |
| `SU` | Supervisor, PSW[15:14]=1 |
| `U5` | User, PSW[15:14]=3 |

Строки перечислены в порядке приоритета. S выглядит как 5, O — как 0.
HALT и ODT не являются независимыми режимами: HALT входит в микрокодную
консоль. Дополнительный бит CPU запоминает причину остановки. Команды ODT
и ошибки чтения из консоли сохраняют `HL`; продолжение, STEP и reset
сбрасывают причину. Новый выполненный HALT снова устанавливает `HL`.
Привилегированный HALT вне kernel вызывает обычную ловушку, а не `HL`.

Короткая кнопка показывает `0d` после фактического входа в консоль.
При долгом нажатии `r5` появляется после штатного порога около двух секунд
и остаётся на время аппаратного reset. Сам сканер сбрасывается только
сигналом power-on, поэтому удерживаемая кнопка его не останавливает.
Инструкция PDP-11 RESET не сбрасывает сканер и не показывает `r5`.

Левая точка отмечает завершение гостевых инструкций, правая — активный
SD CS, включая обмен, инициализацию и ожидание программирования карты.
Это не индикатор завершения запроса дискового контроллера. Импульсы
растягиваются примерно до 100 мс; постоянная активность держит точку
включённой. Работа самого ODT не зажигает точку CPU.

Фазы идут с частотой около 32 кГц. Один импульс — около 31,25 мкс,
полный кадр из 16 позиций по четыре фазы — около 2 мс (500 Гц).
На 50 МГц делитель равен 1562: импульс 31,24 мкс, кадр 1,99936 мс.
На 24 МГц делитель 750 даёт ровно 31,25 мкс и 2 мс.
Обе буквы и точки фиксируются вместе на кадр. Быстрые переключения
kernel/user отображаются выборкой текущего состояния, не статистикой
загрузки. Обновление обоих разрядов завершается не позднее чем за два
кадра (4 мс). Таймер удержания точек делит частоту фаз на 32 и сохраняет
длительность около 100 мс.

## Сборка и проверки

Из каталога `uJ11-fpga`, для экспериментального посегментного режима:

```sh
make CPU=mmu BOARD=hc7000-lcd-sram FPP=off IOP=storage \
    MMU_CLOCK_MHZ=50 HC7000_DIAGNOSTICS=1 synthesis
```

Параметр допускает только 0/1 и только MMU-профиль HC7000. В имя
стандартного выходного каталога добавляется `-diagnostics`. Для прямого
запуска Python используется `UJ11_HC7000_DIAGNOSTICS=1`; значение записано
в manifest и в сгенерированный top-level, участвующий в проверке хешей.
При нуле синтез удаляет сканер и неиспользуемые диагностические сигналы.

```sh
make CPU=mmu BOARD=hc7000-lcd-sram test-diagnostics
UJ11_MMU_FPP=off UJ11_MMU_CLOCK_MHZ=50 python3 tools/test_mmu.py
python3 -m unittest discover -s tests -p 'test_mmu_profiles.py'
```

Тест индикаторов восстанавливает буквы и точки по реальным выходам за
полный кадр, проверяет заполнение 1/64 каждого сегмента, коды, приоритеты,
работу при удерживаемом reset и растяжение точек. На каждом такте проверены
не более одного выбранного катода на обоих разрядах вместе, соответствие
анода выбранному сегменту и гашение при смене катодов. Power-on проверен
в каждой из 64 фаз кадра. Использованы ускоренные делители 1, 24 и 50
тактов на фазу сканирования.
CPU-регрессия проверяет HALT, STEP, CONTINUE, кнопку во время WAIT,
ошибки ODT и аварийный вход, а также устойчивый уровень WAIT при
конвейерной подготовке операндов на 50 МГц.

Первоначальная сборка с целым разрядом `diagnostics-50-01`,
LCMXO2-7000HC-4TG144C, FPP off, IOP storage (до посегментного режима):

| Ресурс | Предыдущая сборка `134fabc` | С индикацией |
|---|---:|---:|
| LUT4 | 4239 | 4346 (+107) |
| FF | 1441 | 1494 (+53) |
| EBR | 26 | 26 |
| Слова микрокода | 1162 | 1162 |
| Fmax после трассировки | 51,148 МГц | 50,538 МГц |

MAP/PAR/TRACE проходят заданные 50 МГц и ограничения внешней SRAM.
Контрольная сборка `diagnostics-off-50-01` с выключенным блоком также
проходит 50 МГц: 4238 LUT, 1441 FF, 26 EBR, Fmax 50,487 МГц.
Таким образом, включение относительно той же версии с параметром 0
стоит 108 LUT и 53 FF; относительно предыдущего релиза — 107 LUT и 53 FF.
Для первоначального варианта проверены 45 сценариев состояния/активности,
полный набор MMU/CPU/ODT на 50 МГц без FPP и на 24 МГц с FPP,
13 проверок MMU-профилей и две проверки инвентаря плат.
Контрольные суммы исходников HC1200
совпадают с ранее выпущенной сборкой.

включая внешнюю SRAM. Все 18 выводов в итоговом `.pad` имеют
`DRIVE:4mA SLEW:SLOW`.

Относительно прошитого релиза `134fabc` вся индикация стоит 146 LUT
и 70 FF. SERV, микрокод и CPU не менялись при переходе к одному сегменту.
Прошли 48 проверок полного кадра и заполнения, 192 проверки сброса в
разных фазах, непрерывная проверка одного выбранного сегмента,
Verilator lint без предупреждений, 14 тестов MMU-профилей и два теста
инвентаря плат. Отдельный тест проверяет, что электрические ограничения
меняют ровно 18 выводов и только при включённой индикации.

`build/diagnostics-single-50-01/impl1/diagnostics-single-50-01_impl1.jed`.

### Проверка на плате, 29 сентября 2026

JED `9DF6` записан во Flash HC7000. Diamond Programmer выполнил
`FLASH Erase,Program,Verify` и сообщил `Operation: successful`.
Журнал программатора сохранён в
`build/diagnostics-hardware/programming/`.

Проверка UART и индикации начата заново с единственным читателем UART;
перед аппаратным reset BSD выполнила `sync`. После reset плата дошла
через меню SD и RL0 до приглашения `70Boot`.

* При удержании reset пользователь наблюдал `r5`; после отпускания — `U5`.
  Для вторичного загрузчика BSD это ожидаемо: прочитанный в ODT
  `PSW=140344` означает User mode, `PC=014360`. Ожидать здесь `SY` неверно.
* Короткая кнопка дала `0d`, подтверждено пользователем.
* Тестовый HALT из RAM по адресу `020000` дал `HL`, подтверждено
  пользователем; ODT показал `PC=020002`, `PSW=000340`.
* STEP выполнил `INC R0`: ODT показал `R0=000001`, `PC=020004`.
  Переход `HL` → `0d` после STEP подтверждён пользователем.
* WAIT по адресу `020006`, при `PSW=000340`, дал `--` без точки CPU.
  Короткая кнопка вернула `0d`; ODT показал `PC=020010`, `PSW=000340`.
  Оба показания индикатора подтверждены пользователем.

После теста выполнен длинный reset и повторная загрузка
`rl(0,0)rlunix`. BSD 2.9.1 показала `mem = 1979072`, перешла в
многопользовательский режим и смонтировала `/usr` с `/dev/xp0h`.
Выполнены вход под `root`, `pwd`, `ls /usr`, `cat /etc/fstab` и `sync`;
все команды вернули приглашение shell. В `fstab` подтверждены RL0 для
корня, XP0h для `/usr` и RL1 для swap. Сохранённые настройки дополнительных
терминалов остались без изменений; при запуске init сообщил `cannot open`
для отсутствующих `/dev/tty00`…`/dev/tty07`.

Плата оставлена в shell `root`, UART освобождён, `ISTRIP` восстановлен
для отображения программной чётности BSD. Итоговые `session.json`,
`uart.bin` и нормализованный `uart.txt` сохранены в
`build/diagnostics-hardware/retest/`. Поле `test_scope` отделяет
визуально подтверждённые состояния от непроверенных и поясняет две ошибки
управляющего сценария; они не являлись сбоями FPGA.

Коды `SY`/`SU` и точка SD отдельно визуально не проверялись;
для reset подтверждён код, состояние точек во время удержания отдельно
не проверено.

Тестовая программа загружена в RAM после остановки загрузчика;
дисковые образы она не меняет. Функциональная проверка индикации
не измеряет пиковый ток LED или выводов FPGA.
