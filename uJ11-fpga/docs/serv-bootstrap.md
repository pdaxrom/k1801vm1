# HC7000: загрузчик J11 в прошивке SERV

2026-10-01. Реализовано для `CPU=mmu FPP=off IOP=storage`, с PAL и без него.
На этом этапе на плате оставалась 2AAE, 13-КиБ конфигурация не прошивалась.
Теперь перенос загрузчика входит в установленную **7CBA**;
[текущая память и ресурсы](synthesis.md#hc7000-установленная-7cba).

Ниже описан промежуточный вариант на 13 КиБ. После объединения секторного
буфера и оптимизации EBR текущие исходники используют
[19 КиБ общей памяти](serv-19k.md), из которых 18,5 КиБ доступны прошивке.
Порядок установки загрузчика остаётся прежним.

Отдельный EBR загрузочного ROM передан памяти SERV: **12 → 13 КиБ**.
Проверенный PDP-11 загрузчик `firmware/boot/SDIOP.MAC` (430 байт) собирается
в массив `bootstrap.h` вместе с прошивкой SERV. Его команды, меню на SD,
проверки CRC и интерфейс загрузки контроллеров не меняются.

## Порядок запуска

1. SRAM заканчивает аппаратную инициализацию, затем стартует SERV.
2. J11 удерживается в reset отдельным сигналом `cpu_start`; шина, SERV
   и секторный DMA уже работают.
3. `firmware/storage/bootstrap.c` через существующий DMA записывает 215 слов
   по физическим адресам `004000…004655` (восьмеричные байтовые адреса).
4. Только после завершения всех записей SERV устанавливает `CPU_START`
   (`0x40000304`, bit 0). J11 стартует с `004000` и исполняет код из SRAM.
5. SERV продолжает прежнюю инициализацию SD и обслуживание контроллеров.
   J11 ожидает результат через существующий регистр `177504`.

При ошибке копирования SERV не разрешает запуск частично записанного кода.
Аппаратный RESET сбрасывает SERV и разрешение запуска J11, поэтому загрузчик
восстанавливается, даже если ОС использовала эту область SRAM. Команда PDP-11
`RESET` сбрасывает периферию, но не переустанавливает загрузчик и не портит
память работающей ОС. После старта область загрузчика остаётся обычной памятью;
нового постоянного резерва SRAM этот перенос не создаёт.

В `IOP=storage` отдельный boot ROM и его наложение на SRAM удаляются синтезом.
Сигнал `boot_complete` сохраняет прежний смысл: переход из загрузочного
окружения к загрузке выбранного диска. HC1200, MMU-less и загрузочный ROM
профиля `IOP=legacy` сохранены.

## Память и ресурсы

Первые 12 КиБ SERV сохраняют организацию с 32-битным доступом. Дополнительный
1 КиБ занимает один 512×16 EBR: каждое 32-битное обращение выполняется двумя
16-битными операциями, а подтверждение выдаётся после их завершения.
Поддерживаются все четыре разрешения записи байтов. В этой сборке в последнем
банке находится стек; обращения к нему требуют дополнительных тактов.
Частота J11 не меняется; влияние на скорость реальных ОС отдельно не измерялось.

| Показатель | Установленная 2AAE | Новая конфигурация |
|---|---:|---:|
| SERV RAM | 12 КиБ / 12 EBR | 13 КиБ / 13 EBR |
| Отдельный boot ROM | 1 EBR | 0 |
| Всего EBR | 26/26 | **26/26** |
| LUT4 | 4911 | **4942** |
| FF | 1791 | 1838 |
| CPU / PAL | 50 / 64 МГц | **50 / 64 МГц** |

Код и константы SERV с PAL — **11191 байт**, BSS — 976 байт,
стек — 640 байт, промежуток между BSS и стеком — **504 байта**.
Без PAL код и константы занимают 11183 байта. Набор контроллеров сохранён.

Полный MAP/PAR/TRACE `serv-bootstrap-50-01` проходит ограничения SRAM и CDC:
Fmax CPU **50,994 МГц**, PAL **64,990 МГц**, отрицательного slack нет.
Таким образом, перенос даёт место в SERV для загрузочного кода и последующих
расширений, но сам по себе не освобождает EBR. На этом этапе перенос регистров
SERV/PAR/PDR в LUT-память оставался отдельной задачей; затем он выполнен
в [19-КиБ реализации](serv-19k.md).

## Проверки

Отчёты и исходные данные сохраняются в
[`releases/hc7000-serv-bootstrap`](../history/releases/hc7000-serv-bootstrap/README.md).
Проверки охватывают модель памяти и официальные примитивы Lattice,
порядок разрешения старта J11, восстановление после аппаратного RESET,
сохранение памяти при гостевом RESET, меню SD и дисковые контроллеры.
Этот промежуточный 13-КиБ JED на плату не устанавливался. Загрузку с SERV
в текущем 19-КиБ варианте подтверждает [аппаратный релиз 7CBA](../releases/hc7000-ps2-idle/README.md).
