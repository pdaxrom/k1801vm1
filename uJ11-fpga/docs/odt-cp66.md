# CP66: точки останова, RUN TO и STEP OVER с прерываниями

Изменения только в PDP-11 программе ODT, загружаемой в HALT FRAM.
Аппаратные исходники CP63b проверяются по SHA256; RTL, microstore и FPGA
не изменены. CP66 установлен на плату, файлы на SD проверены обратным
чтением, ODT загружен и debug включён. [Аппаратный журнал](board-bringup-cp66.md).

## Команды

Адреса и числа ниже восьмеричные; `X` переключает числовой ввод в HEX.

| UART | Действие |
|---|---|
| `P addr` | Установить точку; до четырёх постоянных точек |
| `P` | Показать адреса установленных точек |
| `Z addr` | Снять одну точку |
| `Z` | Снять все точки; повторить восстановление после ошибки памяти |
| `U addr` | RUN TO: выполнить программу до адреса, затем снять временную точку |
| `T` | Для JSR выполнить подпрограмму до адреса возврата и исходного SP |
| `S` | STEP IN, прежний аппаратный одиночный шаг |
| `C` | Продолжить; если PC совпадает с точкой, исполнить оригинал один раз |
| `T limit` | Явно выбрать прежний ограниченный цикл STEP из CP65 |

`T` для команды, отличной от JSR, выполняет один STEP. Для вызова адрес
возврата вычисляется после всей команды, включая extension words. Проверка
SP исключает ложную остановку на внутреннем рекурсивном возврате. Если на том
же адресе задана постоянная точка, она имеет приоритет над временной.
`U` с текущим PC сразу возвращает результат, не исполняя команду.

Патчи разрешены только по **чётным адресам USER RAM `001000..157776`**.
Нулевой исходный opcode (HALT) не принимается. Пользователь выбирает именно
начало исполняемой команды своей программы; монитор не может автоматически
отличить её от операнда, данных, RT-11 overlay или области монитора RT-11.

В свободном RUN обычные IRQ и гостевой trace работают. Короткий RESET
останавливает выполнение, снимает временную точку и восстанавливает патчи;
постоянные определения остаются для следующего C. UART и клавиатура во время
RUN принадлежат гостю, поэтому отмена нового T/U через ESC не обещается.
`T limit` сохраняет прежнюю семантику: IRQ/trace отложены, WAIT/HALT останавливает
цикл, UART/новое нажатие панели отменяет его. Число `limit` — число шагов,
а не время; подробности прежнего режима в [CP65](odt-cp65.md).

## Пульт

Кнопка **9** вызывает новый `T` без лимита. 8, A–F, автопрокрутка, PREV/NEXT
дизассемблера и ожидание между регистрами работают как в CP65. Удержание 8/9
не выполняет второй шаг; цифры 8–F во время HEX-ввода остаются цифрами.

В меню MEM добавлены `BREAKPOINT SET`, `BREAKPOINT CLEAR`, `BREAKPOINT LIST`,
`BREAKPOINTS OFF`, `RUN TO ADDRESS`. PREV/NEXT выбирают пункт, ENTER открывает
ввод адреса или выполняет действие. ENTER подтверждает введённый адрес, MEM
отменяет ввод. Действие печатается в UART как `[PANEL] P/Z/U ...`, затем общий
обработчик выполняет его один раз. UART P выводит все адреса сразу; пульт
показывает последнюю строку списка. Просмотр регистров по одному с ожиданием
остался отдельным режимом пульта.

## Механизм и сохранность контекста

Выбран программный **HALT patch**, использующий уже существующий HALT банк.
Это уточнение первоначального предложения с BPT: не требуется USER trampoline
и перехват USER-вектора `000014`. Гостевые BPT/trace и их стековые кадры
обслуживаются исходными обработчиками. Даже нечётный гостевой SP не мешает
остановке на точке; монитор сохраняет GPR до перехода на собственный стек.

Таблица из четырёх постоянных и одной временной записи содержит адрес,
оригинальное слово и состояние. При приглашении ODT слова восстановлены.
Перед RUN исходные слова сверяются, записываются HALT с readback, затем
HALT-вектор `000170` временно переводится с resident `000200` на ENTER.
Неизвестный исходный вектор, PSW вектора или выключенный debug блокируют RUN
с точками. На входе снимаются все патчи и возвращается исходный вектор.

Свой HALT определяется по адресу CPC−2 и вооружённой записи **до** проверки
R4 на сигнатуру загрузчика `125061`. Сохранённый PC возвращается к оригинальной
команде. Далее существующий pending-debug/START переводит native HALT в
штатный debug-контекст без исполнения USER-команды. Искусственный HALT не
создаёт лишний гостевой trace при последующем CONTINUE.

Для C с PC на постоянной точке оригинал выполняется один раз через аппаратный
STEP, после чего патчи ставятся снова. Аналогично обходится внутренний возврат
рекурсии с несовпавшим SP. Только этот одиночный шаг использует прежнее
откладывание IRQ/trace; остальное выполнение T/U — обычный RUN.

Чужой сигнатурный HALT передаётся неизменённому resident после снятия патчей,
с исходными GPR/SP и служебным состоянием. Поэтому вызов UJLOAD не оставляет
активный hook в перезаписываемом модуле. Такой вызов **разоружает все точки**;
автоматическое перевооружение после загрузчика не выполняется. Чужой HALT
без сигнатуры останавливается в ODT с обычным PC после HALT.

## Ошибки и пределы

Патч восстанавливается только если память всё ещё содержит наш HALT или уже
восстановленный оригинал. Другой ненулевой opcode сохраняется, точка
отключается и выводится `?BP`. Восстановление HALT-вектора также сверяется чтением. При неудачной записи/проверке восстановления
запись сохраняет признак возможного патча. C/STEP и замена временной точки
не могут забыть такой адрес. После устранения причины повторить `Z` и проверить
память. Неудачная установка откатывает уже записанные патчи до запуска гостя.

Самомодифицирующийся код и overlays не являются поддерживаемой областью
постоянных точек. Запись того же значения HALT невозможно отличить от нашего
патча без аппаратного наблюдения; не ставить точки в изменяемые слова.
Нет поддержки невозвратного terminal fault самого CPU.

Длинный RESET/отключение питания завершает сеанс без программного cleanup.
FRAM сохраняет байты, включая возможные HALT-патчи; холодная загрузка не
восстанавливает старую сессию. Перед новым запуском загрузить программу заново,
вновь установить ODT/UJON и задать точки. Для нормальной остановки использовать
короткий RESET, для завершения сеанса — Z перед C.

## Ресурсы и воспроизведение

Payload **10 962 байт**, с данными и стеком **11 746 из 12 288 байт**;
свободно **542 байта**. ODT.BIN — 23 блока RT-11. Отдельный слот FP11
`040000..177777` остаётся прежним: 48 КиБ; FP11 здесь не реализуется.

Прирост FPGA **0 LUT / 0 FF / 0 EBR / 0 микрокоманд**. Последние реальные
аппаратные измерения — CP63b: 1230 LUT, 381 FF, 6 EBR, 1005 uwords,
TRACE Fmax 32,246 MHz; номинальная CPU/FRAM 29,56 MHz. Это не новый synthesis.

```sh
python3 tools/build_odt_cp64.py --out build/cp66-odt-new
python3 tools/check_odt_cp64.py --odt build/cp66-odt-new
python3 tools/test_odt_cp64.py --odt build/cp66-odt-new --out build/cp66-core-new
python3 tools/test_odt_cp66.py --odt build/cp66-odt-new --out build/cp66-bp-new
python3 tools/test_odt_cp65.py --cp66 --odt build/cp66-odt-new --out build/cp66-panel-new
python3 tools/run_odt_cp64.py --cp66 --odt build/cp66-odt-new --out build/cp66-rt11-new
```

Directed breakpoint-тест использует точный ранее собранный CP62 resident,
проверяя его hash; microasm11 не запускается. Нативный UJTEST собирается DEC
MACRO/LINK и проверяет реальный KW11-L, WAIT и чтение ODT.BIN через RT-11
LOOKUP/READW/CLOSE на полном стенде SD/FRAM. Исходный образ диска не изменяется.

Проверки окончательной программы:

| Стенд | Проверки | Микротакты |
|---|---:|---:|
| Прежний ODT, production synchronous ROM | 187 | 5 480 965 |
| Точки, IRQ/trace, loader, ошибки записи и восстановление | 112 | 4 026 367 |
| Матрица клавиатуры и HDSP, 85 окон | 2699 | 114 526 626 |
| Полный RT-11/FRAM/SD/KW11-L/UART/HDSP | 296 | 514 657 090 |

Это такты соответствующего тестового сценария, не benchmark производительности
одной команды и не измерение на физической плате. Тесты включают запись векторов
и опкодов с ошибками/readback, odd SP, сигнатурный R4, чужие BPT/HALT/trace,
WAIT/IRQ, рекурсию, самомодификацию, короткий RESET и восстановление временной
точки после отказа записи. Новый T/U не маскирует обычные IRQ на время RUN.

Для воспроизведения архива после успешного полного прогона:

```sh
python3 tools/archive_odt_cp64.py --cp66 \
  --odt build/cp66-odt-new --rt11 build/cp66-rt11-new \
  --core build/cp66-core-new --panel build/cp66-panel-new \
  --breakpoints build/cp66-bp-new
```

Скрипт сначала проверяет совпадение всех входных hashes и наличие успешных
результатов, затем сохраняет исходники, DEC listing/map, UART и RTL-логи
отдельно в `tb/reports/cp66`. Дисковые образы и microasm11 в source archive
не входят. Исторические архивы CP64/CP64a/CP65 не перезаписываются.

Полный финальный прогон **PASS**: 3038 UART bytes, 80 физических HDSP frames,
RX overrun=0 при прежнем проверенном темпе ~1,77 ms/символ. Пройдены загрузка
через UJLOAD, отклонение повреждённого модуля, стоп внутри RK firmware,
пульт, STEP OVER с KW11-L/WAIT, RT-11 LOOKUP/READW/CLOSE и IRQ, продолжение
гостя, повторный UJON и cold boot. Проверки не считаются физической установкой.

Автопрокрутка на полном FRAM-стенде: начальная пауза 30 924 216 тактов,
внутренний шаг 5 580 491 такт (~1046 и ~189 ms при 29,56 MHz); темп CP65 сохранён.
