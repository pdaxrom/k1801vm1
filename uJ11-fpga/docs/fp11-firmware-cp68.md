# CP68: первый программный модуль FP11(A)

2026-09-14. Загружаемый PDP-11 код исполняется в HALT FRAM на аппаратуре
CP67b. Это **управляющая часть будущего эмулятора**, пока без вычислений.
FP11.BIN не установлен на физическую плату. FIS остаётся в прежнем микрокоде;
MMU выключен. RTL, firmware EBR и microstore сохранены побайтно.

## Источник и граница совместимости

Используется DEC **EK-FP11A-UG-001, FP11-A Floating Point User's Manual**,
May 1978: §4.4, таблица 4-1 (FPS, печатные 4-7/4-8), §4.5 и таблица 4-2
(исключения, 4-8/4-9), §5.1 (AC0–AC5), таблица 5-1 и §5.7 (управление).
[Первичный скан DEC](https://bitsavers.trailing-edge.com/www.computer.museum.uq.edu.au/pdf/EK-FP11A-UG-001%20FP11-A%20Floating%20Point%20User%27s%20Manual.pdf).
SHA256 изученного PDF:
`be6446903afc3d6ca0e1b0efed85301853979e3a1c5631c8a6e707165c63ecf6`.
Это тот же документ, что зафиксирован в `verification-cp30.json`.

Поддерживаются **семь мнемоник, 21 точная кодировка**. Числа в следующей
таблице и адреса ниже восьмеричные.

| Команда | Opcode | Изменения |
|---|---|---|
| CFCC | 170000 | Только NZVC CPU получает младшие четыре бита FPS |
| SETF / SETD | 170001 / 170011 | Сброс / установка FD, FPS bit 7 |
| SETI / SETL | 170002 / 170012 | Сброс / установка FL, FPS bit 6 |
| LDFPS R0–R7 | 170100–170107 | FPS ← Rn AND 147757; неиспользуемые биты 13, 12, 4 нулевые |
| STFPS R0–R7 | 170200–170207 | Rn ← FPS; для R7 это изменение адреса продолжения |

У LDFPS R7 исходный PC указывает после opcode. Все команды, кроме CFCC,
сохраняют полный PSW CPU; CFCC меняет только NZVC. Успешные команды не
используют USER stack, в том числе при нечётном SP. AC0–AC5 и сохранённые
FEC/FEA ими не изменяются.

**Memory modes LDFPS/STFPS, STST, LDF/STF, арифметика и преобразования ещё
не реализованы.** Остальные `17xxxx` этот прототип обрабатывает как
неподдерживаемый opcode: FER=1, FEC=2, FEA=адрес opcode; FID подавляет
переход по USER-вектору 244, но не запись ошибки. Это поведение прототипа
также распространяется на корректные, пока не реализованные команды:
его нельзя считать полным FP11 или использовать для запуска произвольной
программы с плавающей точкой. После появления полной ISA такие команды
получат своё документированное поведение.

Исторический CP30 реализовывал семь управляющих команд аппаратно и добавлял
35 LUT / 1 FF, доводя тогдашнюю плату до 1265 LUT. Он был удалён из активной
сборки в CP31. CP68 использует готовый вход HALT-службы;
[история CP30](fp11a.md) не является описанием нынешнего модуля.

## Размещение и запуск

`firmware/fp11/FP11.MAC` собирается настоящими DEC MACRO/LINK через существующий
`rt11_build.py`. `microasm11` не используется и не изменяется. Модуль
**абсолютный**, relocation пока нет, формат файла CP67 version 2 / ABI 3.

| Область | Адреса / размер |
|---|---|
| INIT и неизменяемый код | 040000–040707, 456 байт / 228 PDP-11 слов |
| FPS / FEC / FEA | 040710 / 040712 / 040714 |
| AC0–AC5, по четыре слова | 040716–040775, 48 байт |
| Сохранённые R0–R7, PSW | 040776–041017, 18 байт |
| Прежний fault vector и scratch | 041020–041033 |
| Частный stack | 041034–041233, 128 байт |
| Вся аллокация | 040000–041233, **668 байт** |
| Свободный непрерывный остаток до I/O page | 041234–157777, **40 292 байта** |

FP11.BIN занимает два RT-11 блока: 512-byte header и 456 байт кода с нулевым
padding. Checksum — сумма 228 слов по модулю 65536, `134521` (47441 decimal).
Mutable state, включая FPS и AC, находится вне checksum; все его 106 слов
очищаются и проверяются при каждом cold init. Таблица модулей хранит длину
неизменяемого образа: диапазон **до MEMEND** нужно резервировать отдельно при
размещении других модулей, как и для ODT. Автоматического BSS allocator нет.

Cold walker проверяет запись и код, вызывает BASE с `JSR PC` в HALT bank.
INIT проверяет CP67 marker и UJSTAT, очищает BSS, записывает с readback
HALT-вектор `010/012 = ENTER/340`, затем включает FP-ready, сохраняя ODT/debug
ready. Он возвращает R0=0 через RTS PC; ошибка проверки возвращает R0=1.
Стандартный walker владеет fault vector на протяжении этого вызова.

При FP opcode аппаратный вход сохраняет CPC/CPSW в HALT `100/102` и вызывает
вектор `010`. ENTER сохраняет общие R0–R6, PC/PSW и переходит на частный stack.
Opcode перечитывается через MFUS из USER[CPC−2]. Эта версия предполагает
исполнение из обычной стабильной RAM; fetch из volatile I/O не поддерживается.
После команды модуль восстанавливает прежний HALT fault vector, CPC/CPSW,
регистры и выполняет START. IRQ, trace и запрос пульта принимаются после
возврата. Копирование opcode в отдельный аппаратный регистр не добавлялось.

Ошибка USER-чтения переводится в обычный USER bus trap 004. FP exception
строит USER-frame PSW, PC и читает vector 244. На время исполнения установлен
собственный HALT fault handler; затем восстанавливаются оба прежних слова
004/006. Повторная ошибка при построении trap frame терминальна: ядро
останавливается в HALT bank, не выдавая её за успешное продолжение гостя.

## Проверки и воспроизведение

Запускать из корня `uJ11-fpga` последовательно:

```sh
python3 tools/test_fp11_cp68.py
python3 tools/test_fp11_cp68.py --mode logic --stride 257
python3 tools/test_fp11_cp68.py --mode vendor --stride 257
python3 tools/test_fp11_events_cp68.py
python3 tools/test_fp11_events_cp68.py --vendor
python3 tools/test_fp11_board_cp68.py
python3 tools/run_fp11_rt11_cp68.py --out build/cp68-fp11/rt11-new
```

Первый вызов собирает FP11 и точную аппаратную модель CP67; следующие используют
те же build inputs. Нужны Verilator, Icarus, Lattice vendor models для vendor
прохода, C compiler, SIMH `pdp11`, штатный `lsi11/rt11tool` и исходный RT-11
образ `lsi11-fpga/images/rt11v503.dsk`. Инструменты работают с частными копиями
диска. `--out` для полного RT-11 теста должен быть новым каталогом.

Эталон управляющих команд — существующий `core/pdp11_fp.c`, включённый через
`core/core.c`, с фиксированными hashes. Он используется только для перечисленных
команд, не как доказательство совпадения всех FP11-A arithmetic exceptions.
Полный sync проход: **90 112 cases / 5 857 280 checks**, включая все 65536
входных значений LDFPS, сочетания FPS/PSW и R0–R7, задержки ACK 0–3 clocks.
Logic и vendor DP8KC повторяют каждый 257-й вектор: **351 / 22 815** каждый.
Directed sync/vendor: **28 cases / 1008 checks** каждый: полный PSW,
нечётный SP, unsupported/FID, vector/frame, failed opcode reread, double fault,
IRQ, RTT/T, trace before IRQ и запрос debug внутри FP. Отдельно проверяются
все 24 слова AC и восстановление прежнего fault vector.

Полная SPI FRAM модель: **4 scenarios / 318 checks**. Настоящие ODT, FP11,
SDBOOT инициализируются в обоих порядках; повторный reset после загрязнения
BSS восстанавливает defaults. Плохой FP checksum не выключает ODT. Окно ESC
ускорено двумя константами только в тестовом firmware ROM; производственный
ROM не изменён. Тест не заменяет электрические измерения на плате.

Полный RT-11/UJMOD/ODT проход: **24 checks / 460 895 201 clocks / 1982 UART
bytes — PASS**. RT-11 установила ODT/SDBOOT/FP11, после reset все три записи
получили `140407`. Через UART ODT пошагово исполнены SETD, SETL, STFPS R1
с проверкой PC и FPS; затем FPTST штатно завершилась в RT-11, прошёл DIR.
Повторный reset очистил FPS без переустановки. OFF2 и следующий reset
отключили только FP, сохранив ODT. Номер 2 относится к порядку установки в
данном тесте, произвольную пользовательскую таблицу сначала нужно прочитать.
Результаты и SHA256 находятся в
[архиве CP68](../tb/reports/cp68/archive.json). Это симуляция полноценной платы,
включая SPI SD/FRAM и проверку UART waveform, а не аппаратная установка.

## Скорость и ресурсы

Числа ниже измерены на модели с прежним SPI FRAM controller. Интервал: от
первого USER opcode request до окончания START с восстановленным USER context.
Bus beats — CPU memory transactions, не количество SPI bytes.

| Команда | Ideal RAM clocks, ACK=0 | SPI FRAM clocks | Bus beats | µs при 29,56 MHz |
|---|---:|---:|---:|---:|
| CFCC | 783 | 8527 | 134 | 288,464 |
| SETF | 747 | 8145 | 128 | 275,541 |
| SETI | 771 | 8337 | 131 | 282,037 |
| SETD | 795 | 8529 | 134 | 288,532 |
| SETL | 819 | 8721 | 137 | 295,027 |
| LDFPS Rn | 925 | 9677 | 152 | 327,368 |
| STFPS Rn | 923 | 9553 | 150 | 323,173 |

Ideal RAM начало берётся на границе START тестового bootstrap, перед первым
USER fetch; на SPI — при первом запросе opcode. Поэтому это разные модели
интерфейса, а не вычисленная добавка только от задержек памяти.
На SPI вход до первого opcode request FP handler занимает **316 clocks**;
от opcode request START до восстановления USER context — **177 clocks**.
Эти интервалы включают fetch и отличаются от старого CP57 microentry accounting.
Этот первый вариант сохраняет весь контекст и ещё не оптимизировался по числу
обращений к FRAM. Скорость FP-арифметики пока не измерялась.

Сверка всех 53 обычных файлов synthesis manifest CP67b дала точное совпадение.
Нового синтеза нет: **1244 LUT / 381 FF / 7 EBR / TRACE Fmax 32,032 MHz** —
прежний результат CP67b. Прирост FP11 firmware: **0 LUT / 0 FF / 0 EBR /
0 microinstructions**. Microstore остаётся 1005/1024, nominal CPU/FRAM 29,56 MHz.
На FPGA свободны прежние 36 LUT и 0 EBR; развитие FP11 идёт в FRAM.

Следующий этап — полноценные addressing modes LDFPS/STFPS и STST, затем
LDF/STF и форматы AC, после них арифметика и дифференциальные проверки с
FP11-A правилами округления/исключений. Имена файлов и адреса рабочих данных
CP68 пока не являются замороженным ABI для будущего полного эмулятора.
