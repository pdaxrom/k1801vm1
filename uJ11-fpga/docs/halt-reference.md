# ВМ2: HALT, системная память и программная FIS

Справочные сведения о КМ1801ВМ2, изученные 2026-09-12 при выборе
служебного пространства uJ11. Это описание ВМ2, не спецификация текущего
процессора; реализованные отличия приведены в [архитектуре uJ11](architecture.md).

Основной локальный источник — [KM1801VM2.pdf](../../doc/KM1801VM2.pdf),

## Адресное пространство (стр. 1–4, 10)

У КМ1801ВМ2 восьмёрка R0–R7, 9-битный PSW и две дополнительные копии:
CPC (16 бит) и CPSW (9 бит). В PSW бит 8 H/U выбирает USER=0 или HALT=1.
Бит 7 P задаёт маскирование; это не 3-битный IPL J-11. Для EVNT/VIRQ
установленный P запрещает приём, а взаимодействие HALT/ACLO зависит также от H/U.

Адресная шина остаётся 16-битной. При адресном обмене HALT процессор
выдаёт активный низкий SEL. Внешняя логика может использовать SEL как
признак другого банка RAM/ROM. Пространства могут не пересекаться, давая
до 64 КиБ USER + 64 КиБ HALT; физическая схема памяти определяется платой.
Это не линейная адресация 128 КиБ одной обычной программой и не MMU.

SEL имеет вторую функцию: при безадресном чтении процессор получает
внешнее конфигурационное слово, также называемое регистром SEL. Не путать
значение этого слова с уровнем вывода или с битом H/U. Его старший байт
задаёт базу системных векторов, бит 7 сообщает об отсутствии эмулятора FIS.

## CPC/CPSW и вход без стека (стр. 11, 15–16, 36)

Копии следуют PC/PSW, пока H/U=0 или P=0. Когда H/U=P=1, они заморожены.
У CPSW уточнение: обновление следует изменению PSW, а не просто каждому такту.
Обработчик должен начинаться с H/U=P=1, чтобы сохранить контекст предыдущего
USER процесса. Вход из уже замороженного состояния не создаёт новую копию.

При HALT-входе нет автоматических PUSH PC/PSW и нет сохранения всех R0–R7
в память. R0–R6, включая SP, остаются общими. Монитор сам сохраняет используемые
регистры и старый SP в HALT-память, прежде чем установить собственный SP.
Поэтому вход не требует исправного стека USER, а отдельного большого RF нет.

HALT-процедура принудительно выбирает HALT-пространство для чтения пары
новых PC/PSW. Окончательный режим задаётся загруженным PSW (все 9 бит).
Вектор формируется как `(SEL & 0xFF00) | offset`, где offset — младший байт:

| Событие | Смещение, восьмеричное |
|---|---:|
| Начальный пуск | 000 |
| Ошибка обмена в HALT | 004 |
| Эмуляция FIS | 010 |
| Команда HALT или внешний HALT | 170 |
| Двойная ошибка обмена | 174 |
| Ошибка при приёме вектора | 274 |

Для описанной УКНЦ SEL=`160000` (восьмерично): HALT читает новый PC из
`160170`, новый PSW из `160172` **HALT-памяти**. Обычные USER-прерывания
имеют другой путь: USER bank, стек и обычный вектор. Эти пути не смешивать.

## Команды HALT (стр. 41–43)

Числа команд ниже восьмеричные; диапазоны включают описанные в документе
алиасы. Исполнение этих команд в USER вызывает reserved trap `000010`.

| Команда | Код | Действие |
|---|---|---|
| START | 000010–000013 | PC←CPC, PSW←CPSW, затем обычная проверка прерываний |
| STEP | 000014–000017 | То же, но пропускает проверку прерываний перед первой командой |
| RSEL | 000020 | R0←внешний SEL |
| MFUS | 000021 | R0←USER[R5], затем R5←R5+2 |
| RCPC | 000022–000023 | R0←CPC |
| RCPS | 000024–000027 | R0←CPSW |
| MTUS | 000031 | R5←R5−2, затем USER[R5]←R0 |
| WCPC | 000032–000033 | CPC←R0 |
| WCPS | 000034–000037 | CPSW←R0 |

MFUS/MTUS выполняют один **словный** обмен в USER, затем возвращают HALT
для дальнейшего исполнения. У них фиксированы регистры R0/R5, нет выбора
произвольных EA. Condition codes сохраняются. MFUS при ошибке всё равно
увеличивает R5 на 2, сохраняет старый R0 и идёт через HALT error `SEL004`;
MTUS сохраняет предварительное уменьшение R5 и также использует HALT error.

START/STEP работают с замороженными копиями. STEP не означает автоматическую
установку T: для описанного пошагового режима удерживается внешний HALT,
тогда после первой команды процессор снова входит через `SEL170`.

Обычные RTI/RTT не эквивалентны START: они восстанавливают из стека, а загрузка
H/U у них зависит от нового PC (`>=160000`); MTPS вообще не изменяет H/U и T.

## Эмуляция FIS (стр. 38, 41)

Коды `075000..075037` не выполняют арифметику микрокодом КМ1801ВМ2.
Процессор читает внешний SEL:

- SEL[7]=0: вход по `SEL010` в программу эмуляции в HALT-памяти.
- SEL[7]=1: эмулятор отсутствует, обычный reserved trap `000010`.

В описанной УКНЦ обработчик начинается по `165612`, эмулирует FADD/FSUB/FMUL/FDIV
для 32-битного FIS. Это не реализация полного FP11. PC/PSW доступны через
замороженные копии; программа пользуется USER-доступами и подготавливает
возвращаемое состояние. Вложенная FIS из H/U=P=1 не создаёт свежий контекст.

## Применение в uJ11

uJ11 использует отдельный служебный режим и 16-битный CPSW, сохраняя
формат PSW J‑11. USER/HALT выбирает банк FRAM. Служебные команды с
фиксированными R0/R5 дают программам ODT/FPP доступ к USER-памяти;
контекст остальных регистров сохраняет firmware. FIS остаётся микрокодным,
а программный FPP имеет собственный service-вход.

Полная совместимость ВМ2 (H/P, tracking, SEL174/274 и вложенные входы)
не заявлена. Карта, векторы, RESET и ограничения текущего варианта —
в [архитектуре](architecture.md), интерфейс модулей — в [ABI](modules.md).
Исходное обсуждение и экспериментальные реализации — в [истории](../history/README.md).
