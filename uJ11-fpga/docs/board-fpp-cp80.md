# Установка CP80: PSW-операнды программного FPP J‑11

2026-09-19 установлен FP11.MAC **00.12** из [пакета CP80](../demos/rt11/service/cp80/README.md),
исходный коммит `ef92aa1997633fdc899c020cc0a96711b92e1e2e`.
На физической HC1200 проверены чтение/запись USER PSW через FPP,
самоинициализация модуля и прежняя арифметическая регрессия.
FPGA остаётся CP67b: JTAG, RTL, микрокод и FIS не менялись; MMU отключён.
ODT CP77, FPTST 00.09, SDBOOT и UJMOD сохранены от предыдущей установки.

## Установка и холодный старт

Хост `sash@192.168.1.108`, рабочий каталог
`/tmp/uj11-cp80-hardware-20260919`, UART `/dev/ttyUSB1`, 115200 8N1.
Существующий picocom PID 217518 временно приостанавливался на время
каждого UART-сеанса и возобновлялся в cleanup. HG работал на 1000 Hz.

Последовательность в RT‑11:

```text
LOAD HG
COPY DK:FP11.BIN HG:OLDFP.BIN
COPY HG:FP11.BIN DK:FP11.BIN
COPY DK:FP11.BIN HG:FPCHK.BIN
UNLOAD HG
RUN UJMOD
FP11
```

Исходный CP79 сохранён как `OLDFP.BIN`; его SHA256 совпал с пакетом CP79.
Обратная копия `FPCHK.BIN` побайтно совпала с новым FP11.BIN: **5120 байт**,
SHA256 `9cab00b3ecad2e4cb2fea5a3c89cd9810a199cc195a6a2e454758f9e734d7f30`.
После `UNLOAD HG` собственный hgfsd остановлен, пины пульта освобождены.
UJMOD сообщил `!UJMOD-I-DONE`.

Таблица после регистрации и после подтверждённого пользователем длинного
RESET без ESC (поля восьмеричные: base, слова, checksum, status):

| Слот | Модуль | Base / слова / checksum | До RESET | После RESET |
|---|---|---|---|---|
| 0 | ODT CP77 | `010000 014233 134145` | `140407` | `140407` |
| 1 | SDBOOT | `006000 000342 053365` | `140407` | `140407` |
| 2 | FPP CP80 | `060000 004174 142034` | `140403` | `140407` |

Переход FPP в `140407` подтверждает принятую checksum и успешный initializer.
Таймерный UART-захват закончился до нажатия: свежий boot banner **не записан**.
Доказательства этого cold init — подтверждённый RESET и прочитанная после
него таблица, а не пустой файл `08-cold-boot/uart.bin`.

Размещение FPP: 4344 байта immutable code/data, 4614 байт вместе с BSS/stack,
`060000..071006` exclusive, **+96 байт** к CP79. FPS находится в `070370`,
FEC `070372`, FEA `070374`, AC0–AC5 с `070376`; ODT читает descriptor,
поэтому пересобирать монитор для нового размещения не потребовалось.

## Проверка PSW на плате

`RUN FPTST` остановился в предусмотренном цикле `001216`. Пользователь
коротко нажал RESET. Пассивное окно `11-odt-enter` к этому времени тоже
закончилось; вход подтверждён последующим UART-приглашением `ODT>` и
чтением контекста. Ответ `?SYNTAX OR RANGE` на пустую пробную команду
ожидаем и не означает ошибку теста.

Перед пробой сохранены R0–R7, PSW и **39 слов USER RAM `006000..006114`**.
В этот участок через ODT записана программа из 22 FP-инструкций и
завершающего `BR .`; все слова прочитаны обратно и сверены.
Сначала установлены `PSW=000340`, `PC=006000`.
Каждая инструкция выполнялась отдельным `S`, затем `F 6` считывал FPS.
Драйвер проверял PC/PSW/FPS и останавливался бы при первом несовпадении.

**Все 22 шага прошли.** В частности:

| Проверка | USER PSW | FPS |
|---|---|---|
| `STCFI` числа +1 в `@#177776` | `000001` | `000000` |
| `LDFPS @#177776` после этой записи | `000001` | `000001` |
| `STEXP` числа +1 в PSW | `000001` | `000000` |
| `STCFI` числа +16: попытка установить T | `000000` | `000000` |
| `STCFI` числа −1 | `174757` | `000010` |
| `STCFI` нуля | `000000` | `000004` |
| `STFPS` значения `003000` в PSW: reserved PS<10:9> | `000000` | `003000` |

Последующие `LDFPS`/`STFPS` подтвердили чтение записанного PSW;
итоговые R0–R3: `000001 144757 000000 000000`. R4–R6 не изменились.
Явная запись CPU flags сохраняется отдельно от conversion flags в FPS.
В этой аппаратной пробе исходный T=0; сохранение T=1, faults, IRQ и
остальные addressing modes покрываются [RTL-квалификацией CP80](fpp-psw-cp80.md),
а не приписываются этим 22 шагам.

Эта же программа предварительно исполнена на frozen CP67 RTL:
**22 инструкции / 97 checks PASS**. Стенд инициализирует внешнюю память,
не подменяет состояние процессора и завершился бы ошибкой при выходе
операнда PSW на внешний USER bus. План и исходники сохранены в `rtl-program`.

После пробы восстановлены и повторно сверены все 39 слов, R0–R7 и исходный
PSW `022340`. FP-состояние пробы затем заменено результатами нового FPTST;
оно не выдаётся за побайтное восстановление прежних AC/FPS.

## Регрессия FPTST и завершение

После `R 10 340`, `R 7 1012`, `S 53` все **43 пары PC/PSW** совпали
с архивом CP80 RTL. Здесь `53` — восьмеричная запись числа шагов.
Захват ожидал `ODT>`, а не истечения короткого фиксированного таймера.
Конечный PC — `001216`; это повтор первой части FPTST после PSW-пробы.

Итог: AC0=AC1=`044200 000000 000000 000000`,
AC2=`040200 012345 065432 023456`, AC3–AC5=0,
FPS=`144300` (D,L), FEC=`000014`, FEA=`001106`.
`M 2342 5` подтвердил `100123 004567 144000 000014 001106`;
`D 1014` — `LDf 002312,AC2`.

`R 7 1220`, затем `C` выполнили заключительную часть FPTST:
получено **`!FPTST-I-RETURNED TO RT11`**, ошибок `STATE MISMATCH` нет.
Финальный STATUS снова показал `140407` во всех трёх занятых слотах.
Плата оставлена в RT‑11, picocom возобновлён, UART-helper завершён,
HG остановлен. Физические кнопки FP-меню отдельно в этом проходе не проверялись.

## Журналы, воспроизведение и границы

[Deployment manifest](../tb/reports/cp80-hardware/deployment.json) хранит
hashes UART-сеансов, readback, исходного контекста и программы пробы.
Проверка архивов не обращается к плате:

```sh
python3 uJ11-fpga/tools/verify_cp80_hardware.py
python3 uJ11-fpga/tools/verify_cp80.py
```

`tools/fp_psw_hardware_cp80.py` формирует план, но сам UART не открывает.
`tools/test_fp_psw_program_cp80.py` квалифицирует этот план после сборки
CP80 и `psw-sync` из основного руководства. `rtl-program/source.tgz`
содержит сохранённый стенд, image/symbols, RTL и microcode для повторения
без зависимости от временных build-файлов; пути в архиве относительно uJ11-fpga.
Распаковывать для воспроизведения следует в отдельный временный каталог.

Прежние release/test manifests CP80 сохраняют состояние до установки
(`installed_on_board: false`); их не переписывали. Физический результат
фиксируется отдельным deployment manifest.

Ресурсы остаются прежними: **1244 LUT / 381 FF / 7 EBR / 628 slices**,
TRACE **32,032 МГц**, номинальный CPU clock **29,56 МГц**. Это данные CP67b,
нового synthesis не было. Прирост FPGA — **0 LUT / 0 FF / 0 EBR**.
CP80 перехватывает PSW только внутри программной эмуляции FPP;
обычный integer `MOV @#177776,...` не получил аппаратный PSW interface.
Полная внешняя диагностика J‑11 FPP остаётся отдельной задачей.
