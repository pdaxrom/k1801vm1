# CP67: HG до и после сеанса ODT

2026-09-13. На физической CP67b проверен круговой перенос **HG → SD → HG**
до и после входа в ODT. Все 1024 байта обеих обратных копий совпали с исходником.
ODT выполнил R/D/C, управление вернулось RT-11. HG daemon и драйвер между
переносами не перезапускались, ошибок в UART/HG журнале обменов нет.

RTL, микрокод, FPGA и установленные FRAM-модули не менялись.
Ресурсы остаются по [последнему synthesis CP67b](system-cp67.md):
1244 LUT / 381 FF / 7 EBR, TRACE Fmax 32,032 МГц. Нового synthesis не было.

## Стенд и данные

- `sash@192.168.1.108`, UART `/dev/ttyUSB1`, 115200 baud.
- Актуальный picocom PID 180461 временно приостанавливался UART helper и
  возобновлялся после каждого завершённого захвата.
- HG daemon PID 180940, отдельный каталог
  `/tmp/uj11-cp67-hg-odt-20260913/share`, частота 1000 Hz.
- Перед записью `DIR DK:H67TST.BIN` подтвердил отсутствие такого файла на SD.
- Тестовый `H67TST.BIN` — два полных блока, без дополнения последнего блока.
  Байт с индексом `i=0..1023`: `((i*73) ^ (i>>3) ^ (i>>8) ^ 0xA5) & 255`.
- SHA256 исходника и обеих копий:
  `ca60af9efb88db2f5a9f25ee8718dfa6437878437ed8572e573ac784c2580dbf`.

Точные параметры и hashes инструментов — в
[setup.json](../tb/reports/cp67-hg-odt-hardware/setup.json).
Использовался прежний Linux `hgfsd`; исходники общей периферии `lsi11-fpga`
и отдельный `microasm11` не изменялись.

## Выполненная последовательность

```text
LOAD HG
DIR HG:
COPY HG:H67TST.BIN DK:H67TST.BIN
COPY DK:H67TST.BIN HG:BEFORE.BIN
```

После возврата RT-11 и побайтовой проверки BEFORE пользователь подтвердил
короткий RESET. Первое 180-секундное окно записи закончилось без UART-байтов;
баннер самого входа не захвачен. Позднейшая проба пустой строкой получила
штатный `?SYNTAX OR RANGE; H FOR HELP` и `ODT>`. Это ожидаемая реакция
на пустую команду ODT, не ошибка HG.

| Команда ODT | Наблюдение |
|---|---|
| `R` | R0=`050000`, R1=`126650`, R2=`126656`, R3=`122136`, R4=`127240`, R5=`000000`, R6=`155234`, R7=`142772` |
| PSW в выводе `R` | `050004`, T=0, IPL=0, NZVC=0100 |
| `D` | `142772: 001772  BEQ 142760` |
| `C` | `CONTINUE`, затем пустая строка подтвердила приглашение RT-11 |

С тем же работающим HG выполнено:

```text
COPY HG:H67TST.BIN DK:H67TST.BIN
COPY DK:H67TST.BIN HG:AFTER.BIN
UNLOAD HG
```

Каждое COPY завершилось приглашением RT-11. После независимого сравнения
AFTER и успешного UNLOAD HG остановлен только созданный для теста daemon,
пины FTDI освобождены. Тестовый `DK:H67TST.BIN` оставлен на SD для повторения;
ODT/SDBOOT/UJMOD не переустанавливались.

## Проверка архива

[Сырые UART-журналы, HG log и обе обратные копии](../tb/reports/cp67-hg-odt-hardware/).
[Итоговый manifest с SHA256](../tb/reports/cp67-hg-odt-hardware/verification.json).
Из корня репозитория:

```sh
python3 uJ11-fpga/tb/reports/cp67-hg-odt-hardware/verify_capture.py
```

Семь проверок архива — PASS. Скрипт заново формирует ожидаемые байты, сравнивает обе копии, проверяет
команды/ответы UART, регистры, дизассемблер, отсутствие ошибок HG и штатную
выгрузку. Он проверяет сохранённые свидетельства, не запускает новый тест платы.

## Границы проверки

RESET выполнен **между файловыми операциями**. Прерывание посреди бита/блока HG,
таймаут хоста при остановленном CPU и восстановление после такого таймаута
этим проходом не проверены. При работающем daemon клавиши пульта не нажимались.
Частота 1000 Hz — настройка HG, не скорость UART или FRAM.

Отдельная проверка пульта после остановки HG подготовлена: короткий RESET,
кнопки A → NEXT → PREV → E, ожидаемые R0 → R1 → R0 и CONTINUE.
180-секундное пассивное окно завершилось без UART-байтов; подтверждение
пользователя о нажатиях пока не получено. Этот пункт остаётся открытым,
не считается ни PASS, ни неисправностью пульта. На завершении тестовые процессы
остановлены, picocom PID 180461 в состоянии `S`, HG выключен. Последнее
подтверждённое состояние CPU — RT-11 после `UNLOAD HG`, ODT доступен для
следующего короткого RESET.
