# CP63: кнопка RESET и аппаратная основа отладчика

> Аппаратный контракт CP63 сохраняется в CP67b. Полный ODT уже реализован,
> а cold firmware теперь автоматически включает его после проверки модуля:
> [актуальные RESET/UART/пульт](user-guide-cp67.md),
> [cold init](retained-modules-cp67.md). Ниже статус разработки именно CP63.

2026-09-12. Отдельный профиль `--debug-cp63` поверх точного CP62a.
Это первый аппаратный этап [плана ODT](odt-debugger-plan.md), без MMU.
Полный UART/HDSP монитор ещё не написан; в направленных тестах исполняется
небольшой HALT-обработчик с командами в памяти.

## Кнопка

`uj11_button.v` содержит двухтактный synchronizer, независимую временную базу
и подтверждение нажатия/отпускания двумя одинаковыми отсчётами. Использована
уже проверенная recurrence `uj11_tick`; отдельный экземпляр не сбрасывается
командой PDP-11 RESET, остановкой CPU или собственным выходом hard_reset.

- Короткое нажатие создаёт один `halt_pulse` после устойчивого отпускания.
- Удержание в течение 100 подтверждённых отсчётов вызывает hard_reset до
  отпускания кнопки. Последующего короткого события нет.
- Начальный reset после конфигурации независим. CPU ждёт устойчивого отпускания
  кнопки; это относится и к кнопке, удержанной при включении.
- Период отсчёта — 591200 clocks, номинально 20 ms при 29,56 MHz.
  Подавление дребезга занимает примерно 20–40 ms, длинный порог около 2 s.
  Это номинальные величины, не измерение кнопки/OSCH на плате.

Board top больше не подключает `res` непосредственно к asynchronous reset CPU.
Контроллер обслуживается clock FPGA, поэтому зависание программы не мешает
длинному reset. Проверка полной электрической цепи RESET до прошивки остаётся
необходимой: LPF подтверждает обычный вход PL9A, но не внешние связи кнопки.

## HALT и вектор отладчика

Защёлкнутый запрос принимается независимо от IPL на завершённой границе ALU
инструкции или в WAIT. Memory beat завершается штатно. Если уже строится
trap frame, останов возможен после его завершения. `rk_service_active` запрещает
вход внутри частной RK/SD процедуры; запрос остаётся pending до её выхода.
HALT-службы также не допускают вложенного сохранения CPC/CPSW.

**Внешний останов/STEP используют отдельный вектор HALT `000110/000112`.**
Это явно выбранное расширение uJ11, не дополнительный стандартный вектор ВМ2.
Обычная инструкция HALT и векторный вызов UJLOAD по `000170/000172` сохраняют
прежний путь. Причина разделения: resident CP62 трактует R4=`125061` как
копирование/вызов загрузчика, а у прерванной программы R4 может иметь любое
значение. Debug-вход вообще не исполняет эту проверку, поэтому сохраняет R0–R6
и произвольный, в том числе нечётный, SP. Расширение требует трёх слов microstore
и не занимает ни одного нового слова firmware ROM.

Новый обработчик в HALT сначала сохраняет R0–R6 прямыми MOV, затем может
установить свой стек. CPC/CPSW остаются по `000100/000102`. Отладочный PC —
следующая команда программы, а не текущий PC монитора. Синхронная ошибка/ловушка
выполняет штатный guest trap frame; последующий останов показывает PC входа
обработчика и уже изменённый SP.

## Расширение CONFIG/STATUS

Номера битов в таблице десятичные; команды и адреса — восьмеричные.
Доступ только из HALT, как в CP62: CONFIG `000042`, STATUS `000043`.
CONFIG берёт значение из R0, STATUS возвращает в R0, NZVC не меняет.

| Бит STATUS | Смысл | Запись CONFIG |
|---:|---|---|
| 0 | ODT ready | Как ABI2 |
| 1 | FP11 ready | Как ABI2 |
| 2 | Отладочное расширение включено | Установить/снять enable |
| 3 | Pending запрос кнопки/одного шага | Установить/снять pending |
| 4 | Текущий сохранённый контекст получен debug-входом | Только чтение |
| 5 | Сохранённый контекст ожидает в WAIT | Установить/снять resume-WAIT |
| 6 | Отложенный trace завершённой команды | Установить/снять deferred trace |
| 7 | FP11 handler отсутствует | Прежний бит RSEL, только чтение |
| 8 | Наличие расширения CP63 | Всегда 1; только чтение |
| 15:9 | Резерв | Читаются нулями; запись игнорируется |

Внешний запрос допускается только при ODT ready и debug enable одновременно.
Установка обработчика: проверить capability, записать/проверить вектор `110/112`
и его код, подготовить собственный контекст/стек, затем включить бит2 последним.
Cold reset очищает enable, pending, context и ready. Старые значения FRAM
не дают права автоматически запускать монитор.

Прежний UJLOAD ABI2 пишет CONFIG только 0..3, поэтому не включает новое
расширение и не переходит по незаполненному вектору. Его STATUS-команды
используют прежние low bits. Старый UJLOAD также снимает enable при изменении
ready: полному отладчику понадобится согласованная активация в установщике.
Для сохранения расширения новый код должен менять CONFIG с учётом bit2,
pending/WAIT/trace; запись прежнего числа 1 или 3 намеренно их очищает.

## STEP и CONTINUE

При HALT-only STEP `000014..000017`, если включён debug, запрос нового останова
ставится при выходе из HALT. Существующий STEP пропускает первую проверку
IRQ/T и получает ровно одну гостевую команду; затем запрос принимается на
следующей безопасной границе. Микрокоманды и инструкции частной/HALT-службы
не превращаются в дополнительные гостевые шаги. Если гостевая команда вызывает
HALT firmware и та возвращается START, pending шага сохраняется до её выхода.

START `000010..000013` из debug-контекста очищает pending и продолжает программу
с обычным приёмом событий. Новый запрос кнопки внутри уже работающего монитора
виден в STATUS, но не создаёт вложенный контекст; программный UI может трактовать
его как отмену ввода. CONTINUE не возвращается немедленно в ODT из-за этого события.

WAIT хранится отдельно от CPC: START возвращает к ожиданию, а не исполняет
следующий opcode. Повторный STEP уже остановленного WAIT снова возвращается
в монитор без новой команды; это специальный путь, а не фиктивный retirement.
Для явного запуска с другого PC монитор должен снять resume-WAIT через CONFIG.

Deferred trace хранится отдельно от CPSW.T: иначе RTT с восстановленным T
давал бы ложный trace сразу после CONTINUE. При STEP обычная начальная проверка
T/IRQ пропускается; после шага сохраняется факт trace для последующего CONTINUE.
Проверены как RTT с подавленным trace, так и завершённая команда с pending trace
и полным 16-битным CPSW. Подмена T самим отладчиком не требуется.

Обычный ABI2 `JMP @000166` по-прежнему выполняет START. Тестовый STEP-выход
сначала восстанавливает SEL004, затем регистры и выполняет STEP. Полный ODT
должен оформить эту последовательность как отдельную программную службу
выхода, не менять смысл вектора 166 и не возвращаться с неправильным SEL004.

Синхронный fault важнее debug-запроса; незавершённый frame не прерывается.
Терминальная двойная ошибка останавливает engine: программный монитор после
неё не работает, остаётся длинный reset. Внешнее время и UART при останове CPU
продолжают идти; checkpoint не добавляет буферизацию UART или заморозку устройств.

## Измерения и проверка

| Профиль | LUT | FF | EBR | Slices | Fmax MHz | Microstore |
|---|---:|---:|---:|---:|---:|---:|
| CP62a | 1229 | 343 | 6 | 616 | 32,087 | 1002 |
| CP63a | 1230 | 381 | 6 | 618 | 32,246 | 1005 |
| CP63b | 1230 | 381 | 6 | 618 | 32,246 | 1005 |

CP63b уточняет разрядность сравнения в debounce/hold counter для strict lint;
результат synthesis тот же. Полные MAP/PAR/TRACE на LCMXO2-1200HC-4SG32C
проходят gate **31,824 MHz** с прежними FRAM constraints. Свободны **50 LUT,
22 slices, 1 EBR и 19 uwords**. Разность LUT полного проекта не равна отдельной
цене нового блока: Synplify переоптимизирует также существующие конусы логики.
Номинальные CPU и SPI остаются 29,56 MHz.

Направленные проверки:

- 19 CPU scenarios × logic decode / synchronous decode / Lattice ROM,
  169 checks в каждом режиме: regs, flags, odd SP, R4 signature, WAIT,
  BPT/IOT/reserved/odd/bus faults, trace/RTT, IRQ, MUL, FIS, HALT/FP service,
  повторная кнопка и запрет debug при legacy configuration.
- Button: 28 проверок при каждом HOLD=10/100/128; короткое/длинное нажатие,
  начальное удержание, повторное включение, все семь фаз уменьшенного делителя,
  подавление короткого импульса и отсутствие ложного события после reset.
- Actual SPI FRAM × portable/vendor: cold ROM bootstrap, загрузка тестового
  обработчика **из USER через native HALT copy/execute**, release boot overlay
  реальными CSR exchanges, кнопка, STEP/CONTINUE, длинный reset, сохранность слота.
  Начальный USER bootstrap в этом направленном тесте заменён программой теста;
  это отдельно от полного RT-11 прогона.
- Четыре намеренные ошибки (нет останова, потеря WAIT, вход через загрузчик,
  потеря trace) обнаружены CPU-тестами.
- Exact synthesis source match; strict button lint; core lint совпадает
  с набором прежних unused diagnostics замороженного CP62, новых предупреждений нет.
- Final EDIF: 3088 nets, 0 multiple drivers, 0 unexplained floating nets,
  8 CIN доказанно не наблюдаются; три negative controls самого audit проходят.

Полный RT-11/UJLOAD regression: **42 сценария + CTRL/C + cold reboot PASS**.
Прежний ABI2 loader работает при периодических импульсах halt_button с выключенным
расширением. 971335085 clocks, 16863737 retired, 232675 upper writes и 3713
UART bytes совпали с CP62; UART transcript побайтно одинаков. CTRL/C: два
принятых символа, ноль overruns. Исходный диск и backing частной копии не менялись.
Это проверка совместимости старого loader, не полноценного UART/HDSP отладчика.

## Воспроизведение

Из `uJ11-fpga`:

```sh
python3 tools/build_debug_cp63.py
python3 tools/test_debug_cp63.py
python3 tools/test_debug_board_cp63.py
python3 tools/checkpoint_board.py cp63new --debug-cp63 --clock-mhz 31.824 --fram-timing
python3 tools/run_loader_cp62.py --asm-dir build/cp62-asm-e --tag cp63new-rt11 --debug-cp63
```

`check_debug_cp63.py` сверяет локальный `build/cp63b/result.json` и EDIF с
точными выходами генератора. Все profile sources строятся из проверенного
архива CP62a; текущий default не подменяется. Профиль не содержит MMU.
CP63 ещё не прошит; на плате CP56a, default CP52a.
