# Готовая SD с RT-11FB

Комплект **2026-09-26** для uJ11/HC1200:
[uj11-rt11fb.img.gz](../releases/sd/uj11-rt11fb.img.gz),
[SHA256](../releases/sd/SHA256SUMS),
[manifest](../releases/sd/manifest.json),
[полный каталог](../releases/sd/directory.txt).

После распаковки это **27 540 480 байт**, 53 790 секторов по 512 байт.
Образ записывается на **всю SD-карту с сектора 0**, а не файлом в FAT
и не в отдельный раздел. MBR/GPT здесь нет. Нужна карта с блочной адресацией
SDHC/SDXC: действующий bootstrap проверяет CCS и не поддерживает SDSC.
На карте большего размера RT-11 использует только этот том.

Загружается **RT-11FB (S) V05.03**, устройство DM0: через RK611/RK07.
На старте выполняются `SET TT SCOPE,NOCRLF`, `SET SL OFF` и вывод короткой
подсказки. **HG, CLOCK и установка модулей во FRAM не запускаются автоматически.**
Существующая конфигурация FRAM сохраняется. Внутри RT-11:

```text
TYPE SY:README.TXT
```

## Состав

| Файлы | Назначение / справка на диске |
|---|---|
| UJMOD.SAV, UJBOOT.SAV | Таблица/размещение FRAM-модулей, ON/OFF/AUTO, программный restart; UJMOD.TXT, UJBOOT.TXT |
| ODT.BIN, SDBOOT.BIN, FP11.BIN | Relocatable-модули формата 4 / ABI3; ODT.TXT, UJMOD.TXT, FP11.TXT |
| HG.SYS, HGTIME.SAV | HG 01.01, файлы хоста и синхронизация **системного** времени RT-11; HG.TXT |
| CLOCK.SAV, CLOCK.REL | CLOCK 01.01, обычный RUN и foreground FRUN; CLOCK.TXT |
| DSPDEM.SAV, KEYDEM.SAV, RGBDEM.SAV | Демонстрации HDSP/клавиш/RGB с уменьшенной яркостью; PANEL.TXT |
| B81FIJ.SAV, B81FIS.SAV, B81FPU.SAV, B81FPD.SAV | FIS с адаптером, исходный FIS, FPP single/double; BASIC.TXT |
| B81TST.BAS, B81DBL.BAS | Числовые/языковые сравнения и дополнительная double-проверка |
| TMRATE.SAV, ODTCHK.SAV, FPTST.SAV | Замер тиков, интерактивная проверка ODT/FPP, fixture полной регрессии; TESTS.TXT |
| README.TXT, HELLO.TXT, STARTF.COM | Указатель справки и запуск |

**130 файлов**, из них 33 добавлены/заменены нашим комплектом; 11 TXT-файлов
содержат указатель, подсказку и самостоятельные руководства. Текст — **ASCII
с CRLF**, чтобы читался штатным `TYPE` без русифицированного терминала.
Справка описывает команды, prerequisites, выход из программ и восстановление.
Полная документация проекта на русском остаётся в `docs/`.

Стандартные DEC-программы сохранены: DIR/PIP/DUP, HELP, MACRO/LINK/LIBR,
редакторы, библиотеки и остальные файлы исходного дистрибутива. Сохранённые
RT11SJ/RT11XM — файлы дистрибутива; установленная загрузка выбирает **FB**.
Это не добавляет поддержки XM/MMU в текущий uJ11.

Свободны **51 104 блока = 26 165 248 байт** файловой системы. Ещё 66 последних
секторов не входят в её пространство данных — как в исходном RK07-образе.

## Запись на SD

Сначала распаковать и сверить checksum. Из `uJ11-fpga`:

```sh
mkdir -p build/sd-card
gzip -dc releases/sd/uj11-rt11fb.img.gz > build/sd-card/uj11-rt11fb.img
shasum -a 256 build/sd-card/uj11-rt11fb.img
```

Ожидаемый SHA256 raw-образа:

```text
5850239d1c27d57cdd307da7bdcf85d255475f1db3f39f52994685994645c295
```

Выберите устройство именно SD: следующая запись заменит её прежнюю
файловую систему. `/dev/sdX` и `/dev/diskN` ниже — **места для подстановки**,
а не найденные устройства. Не использовать номер раздела (`sdX1`/`diskNs1`).

Linux:

```sh
lsblk -o NAME,SIZE,MODEL,MOUNTPOINTS
# Размонтировать смонтированные разделы выбранной SD, затем:
sudo dd if=build/sd-card/uj11-rt11fb.img of=/dev/sdX bs=4M conv=fsync status=progress
sync
sudo dd if=/dev/sdX bs=512 count=53790 status=none | sha256sum
```

macOS:

```sh
diskutil list
diskutil unmountDisk /dev/diskN
sudo dd if=build/sd-card/uj11-rt11fb.img of=/dev/rdiskN bs=1m
sync
sudo dd if=/dev/rdiskN bs=512 count=53790 2>/dev/null | shasum -a 256
diskutil eject /dev/diskN
```

Readback первых 53 790 секторов должен дать тот же SHA256. Проверять до
загрузки RT-11: затем система вправе менять SWAP и записывать файлы.
Оставшаяся часть большой карты не входит в сравнение. Запрос ОС
«инициализировать/отформатировать» такую карту отклонить.

## Первый запуск

UART **115200, 8N1, без flow control**. Вставить SD в выключенную плату,
затем включить. Обычный длинный RESET также загружает RT-11 и активирует
сохранённые исправные AUTO-модули.

Если FRAM пуста, FB и микрокодный FIS уже работают. Сначала `RUN SY:UJMOD`
→ `STATUS`. Для пустой таблицы пример в `UJMOD.TXT` устанавливает ODT,
SDBOOT и `FP11 AUTO`, затем `RUN SY:UJBOOT` выполняет инициализацию.
Наличие BIN на SD **не означает**, что соответствующий модуль установлен.
На действующей плате не повторять AUTO поверх старой записи: проверить
слоты, обновлять осознанно или вернуть существующий модуль через ON.

Для FIS BASIC: `RUN SY:B81FIJ`, ответ `A`, затем `RUN SY:B81TST`.
Этот вариант подходит и с FPP, и без него. Исходный B81FIS использовать
только без FPP после перезапуска; FPU/FPD требуют активного FP11.

Для HG: выбрать GPIO, отключить программатор от общих пинов, запустить
обновлённый hgfsd на хосте, затем `INSTALL HG`, `LOAD HG`, `RUN SY:HGTIME`.
Перед работой с клавишами выгрузить HG и остановить демон.
Для часов параллельно консоли FB — `FRUN SY:CLOCK`, затем **Ctrl+B**.
Завершить: **Ctrl+F**, **Q**, **Ctrl+B**, `UNLOAD F`.
[Подробности HG/времени](host-time.md), [пульт и RESET](user-guide.md).

Для восстановления после плохого FRAM-модуля: длинный RESET и сразу
**UART ESC**. Встроенный bootstrap пропускает модули и загружает эту же SD.
FPGA и FRAM не прошиваются при подготовке или записи SD-образа.

## Сборка и происхождение

```sh
make sd-image SD_OUT=build/sd-new
make test-sd-image SD_OUT=build/sd-new SD_TEST_OUT=build/sd-test-new
```

Нужны Python 3, `../lsi11/rt11tool`, SIMH `pdp11`; для полного теста —
Verilator/C++/make и штатные генераторы проекта. Каталоги должны быть новыми.

[Сборщик](../tools/build_sd_image.py) берёт неизменённый
`lsi11-fpga/images/rt11v503.dsk`, SHA256
`e769228f2e1262220297bfa98b8f2841688849ab4c49ad9cd48d0d73d0a99553`.
BIN/SAV/REL из трёх release manifests проверяются по SHA256. TMRATE/ODTCHK
собираются штатными DEC MACRO/LINK; демо пульта берутся из проверенного комплекта.
Даты новых directory entries фиксированы, gzip не содержит времени сборки.
Исходный диск, boot/home blocks, размещение и байты остальных файлов DEC,
последние 66 секторов сохраняются; свободные области обнуляются от старых данных.

Выходы: raw `.img`, сжатый `.img.gz`, `SHA256SUMS`, `manifest.json`,
`directory.txt`, `image-info.txt`; рабочие извлечения/логи остаются в `build/`.
В `releases/sd/` хранится сжатый образ, чтобы не дублировать 27,5 МБ raw.
Повторная сборка из тех же входов должна давать побайтно тот же `.img`.

Проверка каталога учитывает однословный маркер E.EOS в конце сегмента и
реальный конец данных исходного RK07. Старый `rt11tool fsck` эти особенности
трактует неверно и выдаёт два сообщения уже на исходном загрузочном диске;
`--repair` здесь **не применяется**. Вместо него проверяются цепочка сегментов,
границы/перекрытия, уникальность имён и hashes всех файлов, обратное извлечение
каждого добавленного файла и операции COPY/DELETE самой RT-11.

## Проверки и ограничения

[Результаты](../releases/sd/validation.json) привязаны к SHA256 конечного образа.
Результат от 2026-09-26: **PASS**. SIMH — **116 сравнений BASIC / 0 ошибок**
и дополнительный double-тест; полный RTL — **24 проверки, 399 490 007 clocks,
3434 UART bytes**. CLOCK.REL занимает 1007 слов: background имеет
20 341 → 19 334 → 20 341 слово до запуска / при работе / после `UNLOAD F`.
Повторная сборка даёт те же raw и gzip; `make verify` — PASS.

SIMH загружает частные копии с CPU 11/73 и 11/03 EIS/FIS: читаются все
11 документов, запускаются четыре BASIC с 29 сравнениями каждый и дополнительный
double-тест; проверяются создание/чтение/удаление файла средствами RT-11.

Полный RTL загружает тот же образ через SPI SD в модель 128 КиБ FRAM,
использует производственные ROM и полное окно ESC. Проверяются старт без
FRAM-модулей, документация, реальные INSTALL/LOAD/UNLOAD HG, UJMOD STATUS,
FIS BASIC с делением на ноль и восстановлением, foreground CLOCK.REL,
физический поток HCMS и работа background-консоли.

SIMH не содержит HC1200 GPIO: в его прогоне HG/CLOCK не имитируются.
RTL не подключает внешний HG-хост, поэтому обмен файлами/синхронизацию времени
покрывают прежние тесты [HG TIME](host-time.md), а не эта загрузка образа.
Модули/FPP на новой SD побайтно совпадают с ранее проверенными релизами.
Физическая SD в этой задаче не записывалась; повторного hardware boot
именно собранного образа пока нет. Ресурсы FPGA не изменились.
