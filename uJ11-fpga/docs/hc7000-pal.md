# HC7000: PAL framebuffer

Реализован отдельный профиль **PAL 625/50** для `hardware-lcd`,
LCMXO2-7000HC-4TG144C, SRAM IS61WV102416BLL-10T и генератора 12 МГц.
CPU остаётся на **50 МГц**, видеотракт работает на **64 МГц** от второго PLL.
По умолчанию `HC7000_VIDEO=0`; включение доступно для MMU / SERV storage / FPP off.
FIS и существующие дисковые контроллеры сохранены.

Это описание профиля framebuffer с автономным демо (терминал выключен).
Сейчас на плате установлена [JED 54D2 с зеркалом консоли 640×240](hc7000-terminal.md):
исправлен порядок прокрутки, аппаратная загрузка BSD повторно проверена.
Читаемость текста PAL подтверждена на предыдущей JED 3428; визуальная проверка
исправленной прокрутки пока ожидается.
PS/2 ещё не подключена. [Предыдущая JED 2AAE и отчёты](../releases/hc7000-pal-fast/README.md):
**установлена на плату 2026-09-30**, PAL-демо запущено после полного обратного
чтения его 3798 байт. Пользователь подтвердил работу изображения на экране;
измерения уровней аналогового сигнала ещё не проводились.
[Аппаратный запуск и обнаруженное ограничение ODT](../releases/hc7000-pal-fast/validation/hardware-20260930/README.md).

## Изображение и память

| Режим | Формат | Строка | Кадр | Текст 8×8 |
|---|---|---:|---:|---:|
| 640×200, 16 цветов | два 4-битных индекса в байте | 320 Б | 64000 Б | 80×25 |
| 320×200, 256 цветов | один 8-битный индекс в байте | 320 Б | 64000 Б | 40×25 |

В 4 bpp левый пиксель находится в младшем полубайте. Младший байт 16-битного
слова расположен левее старшего. Палитра — 256 записей **RGB332**;
4 bpp использует записи 0–15. После reset палитра тождественная: индекс = RGB332.
Настройка палитры допускается при выключенном изображении и свободном DMA.

`BASE` — физический **байтовый** адрес SRAM, чётный, не выше `0x1F0600`.
Размер памяти при этом всегда проверяется для полного кадра 64000 байт.
`YORIGIN` задаёт первую строку кольца 0–199. Изменение начала на 8 строк
позволяет прокрутить текст, очистив только 2560 байт вместо переноса кадра.
Конфигурация применяется на границе полного 40-мс кадра; оба поля используют
одну страницу и повторяют те же 200 логических строк.

Демо занимает два слота по 64 КиБ: `0x1E0000` и `0x1F0000`.
**В профиле без терминала все 2 МиБ доступны ОС.** Эти адреса не являются свободными в запущенной
BSD/RT-11/RSX. Демо запускается самостоятельно после остановки ОС.
Для следующего варианта постоянного терминала выбраны **240 строк и одна
видеостраница**: 80 КиБ под кадр (76800 байт пикселей) и предварительно 32 КиБ
под загружаемый модуль SERV. Плановый резерв — **112 КиБ**, для ОС — **1936 КиБ**.
Резервирование до старта ОС и программный терминал реализованы в отдельном
профиле JED 54D2; режимы и регистры ниже описывают профиль без терминала
с 200 строками (2AAE).
См. [принятое решение и порядок реализации](hc7000-video-plan.md).

## Регистры через SERV

16-битные адреса I/O — **177200–177216**, все адреса в этой таблице восьмеричные.
В 22-битном физическом I/O page диапазон — **17777200–17777216**.
PDP-11 I/O перехватывает существующий мост SERV. Прошивка пересылает обращения
в восемь низкоуровневых регистров по `0x40000400`, шаг 4 байта. Отдельного
аппаратного декодера этих PDP-11 CSR нет. Аппаратные теневые регистры и DMA
нужны для применения конфигурации и выдачи пикселей в заданное время.

| Адрес | Регистр | Назначение |
|---|---|---|
| 177200 | CTRL | bit 0: enable; bit 1: 8 bpp; bit 2: встроенная цветовая таблица |
| 177202 | BASELO | BASE[15:0] |
| 177204 | BASEHI | BASE[20:16], младшие 5 бит |
| 177206 | YORIGIN | начало кольца, 0–199 |
| 177210 | APPLY | записать 1: применить; чтение bit 0: busy |
| 177212 | PALINDEX | индекс записи палитры, 0–255 |
| 177214 | PALDATA | записать RGB332; чтение возвращает 0 |
| 177216 | STATUS | состояние и счётчик underrun |

Чтение CTRL/BASE/YORIGIN возвращает теневую конфигурацию. После `APPLY=1`
она заморожена до подтверждения на границе полного кадра; записи в эти
регистры при busy игнорируются. Нечётный/слишком большой BASE или YORIGIN≥200
не применяются и устанавливают `bad_config`. Стандартные PDP-11 byte lanes
сохраняются при пересылке через SERV.

STATUS: bit 0 — config busy, bit 1 — DMA занят, bit 2 — был underrun,
bit 3 — bad_config, bit 4 — начальная загрузка палитры,
bits 15:8 — насыщающийся счётчик underrun 0–255. Запись младшего байта STATUS
очищает счётчик и bad_config. PALDATA принимает младший байт только после
инициализации палитры, при выключенном активном изображении, config idle и DMA idle;
в остальных случаях запись игнорируется. PALINDEX автоматически не увеличивается.

Чтобы изменить палитру: записать CTRL=0, APPLY=1, дождаться STATUS[4:0]=0
(предварительно очистив ошибки), затем записать PALINDEX/PALDATA и включить
нужный режим через APPLY. Выключение изображения сохраняет синхронизацию PAL
и burst. Тестовая таблица требует enable=1, но не обращается к SRAM.
После reset изображение и DMA выключены. CPU RESET также сбрасывает видео.

## Аппаратный тракт

Один EBR DP8KC организован как 1024×9 с независимыми тактами портов:

| Ячейки | Содержимое |
|---|---|
| 0–319 | строка A |
| 320–639 | строка B |
| 640–895 | палитра RGB332 |
| 896–1023 | запас |

Используются восемь бит каждой ячейки. SRAM читается словами, EBR записывается
двумя байтами. В DP8KC x9 сигнал ADA0 — разрешение записи байта; адрес находится
в ADA[12:3]. Это отдельно проверено официальной моделью Lattice, включая
один такт задержки чтения и удержание выхода при отключённом порте.

Арбитр чередует одно слово видео с одним запросом CPU/диска;
CPU и дисковый DMA чередуются, свободные слоты сразу используются другими
клиентами. CPU LOCK соблюдается; начатая транзакция SRAM не прерывается.
Строка N+1 загружается во время строки N, первая — до активного изображения.
При постоянных запросах всех трёх клиентов максимальное время заполнения
строки в RTL-тесте — **38,42 мкс** при периоде строки **64 мкс**.
Длительный LOCK может вызвать underrun: тогда целая строка гасится, растр
продолжается, ошибка фиксируется. Частичная строка не выводится.

Чтение изображения требует 3,20 МБ/с: 200 строк × 320 байт × 50 полей/с.
В исходной FA92 это составляло примерно 32% номинального времени SRAM
при 10 тактах/слово. В 2AAE минимальный интервал готовых запросов сокращён
до 6 тактов, а ответ перекрывается с выдержкой прежних HOLD/RELEASE.
[Устройство оптимизации и новые измерения](hc7000-pal-performance.md).
Частота CPU не меняется, но при включённом framebuffer его доступ к памяти
конкурирует с видео. Потеря скорости реальных ОС ещё не измерена.

### Исходное измерение FA92 до оптимизации SRAM

Ниже сохранена исходная таблица FA92. В 2AAE рост времени от PAL снижен
до **3,29–5,47%** для коротких циклов и **1,09%** для EIS;
см. [актуальное сравнение](hc7000-pal-performance.md).

`tests/mmu/tb_pal_cpu_perf.v` сравнивает настоящее ядро с включённой MMU,
исходный и новый арбитры, неизменённый SRAM-контроллер и модель внешней SRAM.
Для каждого цикла измеряются 160 мс после прогрева — четыре полных кадра PAL,
включая гашение. Код и данные отображены через одну 8-КиБ страницу kernel I.
Дискового трафика, SERV-нагрузки и ОС в этом стенде нет.

| Цикл | Инструкций без видео / с PAL за 160 мс | Потеря производительности | Рост времени на тот же объём работы |
|---|---:|---:|---:|
| Регистровые ADD/XOR/ROR/SOB | 515208 / 372899 | **27,62%** | **38,16%** |
| ADD в память, INC/XOR/SOB | 296149 / 220331 | **25,60%** | **34,41%** |
| MUL/DIV/ASH | 74310 / 68886 | **7,30%** | **7,87%** |
| MOV (R2)+,(R3)+ / SOB | 210512 / 158184 | **24,86%** | **33,08%** |

Производительность — количество завершённых инструкций за фиксированное окно;
эквивалентный рост времени вычислен как `N_off / N_PAL - 1`.
Каждый завершённый внутренний цикл проверяет результат R0; для копирования
дополнительно проверяется содержимое назначения. Видео прочитало ровно
256000 слов за окно, underrun отсутствовал.

С выключенным изображением новый арбитр дал **ровно те же счётчики**, что и
прежний, во всех четырёх циклах. Режимы 640×200/16 и 320×200/256 также дали
одинаковые результаты: их объём SRAM-чтений совпадает. Даже регистровая
арифметика замедляется, поскольку инструкции выбираются из общей SRAM;
длинные EIS-команды больше времени выполняются внутри CPU.

Это измерение синтетических циклов в RTL, не утверждение о скорости BSD,
RT-11 или RSX. При конкуренции с диском результат нужно измерять отдельно.
Для воспроизведения из `uJ11-fpga`:

```sh
UJ11_HC7000_VIDEO=1 UJ11_HC7000_DIAGNOSTICS=1 UJ11_MMU_CLOCK_MHZ=50 \
  UJ11_MMU_FPP=off UJ11_MMU_IOP=storage python3 tools/test_pal_cpu_perf.py
```

[Результаты, хеши и параметры](../releases/hc7000-pal-preview/validation/test-pal-cpu-perf/result.json)
и журналы `mode-0.log`…`mode-3.log` сохранены с проверочной сборкой.

Переходы между 50/64 МГц используют toggle/ack mailbox и EBR. Поля mailbox
удерживаются до подтверждения. LPF исключает только вход первой ступени
синхронизаторов, а многобитным путям задаёт MAXDELAY DATAPATH_ONLY 20/25 нс;
проверка синтеза требует оценки всех четырёх групп и нулевых timing errors.
Reset утверждается асинхронно и снимается через три такта каждого домена.

Растр — 625 строк, 50 полей/25 полных кадров в секунду, строка 4096 тактов,
полустрока 2048. Активная область занимает 50 мкс. Поднесущая непрерывна,
DDS step 297535118 при 64 МГц даёт 4433618,75415 Гц; чередуются V и burst,
учтены полустрочные сдвиги, уравнивающие импульсы и четырёхполевая схема burst.
Кодировщик использует восемь фаз и шестибитный ЦАП, без умножителей и EBR.
Максимальная ошибка относительно независимого расчёта YUV для всех RGB332
и обеих фаз V в тесте — 1,846 кода ЦАП. Это приближение, а не сертификация
аналогового PAL. Основа времён — [ITU-R BT.1700](https://www.itu.int/rec/R-REC-BT.1700).

## Сборка и проверки

Из `uJ11-fpga`, на Linux с Diamond 3.14 и RISC-V GCC 13.2:

```sh
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off IOP=storage \
  MMU_CLOCK_MHZ=50 HC7000_DIAGNOSTICS=1 HC7000_VIDEO=1 \
  OUT=build/pal-build synthesis export
```

Имя каталога синтеза должно быть новым для каждого прогона. Экспорт допускается
только при совпадении исходников и отчётов, полном маршруте, исправных внешних
таймингах SRAM и частотах не ниже 50/64 МГц. Фактические ресурсы и Fmax
сохранены в [отчёте текущей сборки](../releases/hc7000-pal-fast/README.md).

| Ресурс | PAL 2AAE | Всего | Осталось |
|---|---:|---:|---:|
| LUT4 | 4911 | 6864 | **1953** |
| SLICE | 2462 | 3432 | 970 |
| FF, включая I/O | 1791 | 7209 | 5418 |
| EBR | 26 | 26 | **0** |
| PLL | 2 | 2 | **0** |

Относительно установленной 7AE8: +932 LUT4, +1 EBR, +1 PLL.
Fmax после трассировки: CPU **51,536 МГц**, видео **67,290 МГц**;
отрицательных запасов времени нет. Это расчёт Diamond, а не измерение платы.

SERV: код/константы **10651 байт**, BSS **976 байт**, стек **640 байт**,
между BSS и стеком **20 байт**. Новый CSR не требует статических данных.
Только PAL-профиль использует `-fno-tree-dominator-opts`, чтобы избежать роста
кода GCC 13.2. Сокращать стек или удалять контроллеры не потребовалось.
Запаса под VT-парсер здесь нет; для него нужно отдельное решение.

```sh
make test-video
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off IOP=storage \
  MMU_CLOCK_MHZ=50 HC7000_DIAGNOSTICS=1 HC7000_VIDEO=1 test-pal-demo
```

Проверено:

- 13 кадров PAL, **11507200 пикселей**: оба формата, кольцо Y, страницы,
  палитра, все 256 цветов встроенной таблицы, reset во время SRAM-чтения,
  underrun при LOCK, восстановление и очищение счётчика.
- 33834 отсчёта кодировщика; все адреса/байты и задержка EBR, в том числе
  отдельный прогон RAM на официальной модели Lattice DP8KC.
- Настоящий SERV: 15 проверок CSR, byte lanes, заморозки/применения,
  NXM соседнего адреса и CPU RESET; стек 208/640 байт.
- Настоящие PDP-11 + MMU + SERV + SRAM + PAL DMA: демо и UART-команды;
  **393216 байт** двух страниц обоих режимов и прокрутки совпали с эталоном.
- В 2AAE: RK05/RQ при активном PAL — 1029647 проверок, стек 320/640 байт,
  без underrun; RT-11 V4 с выключенным изображением загрузилась с RK0,
  выполнила `DIR` и `TYPE`. [Проверки ускоренного SRAM](hc7000-pal-performance.md).
- Регрессии неизменившейся прошивки дисков на этапе FA92: RL/XP 367240;
  RH основная/резервная метка, ошибочные метки. Максимум стека в этих
  прогонах — 336/640 байт. Их SRAM/SD модели не заменяют проверку на плате.
- HC1200: штатный `make BOARD=hc1200 verify` повторно прошёл после ускорения
  SRAM. На этапе FA92 при VIDEO=0 бинарник SERV совпал с прежним побайтово;
  отдельный синтез без видео прошёл 50 МГц.

## Автономное демо

`make pal-demo` собирает `firmware/video/PALDEM.MAC.in` штатными MACRO/LINK
в RT-11/SIMH. Получаются `build/pal-demo/PALDEM.MAC`, `paldem.bin`, таблицы
загрузки и `result.json`. Размер — 3798 байт; загрузка по **020000**, старт
с **020000**. Сначала штатно остановить ОС и войти в ODT: программа заменяет
настройку MMU и содержимое двух верхних 64-КиБ слотов SRAM.

| Клавиша UART | Действие |
|---|---|
| 1 | 640×200, текст 80×25 |
| 2 | 320×200, текст 40×25 |
| S | кольцевая прокрутка на 8 строк |
| P | переключение страницы A/B |
| B | встроенная таблица 256 цветов и полосы чёткости |
| Q | выключение изображения/MMU и HALT |

Шрифт взят из `pico-lsi11/pico-vt100/src/font5x7.c`, размещён в ячейках 8×8.
[Цифровой кадр RTL-теста](../releases/hc7000-pal-preview/demo/text-80x25.png)
показывает содержимое framebuffer; это **не снимок с телевизора**.

Следующая проверка на плате: PAL-захват/телевизор на RCA, синхронизация и цвет,
уровни под нагрузкой 75 Ом, читаемость 80 столбцов и overscan, оба режима,
страницы, прокрутка и длительная конкуренция с дисковым DMA. Затем — выбор
памяти/архитектуры терминала и интеграция с ОС. Полный прогон загрузок
BSD/RT-11/RSX с активным framebuffer пока не выполнен.
