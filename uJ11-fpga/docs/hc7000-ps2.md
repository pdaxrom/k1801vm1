# HC7000 hardware-lcd: клавиатура PS/2

2026-10-02. Клавиатура вводит символы в существующую системную консоль J11
совместно с UART. Для PDP-11 сохраняются DL11 `177560..177566`, векторы
`60/64` и драйверы RT-11/RSX/BSD. Эхо выполняет гостевая система: её вывод,
как прежде, идёт одновременно в UART и на PAL. Отдельный TTY не добавлен.

Текущая установленная сборка — **7CBA**, с обработкой FIFO только в свободные
интервалы SERV; [ресурсы](synthesis.md#hc7000-установленная-7cba).
Сравнения с E517/347F ниже описывают первоначальные этапы до этого изменения.

## Подключение по схеме

Источник: `/Users/sash/Work/FPGA/Z-pdaXrom-TV/hardware-lcd/main.sch`,
разъём `PS/2` типа MD06SS. Проверены сети и выводы U1 именно варианта
`hardware-lcd` со статическим SRAM.

| Сигнал | Контакт mini-DIN | FPGA | Вывод TG144 | Подтяжка |
|---|---:|---|---:|---|
| Клавиатура CLOCK | 5 | PL3B | 2 | R25, 10 кОм к +3V3 |
| Клавиатура DATA | 1 | PT11B | 138 | R26, 10 кОм к +3V3 |
| Мышь CLOCK | 6 | PL4B | 4 | R24, 10 кОм к +3V3 |
| Мышь DATA | 2 | PL6A | 5 | R23, 10 кОм к +3V3 |
| Питание | 4 | +3V3 | — | — |
| Земля | 3 | GND | — | — |

Обычная PS/2-клавиатура использует контакты 1/5. Мышь на контактах 2/6
предусмотрена для совместного подключения через подходящий Y-разветвитель;
приём мыши пока не реализован. Нумерация относится к контактам разъёма,
а не к порядку ножек на фотографии.

Разъём питается от **3,3 В**. Линии идут непосредственно в FPGA, без
преобразователей уровней: подключаемая клавиатура должна работать при этом
питании. Не подключать к этим линиям подтяжки к 5 В. CLOCK со стороны FPGA
управляется только как `0/Z`; DATA служит входом. USB-клавиатура с пассивным
переходником подходит только при собственной поддержке PS/2.

## Реализация

`boards/hc7000/uj11_ps2_keyboard.v` содержит синхронизаторы, фильтр CLOCK,
приём 11-битного кадра и очередь 16 байт в distributed RAM. Проверяются
start, нечётная parity и stop; незавершённый кадр прерывается через 1 мс.
Ошибки передаются как упорядоченный маркер `00`, очищающий состояние
префиксов и модификаторов в SERV. При 14 байтах в очереди CLOCK удерживается
в нуле между кадрами минимум 100 мкс; два свободных места оставлены в запасе.

Сканкоды set 2 переводит `firmware/storage/keyboard.c`. Поддержаны US ASCII,
оба Shift/Ctrl/Alt, Caps Lock, Num Lock, повтор, Enter/Tab/Esc, Backspace и
Delete (`DEL`, 127), стрелки, Home/End/Insert/Page Up/Page Down, цифровой
блок и F1–F4 как PF1–PF4. Ctrl+C/D/U/S/Q и Ctrl+Space (`NUL`) проходят
обычным консольным вводом. Alt добавляет ESC перед печатным символом.
Pause и Print Screen распознаются и игнорируются, без ложного Shift/Ctrl.

Стрелки/PF следуют текущему режиму экранного парсера: VT52 `ESC A..D` /
`ESC P..S`; VT100 `ESC [ A..D` / `ESC O P..S`; DECCKM переключает стрелки
на `ESC O A..D`. Цифровой блок стартует в numeric mode; Shift временно
обращает Num Lock. Команды клавиатуре пока не передаются, поэтому её
индикаторы Caps/Num/Scroll не синхронизируются. F5–F12, русская раскладка,
application keypad и назначение Pause/Print Screen остаются расширениями.
Клавиатура должна выдавать стандартный set 2, установленный после её включения.

SERV MMIO:

| Адрес | Чтение | Запись |
|---|---|---|
| `0x40000600` | Pop сканкода, bit 8 = valid | — |
| `0x40000604` | Bit 0 = свободен ASCII mailbox | Байт для DL11 RBUF |
| `BUS_STATUS`, bit 4 | В очереди есть сканкод | Обычные операции BUS_STATUS |

Считанный сканкод удерживается до ACK SERV. ASCII mailbox удерживает байт,
пока DL11 не готов; локальный ввод не заменяет непрочитанный RBUF и ждёт
окончания текущего UART-кадра. Гостевой RESET очищает очередь и программное
состояние клавиатуры; RESET не выключает экранный терминал.

Наличие сканкодов сообщается через `BUS_STATUS`. Разбор клавиш вызывается
только из основного цикла SERV после обхода дисковых контроллеров: должны
отсутствовать busy-контроллеры и события шины (запрос I/O, RESET, IRQ ACK).
Один свободный проход принимает один сканкод или отправляет один ASCII-байт.
`poll_io`, ожидание SPI/DMA и рисование терминала не читают PS/2 FIFO.
При длительном дисковом обмене очередь сохраняет сканкоды, а CLOCK тормозит
клавиатуру; после освобождения SERV приём продолжается в прежнем порядке.
Гостевой RESET по-прежнему очищает аппаратную очередь и состояние декодера.
Справочник кадра и раскладки: [Digilent PmodPS/2 Reference Manual](https://digilent.com/reference/_media/pmod:pmod:pmodPS2_rm.pdf).

## Сборка и проверки

```sh
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off IOP=storage MMU_CLOCK_MHZ=50 \
  HC7000_DIAGNOSTICS=1 HC7000_VIDEO=1 HC7000_TERMINAL=1 HC7000_KEYBOARD=1 hardware
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off IOP=storage MMU_CLOCK_MHZ=50 \
  HC7000_DIAGNOSTICS=1 HC7000_VIDEO=1 HC7000_TERMINAL=1 HC7000_KEYBOARD=1 test-keyboard
```

`HC7000_KEYBOARD` по умолчанию равен 0; он требует MMU / storage / FPP off /
PAL terminal / 50 МГц. Физические ограничения PS/2 подключаются к синтезу
только в этой конфигурации из `boards/hc7000/ps2-pins.lpf`.

HC1200 использует прежний `rtl/peripherals/wbc_uart_xo2.v`. Для HC7000
генератор `tools/console_uart.py` добавляет локальный приём к копии модуля;
при `LOCAL_ENABLE=0` этот тракт исключается. Общие исходники HC1200 не менялись,
проверка production подтвердила прежние RTL/ROM/программные образы.
Сборка SERV с `HC7000_KEYBOARD=0` побайтово совпадает с прежней E517.

Проверены декодер клавиш на хосте, приёмник на физических кадрах PS/2 в RTL
и весь путь PS/2 → SERV → DL11 CSR/RBUF/IRQ вместе с UART. Тест заполняет
очередь, проверяет физическое торможение CLOCK, порядок байтов после
возобновления чтения и очистку по гостевому RESET. Выполнено 39 проверок
консольного приёма; реальные записи SERV использовали 240 из 640 байт стека.
Физический ввод `dir` с подключённой PS/2-клавиатуры принят в UART;
пользователь подтвердил, что команду ввёл именно с клавиатуры платы.

Итоговая сборка `hc7000-ps2-final-20261002`, JED **347F**, прошла
MAP/PAR/TRACE для CPU 50 / PAL 64 МГц, внешние тайминги SRAM и ограничения CDC.

| Показатель | E517 без клавиатуры | 347F с клавиатурой |
|---|---:|---:|
| LUT | 5897 | 6046 (+149), свободны 818/6864 |
| FF | 2020 | 2098 (+78) |
| EBR / PLL | 26 / 2 | 26 / 2 |
| Fmax CPU / PAL | 50,633 / 64,927 МГц | 50,123 / 65,733 МГц |
| Код/константы SERV | 15067 байт | 16363 байта (+1296) |
| BSS | 1072 байта | 1084 байта (+12) |
| Запас перед стеком / cold bank | 1652 / 512 байт | 344 / 512 байт |
| Резерв стека | 640 байт | 640 байт |

Полный UART/PAL тест прошёл 158842 проверки, 2187 байт провода и 12
отдельных сдвигов. Все колонки 35 строк каталога видны до CR; время
55234697 тактов / 1,104693 с против 51160906 / 1,023218 с у E517 —
прибавка 7,96% для этого теста вывода при пустой клавиатуре. Это не
измерение замедления J11 в вычислительных задачах или реальной ОС.
Максимум записей стека в этом тесте — 224/640 байт, в тесте ввода — 240/640.

Промежуточный вариант с вызовом обработчика на каждом шаге рисования
занимал 1,657 с на этом каталоге; он заменён проверкой события перед
вызовом. Конфигурация с отключённой клавиатурой оставляет прежний бинарный
код SERV. Сводка, точные исходники, JED и журналы —
[checkpoint PS/2](../history/releases/hc7000-ps2/README.md).
347F прошла физическую FLASH Erase/Program/Verify и загрузила RT-11 XM с RH0,
но первая попытка DIR/SHOW CONFIGURATION дала `?KMON-U-Overlay read error`.
Для сравнения временно восстановлена E517. На той же SD прошли полный
каталог XM (214 файлов / 5346 блоков), конфигурация XM, V4 с RK0 и чтение
V4USER.TXT, RSX с RQ1 и каталог `DU1:[1,54]RSX11M.SYS`, BSD с RL0,
multiuser/root и чтение `/usr` на XP0. RSX остановлена через SHUTUP;
BSD выполнила sync. Однако последующее чтение на контрольной E517 после
периода простоя дало ошибку RL0 (`cs=110315`) и `panic: IO err in swap`.
Начальная загрузка BSD прошла, длительную работу нельзя считать проверенной.
Проверка причины дисковых ошибок продолжается;
эту попытку установки нельзя считать успешной проверкой дискового ввода.

Регрессия RK05/MSCP с тем же бинарным SERV прошла 1075994 проверки
с быстрым SRAM и параллельным PAL; стек использовал 336/640 байт.
Стенд больше не ограничивает код старой константой 13 КиБ: граница
извлекается из ELF и проверяется вместе с границами данных/стека.

## Обслуживание только в свободном цикле SERV (2026-10-02)

Новый вариант прошивки использует прежнее аппаратное FIFO 16 сканкодов и
CLOCK inhibit; дополнительная EBR не нужна. Клавиатура исключена из
`poll_io` и всех ожиданий SPI/DMA/рисования. Обработчик вызывается после
обхода контроллеров, только при отсутствии дисковых команд и событий шины.

Приёмник и декодер проходят прежние проверки; интеграция SERV/DL11/UART
принимает 39 байт, стек использует 240/640 байт. Проверка дискового
приоритета отправляет 24 сканкода при чтении целой дорожки RL (5120 слов):
на время дискового обслуживания запрещены любые MMIO клавиатуры,
аппаратная очередь тормозит CLOCK и затем продолжает ввод. Данные DMA
проверяются побайтово, исходный образ SD не меняется.

Полный PAL-тест проходит 157759 проверок / 2187 байт / 12 сдвигов.
Каталог из 35 строк рисуется до CR за 51165949 тактов / 1,023319 с
(у E517: 51160906 / 1,023218 с). Это измерение конкретного теста вывода.
Код SERV — 16451 байт, BSS — 1080 байт, запас до стека — 260 байт;
максимум записей стека в дисковом тесте — 336 из 640 байт.
Проверка production HC1200 проходит.
Сборка `hc7000-ps2-idle-02-20261002`, JED **7CBA**, проходит
MAP/PAR/TRACE на 50/64 МГц, ограничения SRAM и CDC. Ресурсы прежние:
6046 LUT / 2098 FF / 26 EBR / 2 PLL. Первая попытка размещения дала
49,485 МГц; следующие варианты дали Fmax CPU 50,123 / PAL 65,733 МГц.
В первом прогоне новой прошивки RT-11 XM приняла DIR кадрами PS/2 и
вывела полный каталог: 214 файлов / 5346 блоков / 48310 свободных блоков.
Затем проверка SHOW CONFIGURATION не прошла: UART-команда была принята
как SHOW без аргумента. Эта попытка сохранена как незавершённая, без PASS.
Повторный прогон ожидает освобождения однобайтного DL11 RBUF между байтами
UART-команд и проходит: 13039379 проверок / 485826386 тактов / 438282 DMA слов.
Проверены конфигурация (1936 КБ), карта памяти, DM1, BASIC, Pascal и Fortran.
PAL принял 3047 байт по порядку, стек 336/640. Полный DIR через PS/2
зафиксирован в первом прогоне; полный повтор использует UART.
На физическую плату установлена **7CBA**: FLASH Erase/Program/Verify прошла.
На прежней SD прошли RT-11 XM с RH0, полный каталог через UART и PS/2
(214 файлов / 5346 блоков / 48310 свободных), SHOW CONFIGURATION/MEMORY,
storage VOL: и диски BAS:/PAS:/FOR:. Пользователь подтвердил нормальное
изображение каталога от PS/2 на PAL. RT-11 V4 с RK0 прочитала полный каталог
(106 файлов / 1942 блока) и V4USER.TXT. RSX с RQ1 завершила старт и прочитала
`DU1:[1,54]RSX11M.SYS` (1026 блоков), затем штатно остановлена через SHUTUP.
BSD с RL0 перешла в multiuser/root, смонтировала `/usr` на XP0h; чтение
по 1 МиБ напрямую с RL0, RL1 и XP0h и ещё 2 МиБ с RL0 прошло без ошибок.
В BSD пользователь подтвердил ввод с физической PS/2-клавиатуры; UART
зафиксировал `ls -l /`, компиляцию `cc -v hello.c -o hello` и запуск
`./hello` с выводом `hello`. Эти команды введены после дискового теста;
заполнение FIFO одновременно с длинным чтением на плате не зафиксировано.
После проверки UART освобождён, плата оставлена в BSD на приглашении root.
Это ограниченный аппаратный прогон: прежний сбой RL после длительного
простоя ещё нельзя считать устранённым.
Точные исходники и журналы сохранены в
[checkpoint 7CBA](../releases/hc7000-ps2-idle/README.md).
