# Время RT-11 с хоста и часы на HDSP

`HGTIME.SAV` получает локальную дату и время компьютера через HG и устанавливает
**системные дату и время RT-11** вызовом `.SDTTM`. После этого `DATE`, `TIME`
и программы RT-11 видят установленное значение. `CLOCK.SAV` / `CLOCK.REL` читают часы
монитора через `.GTIM` и показывает их на HDSP. Изменения RTL, микрокода,
FPGA-прошивки и FRAM-модулей для этого не нужны.

Комплект от 2026-09-22 собран и проверен в RT-11FB V05.03 под SIMH.
В тот же день установлен на HC1200: синхронизация и ход системных часов,
выход CLOCK по Q проверены через UART. [Аппаратный отчёт](../releases/hg/hardware.json).
Версия CLOCK 01.01 от 2026-09-26 добавляет `CLOCK.REL` и параллельную работу
с background-консолью; [проверка на плате](../releases/hg/foreground.json).

## Установленный стенд

На `sash@192.168.1.108` новый демон запускается командой:

```sh
/home/sash/Work/FPGA/uj11-hg/start-hg.sh
```

Она обслуживает каталог `share` рядом со сборкой на 1000 Гц. На SD установлены
`HG.SYS`, `HGTIME.SAV`, `CLOCK.SAV`; обратные копии всех трёх файлов совпали
с релизом по SHA256. Старый драйвер сохранён как `SY:HGOLD.SYS` и на хосте
в `share/HGOLD.SYS`; его SHA256 совпал с прежним файлом из Git.

При завершении установки HG 2026-09-22 драйвер выгружен, демон остановлен, а `CLOCK` оставлен
запущенным. Для повторной синхронизации выйти из CLOCK по Q, запустить демон,
в RT-11 выполнить `LOAD HG` и `RUN HGTIME`. Затем `UNLOAD HG`, остановить
демон через Ctrl-C и снова `RUN CLOCK`. UART `picocom` после проверки восстановлен.

## Установка

На компьютере, к которому подключён FT2232:

```sh
make -C lsi11-fpga/host/hg test all
```

Поместить четыре готовых файла в **новый** каталог обмена HG и запустить
обновлённый демон. Например, для местного времени Еревана:

```sh
TZ=Asia/Yerevan lsi11-fpga/host/hg/hgfsd --directory /path/to/new-share --clock 1000
```

Без `TZ` используется системный часовой пояс хоста. Уже существующий
`.hg-volume.dsk` является основным содержимым HG: простая замена файлов
рядом с ним не обновит образ. Новый каталог устраняет эту неоднозначность.
Для клавиш/общих выводов соблюдать [порядок JTAG/HG](user-guide.md#передача-через-hg).

Сначала старым рабочим HG скопировать обновление под временным именем.
`HGOLD.SYS` ниже — резервная копия; выбрать свободное имя, если оно занято.

```text
.LOAD HG
.COPY SY:HG.SYS SY:HGOLD.SYS
.COPY HG:HG.SYS SY:HGNEW.SYS
.COPY HG:HGTIME.SAV SY:HGTIME.SAV
.COPY HG:CLOCK.SAV SY:CLOCK.SAV
.COPY HG:CLOCK.REL SY:CLOCK.REL
.UNLOAD HG
.REMOVE HG
.COPY SY:HGNEW.SYS SY:HG.SYS
.INSTALL HG
.LOAD HG
.RUN HGTIME
.DATE
.TIME
.UNLOAD HG
```

Затем остановить демон HG на хосте. Часы запускаются через `RUN CLOCK`
или `FRUN SY:CLOCK`, если нужна доступная консоль RT-11FB.

`UNLOAD`/`REMOVE` нужны, чтобы монитор загрузил новую версию обработчика.
Перезапуск платы и UJMOD не требуются. При обновлении файла через HG нельзя
выгружать обработчик до завершения COPY. `?PIP-W-Reboot` после создания
резервного/нового `.SYS` — штатное предупреждение. В этом порядке действующий
HG сначала выгружается и удаляется из таблицы установленных драйверов, затем заменяется и
устанавливается заново; другие используемые `.SYS` не перемещаются.
[Описание сообщения DEC](https://www.bitsavers.org/pdf/dec/pdp11/rt11/v5.6_Aug91/AA-5284H-TC_RT-11_System_Message_Manual_Aug91.pdf), 3–134.

Успех `HGTIME` печатает `RT-11 SYSTEM DATE AND TIME SET FROM HOST`, затем
установленные часы и день/месяц. Ошибка возвращает fatal completion status
и не вызывает `.SDTTM`: прежние часы продолжают идти. Новый демон совместим
со старыми дисковыми запросами; для времени нужны **обе** новые части.
Старый драйвер или демон не поддерживают запрос времени.

Синхронизация выполняется один раз за `RUN HGTIME`. При необходимости
добавить его в командный файл запуска после `LOAD HG`, когда демон доступен.
Повторный запуск вновь сверяет RT-11 с хостом. Постоянного опроса хоста,
автоматического изменения часового пояса или коррекции DST в RT-11 нет.

## Часы на панели

Формат всех 16 позиций: `HH:MM:SS DD/MM  `. Панель обновляется, когда меняется
строка. **Q, q или ESC через UART** завершают программу и выводят
`RT-11 READY` на HDSP; Enter не нужен. Ctrl-C обрабатывает монитор.

В CLOCK от 2026-09-23 уменьшен пиковый ток HCMS: **4,0 мА вместо 9,3 мА**,
PWM прежний. Настройка программная, FPGA не меняется;
[значения CW0 и расчёт потребления](panel-brightness.md).
Обновлённый CLOCK установлен и повторно запущен после cold boot ODT.
Сверка 2026-09-23: RT-11 `22:36:26`, хост `22:36:26.161–22:36:26.963` UTC+04.
Выход по Q проверен; HG остановлен, CLOCK оставлен работающим.

`CLOCK` работает и без HG: ему достаточно установленного времени RT-11.
Он не обращается к хосту и не сканирует клавиатурную матрицу. После
синхронизации можно выполнить `UNLOAD HG`, остановить демон и затем запустить
`CLOCK`. Это освобождает общие выводы для последующей работы с пультом ODT.
Во время работы HG клавиши матрицы не использовать.

С версии 01.01 от 2026-09-26 ожидание между проверками времени — системный
`.TWAIT` на 100 мс (5 тиков при 50 Гц, 6 при 60 Гц). Он освобождает процессор
для второй задачи RT-11FB. Раньше использовалась инструкция CPU `WAIT`,
которая не переключает задачи монитора. Ошибка выделения элемента очереди
таймера завершает CLOCK с сообщением, а не запускает бесконечный опрос.

Часы не считают пробуждения: источник времени — `.GTIM`.
Поэтому лишнее UART-прерывание не ускоряет секунды. Перенос даты на следующие
сутки выполняет монитор; его возможности на границе месяца/года зависят от
SYSGEN. Запись времени имеет задержку HG-транзакции и не является точной
сетевой синхронизацией. После установки точность зависит от тактов часов платы;
до калибровки короткий замер выявил опережение 0,82%; после неё — 0,068%, см. ниже.
Погрешность самой синхронизации и длительная стабильность не квалифицированы.

### Часы одновременно с командной строкой и программами

В терминологии RT-11 `RUN CLOCK` занимает **background** — ту задачу,
где работает командная строка. Для параллельной работы часов используется
**foreground** и отдельный перемещаемый файл `CLOCK.REL`:

```text
.FRUN SY:CLOCK
```

После запуска командная строка остаётся доступной. **Ctrl+B** направляет
ввод в background, **Ctrl+F** — в CLOCK. Для остановки часов нажать
**Ctrl+F, затем Q** (без Enter), **Ctrl+B**, затем:

```text
.UNLOAD F
```

`Q` или ESC завершает программу, а `UNLOAD F` освобождает занятую память.
Часы можно снова запустить через `FRUN`. В RT-11FB доступна одна foreground-задача.
Ошибка `?KMON-F-File not found DK:CLOCK.REL` означает, что REL ещё не
скопирован на выбранное устройство; переименование SAV в REL не заменяет
сборку `LINK/FOREGROUND`.

Сборщик [build_hg.py](../tools/build_hg.py) создаёт оба варианта из одних
объектных файлов; команда foreground-сборки:

```text
.LINK/FOREGROUND/MAP:CLKFG CLOCK,TMDRV,PNLDRV
```

CLOCK занимает дополнительную USER RAM; ресурсы FPGA и HALT FRAM не меняются.

Во время остановки в HALT/ODT RT-11 не обслуживает тики KW11. После длительной
отладки системное время может отстать: выполнить HGTIME после возврата в RT-11.
UJBOOT заново загружает систему и завершает foreground-задачи; после него
повторить синхронизацию и `FRUN SY:CLOCK`.
Одновременно другую программу, управляющую панелью, запускать нельзя:
GPIO/HDSP не имеют арбитра. Перед работой через HG завершить CLOCK и
выполнить `UNLOAD F`; после `UNLOAD HG` и остановки демона запустить часы снова.
Проверка HGTIME параллельно с CLOCK в SIMH подменяет GPIO и **не** является
проверкой совместного доступа к физическим выводам.

Проверки `.REL` включают настоящий FRUN/перемещение, ход часов при доступной
background-консоли, команды DIR/TIME, background-программу HGTIME,
Ctrl+B/Ctrl+F, выход Q/ESC и повторный FRUN/UNLOAD.

**На HC1200 установлено и проверено 2026-09-26.** SHA256 обратных копий
SAV и REL совпали с релизом. При работающем foreground CLOCK выполнены
DIR, TIME и `UJMOD STATUS`; три FRAM-модуля сохранили статус `140407`.
Проверены Ctrl+F → Q, UNLOAD F и повторный FRUN. SHOW MEMORY показывает
**1007 слов / 2014 байт** для CLOCK; background получает 19334 слова
вместо 20341. После UNLOAD F эти 1007 слов возвращаются.
Часы оставлены работающими, консоль направлена в background,
picocom восстановлен, HG остановлен. Старая SAV сохранена на SD как
`SY:CLK926.SAV`. Отдельного визуального подтверждения foreground-режима
на HDSP пока нет. [Журнал и хеши](../releases/hg/foreground.json).

## Интерфейс программ

Функция драйвера — `.SPFUN 200` (номер восьмеричный):

```text
.SPFUN #AREA,#channel,#200,#buffer,#3,hz,#0
```

Перед ней нужен `.LOOKUP` устройства `HG:`. `AREA` занимает шесть слов,
буфер — три слова; `hz` содержит 50 или 60 **десятичных** тиков в секунду.
Последний аргумент задаёт ожидание завершения. Драйвер проверяет функцию,
размер и частоту. Ошибка возвращается обычным механизмом I/O completion.
Получение буфера само по себе не меняет часы: это делает вызывающая программа.

`HGTIME` читает конфигурацию монитора через `.GVAL` по смещению `0300`:
`CLOCK$=100000`, `CLK50$=40` (восьмеричные). При отсутствии часов он прекращает
работу. Наша RT-11 V5.03 собрана на 50 Гц; поддержка поля 60 Гц предназначена
для соответствующего монитора. Смена одного флага не заменяет его SYSGEN.

### Расширение протокола HG v1

| Поле заголовка | Значение для TIME |
|---|---|
| magic / version | `HG` / 1 |
| operation | 3, без MORE |
| unit | 0 |
| block, 16 бит LE | Частота тиков: 50 или 60 |
| count, 16 бит LE | 6 байт |
| checksum | XOR первых девяти байтов заголовка |

Ответ: байт status; при status=0 ещё шесть байтов данных и 16-битная
little-endian сумма **байтов** данных. Это тот же формат, что у READ.
TIME разрешён и с `--read-only`, не читает/не пишет блоки диска.

| Слово буфера | Содержание |
|---|---|
| 0 | Дата RT-11: age[15:14], месяц[13:10], день[9:5], год[4:0] |
| 1 | Старшие 16 бит числа тиков с местной полуночи |
| 2 | Младшие 16 бит числа тиков с местной полуночи |

Каждое слово передаётся младшим байтом вперёд; старшее слово счётчика идёт
**перед** младшим, как требует `.SDTTM`. Год = 1972 + 32×age + year.
Для V5.03 здесь разрешены **1972–2035**: дата с установленным знаковым битом
не подходит этому варианту `.SDTTM`. Хост проверяет календарь и диапазоны,
включая високосные годы. Непредставимое время возвращает ошибку. Гость
проверяет checksum, положительную дату и `ticks < 86400×hz`, прежде чем
менять системные часы.

## Сборка и проверки

Из `uJ11-fpga`, с новыми каталогами результатов:

```sh
make hg HG_OUT=build/hg-new
make test-hg-time HG_TEST_OUT=build/test-hg-new
```

Нужны SIMH `pdp11`, `../lsi11/rt11tool`, исходный образ RT-11 V5.03,
C compiler, `pkg-config` и `libftdi1` для демона. MACRO/LINK работают на
частной копии диска; SHA256 исходного образа проверяется после сборки.
Listings, maps, objects, console logs и `build-inputs.json` остаются в `build/`.

Проверено 2026-09-22:

- Хост: 23 808 календарных случаев, 50/60 Гц, границы времени и некорректные
  заголовки; настоящий request dispatcher с моделью транспорта; регрессия
  чтения/записи HG и read-only.
- RT-11: 56 случаев даты/форматирования; реальный `.SPFUN` и обработчик
  заголовка/данных/checksum; `.SDTTM`, команды DATE/TIME, CLOCK, выход Q/ESC
  и перенос 22→23 сентября через полночь.
- Status error, checksum error, timeout, нулевая дата, суточный предел и
  слишком большой счётчик не меняют системное время.

В SIMH смоделированы GPIO handshake/передача байта и вывод PNLDRV; физические
электрические сигналы HG/HDSP этим не проверяются. 60 Гц проверены на хосте

Это два коротких замера в разные дни, а не обещание точности за час/сутки.
Оценка OSCH на этот раз ≈29,822 МГц; фиксированная поправка делителя
не устраняет изменения самого RC-генератора. Температура, питание и длительный
дрейф пока не исследованы. Делитель подходит этому экземпляру платы;
для другой платы его нужно измерять отдельно. CPU, UART и OSCH не перенастроены.

Для повторения замера есть диагностический
[TMRATE.MAC](../demos/rt11/panel/TMRATE.MAC). Он печатает конфигурацию и 121
пару старшего/младшего слов `.GTIM`, примерно через каждые 50 тиков.
На SD стенда уже установлен `TMRATE.SAV` (1024 байта). Сборка из `uJ11-fpga`:

```sh
python3 tools/rt11_build.py demos/rt11/panel/TMRATE.MAC --out build/tmrate-new
```

На Linux-хосте платы после доставки SAV через HG и освобождения HG-пинов:

```sh
python3 tools/hardware_clock_rate.py --port /dev/ttyUSB1 --pause-pid PID \
  --out build/clock-rate-new --divisor 596037 --interrupt --resume-clock
```

Нужен действительный PID `picocom`, если он держит UART; иначе убрать
`--pause-pid`. `--interrupt` останавливает текущую BG-программу двумя Ctrl-C,
`--resume-clock` после успешного замера запускает CLOCK. Runner использует
монотонное время Linux, сохраняет raw samples и UART log, затем восстанавливает
читателя UART. Переводить системное время во время замера нельзя.
`--divisor` обязателен: указать делитель реально прошитой версии
(591200 для CP67b, 596037 для калиброванной сборки). Он используется только
для косвенной оценки частоты OSCH; частота тиков вычисляется из UART-отметок.

### DEC-документация

- [RT-11 System Macro Library](https://bitsavers.org/pdf/dec/pdp11/rt11/v5.6_Aug91/AA-PD6LA-TC_RT-11_System_Macro_Library_Manual_Aug91.pdf):
  `.GTIM` (2–123), `.SDTTM` (2–236), `.SPFUN` (2–257), `.TTINR` (2–273),
  `.TWAIT` (2–278).
- [Introduction to RT-11](https://www.bitsavers.org/pdf/dec/pdp11/rt11/v5.6_Aug91/AA-5281E-TC_Introduction_to_RT-11_Aug91.pdf):
  глава 5, FRUN, Ctrl+B/Ctrl+F и UNLOAD F.
- [RT-11 Device Handlers](https://bitsavers.trailing-edge.com/pdf/dec/pdp11/rt11/v5.6_Aug91/AA-PE7VA-TC_RT-11_Device_Handlers_Manual_Aug91.pdf):
  special functions, SPFUN$/`.DRSPF`, очередь I/O.
- [RT-11 System Internals](https://bitsavers.trailing-edge.com/pdf/dec/pdp11/rt11/v5.6_Aug91/AA-PD6NA-TC_RT-11_System_Internals_Manual_Aug91.pdf):
  configuration word и JSW. Имена новых convenience macros из позднего
  SYSMAC не предполагаются: исходники собираются библиотекой V5.03.
