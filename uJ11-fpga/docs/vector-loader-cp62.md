# CP62: файловый UJLOAD через HALT-вектор

Профиль `--loader-cp62`, без MMU. Цепочка старта CP61 сохранена:
ROM → HALT FRAM → копирование bootstrap в USER FRAM → START → RT-11.
Новые файловые операции выполняются загружаемой программой PDP-11 в HALT
FRAM. В RTL не добавлены состояния, регистры или инструкции.

## Два уровня резидента

Постоянный загрузочный вход остаётся по HALT-вектору `000170/000172`.
Как в CP61, R4=`125061`, R5=USER source, R1=HALT destination и R2=1..64
переносят слова с проверкой чтением обратно. CP62 добавляет **R2=0**:
после проверок адресов передать управление на HALT-адрес R1. Это явный
вызов ранее записанного кода; копирование само код не запускает.
Параметры этого низкого уровня доверенные, это не изоляция пользовательских
процессов. Нельзя исполнять данные или перезаписывать работающий резидент.

ROM имеет прежние 164 байта резидента и 50 байт начальной процедуры.
Для размещения `JMP (R1)` проверка нулевого count перенесена в конец
проверок, а `SUB #2,R5` при холодном переносе bootstrap заменена на
`TST -(R5)`. Последняя выполняет обычное чтение HALT-копии bootstrap;
декремент остаётся равен двум. Адреса initialize, copier, fault и idle
сохранены. Microstore по-прежнему содержит 1002 слова.

UJLOAD перед командной строкой копирует встроенный HALT helper из своего
USER-буфера в HALT `001000..001707` четырьмя вызовами резидента (64/64/64/36
слов), затем вызывает его с R2=0. **456 байт helper входят в UJLOAD.SAV,
а не в firmware EBR.** Исходник `firmware/cp62/loader.asm`, генератор
`tools/build_loader_cp62.py`; таблица `.WORD` в MACRO-файле генерируется
из собранного бинарника и проверяется по хешам.

Нужен FPGA-профиль CP62. Это не универсальный автодетектор произвольного
PDP-11: HALT на другой машине может остановить её. Старый UJLOAD ABI1
сохранён отдельно для CP60; CP61g/CP62 запрещают его USER-инструкции.
В CP61 нулевой count ещё не означает вызов: новый UJLOAD отвергает его
ответ до установки модулей. Файлы и бинарники разных ABI не смешивать.

## Вызовы helper

USER descriptor: operation, raw HALT address, value/count, USER source.
Последнее слово используется только копированием блока. R5 указывает на
descriptor; R1=`001000`, R2=0, R4=`125061`, затем HALT. Операции ниже
пронумерованы десятично:

| Operation | Действие |
|---:|---|
| 0 | Прочитать физическое слово HALT FRAM |
| 1 | Записать слово и сравнить чтение обратно |
| 2 | Установить ready mask 0..3 и выбрать ODT/fallback |
| 3 | Получить прежнее status word, включая ready |
| 4 | Инициализировать общие переходы при ready=0; вернуть `125062` |
| 5 | Сумма 1..8 физических слов modulo 65536 |
| 6 | Обнулить 1..8 слова, проверить каждую запись |
| 7 | Перенести 1..8 слова USER → raw HALT, проверить каждую запись |
| 8 | Проверить, что каждое из 1..8 слов равно нулю |

R2=0 означает успех, R2=1 — неверный запрос или ошибка доступа/readback.
R0 возвращает данные/status/checksum, если операция их определяет.
R0/R1/R2/R3/R4/R5 рабочие; SP не используется, START восстанавливает CPSW.
USER-обёртка UJLOAD сохраняет свои регистры на обычном стеке RT-11.

Все адреса слов чётные, block count ненулевой и не больше 8. Запись и
блочные операции не допускают адресов ниже `001000`. Конец raw диапазона
может быть ровно 65536, но не выходить за него; последнее слово `177776`
и физическая память под I/O page доступны. USER-источник должен целиком
находиться ниже `160000`. Raw операции не выбирают устройства I/O.

Helper временно направляет SEL004 на собственный отказ, возвращает R2=1
и восстанавливает адрес `000312` перед START. Чтение самого слова 004
возвращает сохранённое значение до входа helper, поэтому проверка общего
ABI не сравнивает с временным обработчиком.

## Размещение ABI2

Все адреса в таблицах восьмеричные, размеры десятичные.

| HALT RAM | Назначение |
|---|---|
| `000100/000102` | Аппаратные CPC/CPSW |
| `000160` | Прежний адрес HALT→USER copier |
| `000164` | ODT wrapper `002000` либо fallback `000326` |
| `000166` | Адрес общего возврата `001700` |
| `000170/000172` | Постоянный загрузочный HALT-вектор `000200/000340` |
| `000200..000443` | Холодный резидент, его проверки и copier |
| `000320/000322` | После инициализации: `JMP @000164` |
| `001000..001707` | Загружаемый helper, включая общий возврат |
| `002000` / `002020` | Wrappers ODT / FP11 |
| `004000..004651` | Копия SD bootstrap, восстанавливается при cold reset |
| `010000..037777` | ODT: 12288 байт |
| `040000..177777` | FP11: 49152 байта |

Системе отведены первые 4096 байт HALT RAM. Поэтому bootstrap при reset
не повреждает слоты модулей. Это использование второго банка 64 КиБ,
а не линейные 128 КиБ для RT-11, и не MMU/RT-11XM.

Формат файла прежний: один блок заголовка, payload, нулевой padding.
File version=1, **firmware ABI=2**; ODT base=`010000`, FP11 base=`040000`.
Остальные поля, суммы, проверка точного размера файла и BSS следуют CP60.
Исполняемые entry/fault должны оставаться ниже `160000`; верхние 8 КиБ
физического слота FP11 доступны для данных через raw обращения.

## Установка и возврат модулей

Файлы читает только RT-11 через `.LOOKUP/.READW/.CLOSE`, ввод — `.GTLIN`.
Поддерживаются STATUS, OFFODT, OFFFP, EXIT и имя 1–6 букв/цифр для SY:*.BIN.
До принятия заголовка ready и слоты модулей сохраняются; служебный helper
и аппаратный контекст при этом уже могут быть обновлены.

Если другой модуль готов, UJLOAD проверяет общие слова 004/006/166/010/012.
При расхождении он отказывается от установки до отключения целевого модуля.
Для восстановления можно отключить оба модуля и снова запустить UJLOAD.
Затем целевой ready снимается; payload пишется с readback, BSS обнуляется,
весь payload перечитывается для суммы, вся BSS проверяется по каждому слову.
Wrapper пишется и проверяется последним, после чего выставляется ready.
Ошибка или CTRL/C после начала переноса оставляет целевой модуль отключённым.

HALT-вектор никогда не заменяется вектором ODT: обычный HALT без сигнатуры
попадает через `JMP @000164` в выбранный wrapper либо в fallback. Wrapper
выполняет `MOV #fault,@#004; JMP @#entry`. Вектор FP11 `010/012` указывает
на его wrapper, а аппаратный ready разрешает вход. Файлы тестов содержат
только короткие обработчики, не полноценный ODT или эмулятор FP11.

**ABI2 модуль возвращается через `JMP @000166`**, а не прямой START.
Общий возврат восстанавливает SEL004 для загрузочного входа и выполняет
START. Он сохраняет R0–R6 и не использует стек. Сам модуль обязан сохранить
изменяемые регистры и старый SP; CPSW содержит флаги прерванной программы.
RT-11 и её дисковые функции внутри HALT вызывать нельзя: IRQ отложены.

Cold reset снимает ready и восстанавливает холодный резидент/bootstrap;
слоты ODT/FP11 сохраняют данные, но автоматически не включаются. RESET
периферии сохраняет прежнее поведение. Полные ODT/FP11, внешний HALT,
SEL174/274 остаются отдельными задачами; FIS остаётся в микрокоде.

## Размер блока и CTRL/C

Вариант с 32 словами отклонён: при замене большого FP11 файла тестовые
два CTRL/C не остановили загрузку, ready был опубликован. Максимальный
HALT-copy занимал 59339 clocks (~2,007 ms); вход UART имеет один holding
register. Финальный предел — **8 слов**, copy занимает 19571 clocks
(~0,662 ms). В целевом RTL-тесте UART прочитал оба CTRL/C, overflow=0,
замена остановилась и сохранила другой модуль. Между стартами входных
символов тест выдерживает около 52314 clocks (~1,770 ms). Непрерывный поток
115200 baud отдельно не проверен; это не доказательство FIFO-устойчивости.

## Измеренный synthesis

CP62a, LCMXO2-1200HC-4SG32C: **1229 LUT / 343 FF / 6 EBR / 616 slices**,
**Fmax 32,087 MHz**. Полные MAP/PAR/TRACE с gate 31,824 MHz и прежними
FRAM budgets прошли. От CP61g: 0 LUT/FF/EBR и неизменный Fmax.
Осталось 51 LUT, 24 slices, 1 EBR и 22 microinstructions.
Номинальные CPU/SCK 29,56 MHz; реальные PCB delays/SCK ещё не измерены.
Нового JED/прошивки платы нет; установлен CP56a, default профиль CP52a.

## Финальные проверки

42 полных RTL file/command cases + CTRL/C + cold reboot — PASS:
**971335085 clocks, 16863737 retired, 232675 upper writes, 3713 UART bytes**.
Источник и disk backing проверены по SHA-256 и не изменялись. UART сверялся
по start/data/stop bits; в CTRL/C приняты два символа, RX overwrite=0.
Верхний банк сравнивался целиком после каждого случая; CPC/CPSW исключены
из статического scoreboard, их семантика покрыта отдельными CPU/boot tests.

Проверены оба типа и повторная загрузка; 12 неверных заголовков/размеров;
checksum/padding; SD read failure с возвратом RT-11; write-protected target;
порча после первого readback; повреждение return vector 166 и восстановление;
HALT → SEL004 → общий START и FP11 → общий START, сохранение R0/R1/SP;
почти полный physical FP11 slot; CTRL/C, повторная установка и cold reset.
Модули при этом — тестовые stubs, не монитор/эмулятор.

17 cold/copy/execute cases и 17 helper boundary cases прошли на portable
и Lattice ROM. Включены последний raw word, полный верхний endpoint,
wrap/count/alignment/protected-low range, SP/NZVC и обе банки памяти.
6 host tests формата ABI2 и 4 clock checks PASS. MACRO/LINK — 0 ошибок,
UJLOAD.SAV 4096 байт, code/data 3566 байт, начальный PC 001000.

[Verification](verification-cp62.json), [synthesis](synthesis-cp62.json),
[архив источников/логов](../tb/reports/cp62/). Отклонённый вариант с блоком
32 слова сохранён в rejected32; его не использовать как готовый загрузчик.

## Воспроизведение

Из `uJ11-fpga`, новые каталоги для сборки/прогона:

```sh
python3 tools/build_vector_loader_cp62.py
python3 tools/build_loader_cp62.py
python3 tools/rt11_build.py demos/rt11/service/cp62/UJLOAD.MAC demos/rt11/service/cp62/UJCHEK.MAC --out build/cp62-asm-new
python3 tools/run_loader_cp62.py --asm-dir build/cp62-asm-new --tag cp62new
python3 tools/test_halt_boot_cp62.py
python3 tools/test_loader_gate_cp62.py
python3 -m unittest discover -s tb -p test_service_image_cp62.py
python3 tools/checkpoint_board.py cp62new --loader-cp62 --clock-mhz 31.824 --fram-timing
```

`--assemble` у двух builders использует существующий microasm11 read-only;
все выходы пишутся только в uJ11-fpga. MACRO/LINK работают в SIMH на отдельной
копии диска. Testbench выполняет реальный RTL с SPI FRAM/SD и UART; файлы
в штатном прогоне читает RT-11, регистра CPU не подменяются.
