# PSW-операнды программного FPP J‑11

FP11.MAC **00.12** обрабатывает операнды по адресу **177776** через
сохранённый USER PSW. Чтение или запись живого HALT PSW здесь было бы
ошибкой: HALT-контекст принадлежит эмулятору, USER-контекст — выполняемой
программе. Реализация полностью программная, в HALT FRAM.

**Установлен на плату 2026-09-19:** SD readback, cold init, 22 PSW/FPS шага, 43 шага регрессии и native FPTST — PASS. [Аппаратный журнал](../history/README.md). FPGA остаётся CP67b.
RTL, микрокод и FPGA CP67b не менялись: **+0 LUT / +0 FF / +0 EBR /
+0 microinstructions**. Последние аппаратные числа прежние:
1244 LUT / 381 FF / 7 EBR / 628 slices, TRACE 32,032 MHz,
рабочая номинальная частота 29,56 MHz. Повторный synthesis не выполнялся.

## Контракт

Основание — DEC *DCJ11 Microprocessor User's Guide*, October 1983,
§1.3, Figure 1-3, Table 1-3 и chapter 7 (LDFPS, STFPS, STST, STEXP,
STCfi): [локальный оригинал](../../doc/EK-DCJ11-UG-PRE_J11ug_Oct83.pdf).
Это продолжение программного [профиля DCJ11 CP79](fpp.md).

| Обращение | Результат |
|---|---|
| Чтение слова 177776 | Сохранённый USER PSW; зарезервированные PS<10:9> возвращаются нулями |
| Запись слова 177776 | Меняется сохранённый USER PSW; T сохраняется, PS<10:9> обнуляются |
| NZVC после явной записи PSW | Сохраняются биты записанного слова; флаги STEXP/STCfi не перезаписывают их |
| FPS после STEXP/STCfi | Получает собственные флаги результата преобразования, независимо от записанного PSW |
| Нечётное слово 177777 | Обычный address fault; не алиас PSW |
| Следующее слово после 177776 | Адрес 000000, с обычным внешним доступом |
| Ошибка последующего слова | Предыдущая запись PSW сохраняется; её значение входит в trap frame |

Пример: `STCFI AC0,@#177776` при AC0=+1 записывает в USER PSW
значение 000001 (с сохранением прежнего T). CPU C становится 1 из
записанного слова, а FPS NZVC становятся 0000 по результату преобразования
+1. При AC0=0 PSW получает 000000, но FPS Z=1. Это намеренно разные флаги.

Перехват применяется и к указателям косвенных режимов, индексному
смещению, immediate/absolute и каждому слову многочастного операнда.
Например, длинный операнд может начинаться на 177774, проходить через
PSW и продолжаться на 000000. Обычные чтения/записи оставлены за MFUS/MTUS.

## Реализация

В [FP11.MAC](../firmware/fpp/FP11.MAC) `USGET` повторяет семантику
MFUS: читает слово и увеличивает R5 на 2. `USPUT` повторяет MTUS:
уменьшает R5 на 2 и пишет слово. Только адрес 177776 обслуживается
локально через `REGS+20`, остальные обращения выполняют прежнюю
служебную команду. При входном R5=0 назначение MTUS равно 177776.

Слово BSS `PSWWR` сбрасывается при входе в каждую FP-инструкцию и
отмечает успешную явную запись. Общий выход STEXP/STCfi пропускает
обновление CPU NZVC при установленном признаке, но всегда фиксирует
флаги FPS после успешного завершения всех operand accesses.

Автоизменение R0–R6 фиксируется после успешного операнда; изменения PC
при потреблении instruction stream сохраняют прежний контракт.
Bus error покидает вспомогательную подпрограмму через общий аварийный
выход, восстанавливающий USER SP. На стеке эмулятора не остаётся
невыполненного возврата. IRQ/trace/ODT получают управление на прежней
границе окончания FP-инструкции.

| Область | Адрес/размер |
|---|---|
| Начало модуля | 060000 |
| Проверяемый неизменяемый образ | 2172 слова / 4344 байта |
| BSS и стек включены в размещение | 4614 байт, **+96 байт к CP79** |
| Конец размещения, exclusive | 071006 |
| Место до 160000 | 28154 байта |

Адреса FPS/FEC/FEA/AC изменились. ODT получает их через прежний descriptor
v1 на 060010, поэтому бинарный ODT CP77 не требует изменений. Это описание абсолютного образа CP80. Текущая сборка использует
relocatable format4 / ABI3; preferred BASE остаётся 060000, но UJMOD AUTO
может выбрать другое место. ODT теперь находит descriptor по активному
FP-вектору и таблице модулей. Семантика PSW-операндов не менялась.

## Накладные расходы

Контроль PSW выполняется программно и добавляет инструкции/обращения
к FRAM. 8512 совпадающих timing samples сопоставлены с CP79 после проверки
SHA256 исходных vectors и границ четырёх частей. Примеры **zero-wait RAM**
(все memory beats, включая HALT instructions/data):

| Opcode / пример | Clocks CP79 → CP80 | Memory beats CP79 → CP80 |
|---|---:|---:|
| 170000 / CFCC | 790 → 803 | 135 → 138 |
| 170102 / LDFPS R2 | 1193 → 1206 | 191 → 194 |
| 170112 / LDFPS (R2) | 1234 → 1290 | 202 → 213 |
| 170137 / LDFPS @#address | 1327 → 1426 | 219 → 238 |
| 172412 / LDF (R2),AC0 | 2146 → 2245 | 343 → 362 |
| 174012 / STF AC0,(R2) | 1802 → 1867 | 283 → 300 |
| 175005 / STEXP AC0,R5 | 2405 → 2434 | 381 → 388 |
| 175405 / STCFI AC0,R5 | 8183 → 8212 | 1914 → 1921 |

Это конкретные одинаковые samples матрицы, не worst-case и не скорость
физической SPI FRAM. Общие +13 clocks / +3 beats приходятся на сброс
признака явной записи при входе. Числовые циклы прежние.
Это историческое сравнение двух версий. Скрипт `measure_fp_cp80.py` и
обе исходные матрицы доступны в [снимке до очистки](../history/README.md).
Текущие прогоны записывают собственные timing samples в `build/fpp/`.

## Границы совместимости

- Исправлены **операнды программного FPP**. Обычная integer-команда
  `MOV @#177776,R0` на установленном CP67b по-прежнему не реализована.
  Аппаратный кандидат CP78 не помещается в HC1200.
- FPP использует word accesses. Байтовые MOVB/MFPS/MTPS не проходят
  через эти помощники; новый байтовый PSW interface не добавлялся.
- Mode/RS сохраняются как метаданные прежнего CP67; переключение
  банков R0–R5 и отдельных SP не добавлялось. MMU отсутствует.
- CP67 может хранить reserved PS<10:9> через RTI/START. Перехват чтения
  скрывает их, явная запись обнуляет. Остальной CPU не менялся.
- Opcode reread и построение trap frame сохраняют raw MFUS/MTUS.
  Исполнение opcode из PSW и размещение trap stack на PSW не заявляются.
- Совпадение с физическим DCJ11 и внешняя полная J‑11 FPP диагностика
  остаются отдельными задачами. Тесты FP11-A не заменяют эту проверку.

Проверка текущих исходников: `python3 tools/test_fpp_psw.py --mode sync`;
также доступны `logic` и `vendor`. [Сборка](development.md).
