# Модули HALT FRAM

UJMOD 04.00: форматы файлов 2/3/4, неизменный ABI 3. Доверенный ROM проверяет общую таблицу и вызывает
инициализатор каждого включённого модуля. Тип модуля не кодируется в таблице.
Текущий комплект — ODT, SDBOOT и FPP; [версии и размеры](software.md),
[установка и восстановление](user-guide.md), [переключение FPP](configuration.md).

## Таблица и адреса

Все адреса ниже восьмеричные, относятся к верхним 64 КиБ HALT FRAM.
Основная USER RAM остаётся отдельными нижними 64 КиБ.

| Область | Назначение |
|---|---|
| `000000..005777` | Векторы, resident, стек, helper, копия резервного bootstrap, cold walker |
| `006000..006777` | 512 байт для малого модуля; сейчас SDBOOT |
| `007000..007077` | Восемь записей по четыре слова |
| `007100..007277` | Метаданные полного размещения: 8 записей по 8 слов |
| `007300..007777` | Системный резерв, запрещён для образов |
| `010000..157777` | Исполняемые образы; ODT занимает `010000..042707`, FPP — `060000..071005`, включая BSS/стек |
| `160000..177777` | Общая I/O page при обычных обращениях; не исполняемый образ |

| Смещение записи | Поле | Единицы |
|---:|---|---|
| `0` | BASE | Байтовый адрес начала, одновременно точка входа инициализатора |
| `2` | LENGTH | Число 16-битных слов неизменяемого образа |
| `4` | CHECKSUM | Сумма этих слов по модулю 65536 |
| `6` | STATUS | Cookie и флаги |

Образ должен целиком лежать в одном разрешённом диапазоне. Адрес и длина
проверяются до чтения кода: чётность, ненулевая длина, переполнения и I/O.
Загрузчик отвергает перекрывающиеся образы и повторяющиеся BASE.

STATUS: старшие биты `C100` hex, младшие `VALID=1`, `AUTO=2`, `OK=4`, `ERROR=8`.
Иные биты не принимаются. Значения:

| Hex | Octal | Значение |
|---|---|---|
| C102 | 140402 | Запись ещё не опубликована |
| C103 | 140403 | Проверенный образ, включён автозапуск |
| C107 | 140407 | Инициализация в этом обычном старте успешна |
| C10B | 140413 | Ошибка контрольной суммы, диапазона или инициализации |
| C101 | 140401 | Образ зарегистрирован, AUTO выключен |

Нулевые/стёртые/неизвестные записи пропускаются. При обычном старте прежние
OK/ERROR очищаются у распознанных VALID-записей, включая выключенные AUTO.
При принудительном ESC-старте таблица вообще не обрабатывается: её прежние
результаты остаются историческими, `HALT[000074]=1` отмечает recovery.

## ABI инициализатора

Вход — обычный `JSR PC` на BASE, в HALT-пространстве, IPL 7, R0=0.
Возврат — `RTS PC`, R0=0 при успехе, ненулевой при ошибке. R1..R5 можно менять;
SP должен вернуться в исходное состояние. Cold walker сохраняет собственный
стек и курсор независимо от рабочих регистров модуля. Инициализатор не делает
START/STEP и не заменяет принадлежащий walker вектор ошибки `004/006`.

Инициализатор сам очищает изменяемое состояние, устанавливает его ненулевые
начальные значения и проверяет запись векторов. Готовность публикует последней.
При ошибке walker восстанавливает предыдущие ready/debug bits и BOOTPC,
ставит ERROR и продолжает со следующей записью. Произвольные записи модуля в
память автоматически не откатываются: инициализатор отвечает за собственные
побочные эффекты и совместимость с ранее вызванными модулями.

Контрольная сумма включает код, константы, шрифты, раскладку и сам инициализатор.
Изменяемые регистры, breakpoint records, очереди, буферы и стек находятся после
IMMEND и не входят в LENGTH. Их размещение — контракт конкретного модуля.
Сам ROM по-прежнему видит четыре поля. UJMOD хранит полный размер отдельно
по `007100 + slot*020`: magic `110521`, BASE, LENGTH, CHECKSUM, полный размер
в словах, версия метаданных `3`, нуль, дополняющая до нуля сумма восьми слов.
Запись привязана к точному образу и проверяется перед использованием. Она
покрывает неизменяемый код, изменяемые данные, BSS и собственный стек.

При новой загрузке отсутствующие, устаревшие или повреждённые метаданные
резервируют **весь остаток пула** от BASE старого модуля. Это консервативное
правило защищает неизвестный стек старой версии; оно не означает, что тот
модуль действительно использует всю память. Для перехода со старых образов
сначала переустановить ODT, затем FPP и SDBOOT новым UJMOD. Совпадающий BASE
разрешает заменить старую запись. `OFFn` сохраняет полное размещение.

ODT, SDBOOT и FPP теперь собираются с relocation records штатного DEC LINK
`/R`. Файл содержит код, связанный с `001000`, а preferred BASE сохраняет
привычные адреса `010000`, `006000`, `060000`. UJMOD исправляет абсолютные
адреса и PC-relative ссылки на внешние абсолютные адреса, затем вычисляет
сумму **размещённого** образа для четырёхсловной таблицы. ROM не знает о
перемещении. Для каждой сборки перенос на preferred BASE побайтно сравнивается
с независимой абсолютной сборкой того же исходника.

`имя AUTO` ищет первое свободное место в основном пуле `010000..157777` с
учётом полных размеров, включая выключенные VALID-модули. Это новая запись,
а не поиск прежнего модуля по типу: типов в ABI нет. Перед перемещением или
повторной автоматической установкой прежнюю запись нужно удалить через
`DELn`. Команда без AUTO заменяет образ по preferred BASE. Абсолютные файлы
форматов 2/3 с AUTO отвергаются до любых записей. При отсутствии подходящего
места или свободного слота таблица и живые службы остаются прежними.

## Заменяемый bootstrap и независимое восстановление

ROM всегда устанавливает свой resident, cold walker и резервный USER bootstrap
по `004000`. До любого вызова из FRAM он принимает UART ESC. После отпускания
длинного RESET нужно отправить ESC через UART; удобно посылать его повторно.
Окно примерно 2,18 s при номинальных 29,56 MHz, по симуляции CPU/SPI, без
измерения секундомером на физической плате. Иные символы не продлевают окно.
Пульт/ODT/JTAG GPIO для этого не требуются.

ESC пропускает **все** модули и запускает встроенный bootstrap. Это работает и
для модуля с правильной суммой, который зависает или ошибочно выбирает загрузку.
Автоматического watchdog для произвольного зависшего инициализатора нет:
нужно сделать длинный RESET и выбрать ESC. Содержимое FRAM при обходе не стирается.

Перед инициализацией `HALT[000120]` (BOOTPC) получает `004000`.
Обычный модуль может подготовить другой bootstrap в USER RAM и записать его
точку входа в BOOTPC, затем вернуть управление. Walker проверяет чётность и
границу I/O; resident выполняет обычный START с выбранным PC и PSW=0.
При ошибке инициализации выбор откатывается. Это соглашение не вводит тип модуля
в таблицу. `HALT[000122]=007000` — программная метка установленного CP67 walker,
не аппаратная идентификация версии FPGA.

SDBOOT содержит проверенный 426-байтный SD bootstrap CP63b и свой инициализатор:
всего 452 байта. Инициализатор копирует код через resident-вектор `000160`
в USER `004000`, выбирает BOOTPC и возвращается. Образ можно заменить расширенным;
если он больше малого 512-байтного окна, его следует собрать для свободного
диапазона основного пула. Встроенная ROM-копия от этого не меняется.

## Файлы и UJMOD

Файл `.BIN`: 512-байтный заголовок, неизменяемые слова с нулевым дополнением
до блока, а в формате 4 — записи перемещения с отдельным дополнением до блока.
Все смещения в следующей таблице восьмеричные:

| Смещение | Содержание |
|---|---|
| `00,02` | magic `045125,030461` |
| `04,06` | версия файла `2`, `3` или `4`; ABI `3` |
| `10,12,14` | preferred BASE, immutable LENGTH в словах, сумма исходного кода |
| `16` | дополняющая сумма первых 16 слов заголовка |
| `20` | полный размер в словах, только форматы 3/4 |
| `22` | адрес линковки `001000`, только формат 4 |
| `24,26` | количество записей перемещения и сумма их слов, только формат 4 |

Неиспользуемые поля, padding и лишние блоки отвергаются. Формат 2 остаётся
совместимым, но не содержит размера BSS. Формат 3 — абсолютный образ с полным
размером. Формат 4 — relocatable. Старые UJMOD 03.00/UJLOAD новые форматы не
принимают: сначала обновить `UJMOD.SAV`.

Запись перемещения — пара 16-битных слов DEC `.REL`: смещение слова от начала
кода с признаком вычитания в бите 15, затем его исходное значение. Смещения
строго возрастают и лежат внутри immutable image. Повтор, неверное исходное
слово, checksum или padding запрещены. Поправка равна `BASE − 001000`;
она прибавляется или вычитается по биту 15. Источник формата — локальный
[RT-11 File Formats Manual, §2.8](../../lsi11/docs/AA-PD6PA-TC_RT-11_Volume_and_File_Formats_Manual_Aug91.pdf).
Overlays и relocation в изменяемых данных этим профилем не поддерживаются:
начальное содержимое BSS и указатели устанавливает initializer.

`RUN UJMOD` принимает `имя`, `имя AUTO`, `STATUS`, `ON0`..`ON7`, `OFF0`..`OFF7`,
`DEL0`..`DEL7`, `EXIT`. Имя — 1–6 латинских букв/цифр; файл `SY:имя.BIN`.
`ONn` проверяет статус, диапазоны, пересечения и всю сумму сохранённого образа,
затем ставит AUTO без чтения SD и без изменения живых служб. Повторный ON уже
включённого исправного модуля ничего не меняет, включая OK/ERROR. Для старой
записи без метаданных ON проверяет immutable range: он не размещает новый код.
Ошибочная команда/неверная сумма не включают запись.

OFF снимает AUTO, сохраняя размещение; DEL забывает запись, не стирая образ.
Обе операции выключают живые службы; следующий обычный старт переинициализирует
оставшиеся включённые модули. Неверный OFF сначала отвергается, без выключения
служб. Установка сначала проверяет заголовок и таблицу, затем:

1. Выключить службы и записать C102 в STATUS с readback.
2. Скопировать исходный код через HALT helper с readback каждого слова.
3. Проверить входную сумму, padding и независимую сумму всего записанного кода.
4. Применить relocation records, проверяя каждое исходное и записанное слово,
   весь trailer и повторную сумму размещённого образа.
5. Записать BASE/LENGTH/новый CHECKSUM и метаданные полного размера с readback.
   Magic метаданных публикуется последним внутри sidecar.
6. Последним записать C103 в основную таблицу.

После загрузки нужен длинный RESET без ESC. UJMOD не вызывает инициализатор
непосредственно из RT-11. Прерывание копирования оставляет неподтверждённую
запись, которую cold walker пропускает. Этот порядок не заменяет физические
испытания при отключении питания в середине SPI-записи.

ODT при cold init очищает старый сеанс, не применяет сохранённые breakpoint
патчи к новому USER-коду. Прежнюю отлаживаемую программу после reset нужно
загрузить заново. Включение debug-вектора происходит после readback всех данных.
Неизменяемый образ текущего ODT — 12698 байт, BSS/стек — 1070 байт,
всё размещение — 13768 байт (`010000..042707`). Прежнего 12-КиБ окна
для текущего ODT недостаточно; [действующие размеры](software.md).

## Как написать свой модуль

Выбрать BASE с учётом **полного** размещения уже установленных модулей.
Текущий ODT с BSS/стеком занимает `010000..042707`, SDBOOT — малое окно
`006000..006777`, FPP — `060000..071005`. Для короткого примера ниже выбрано
`044000`: его полный диапазон должен закончиться до `060000` и не пересекать
другие установленные расширения. Адрес `040000` уже занят ODT.
Полный размер нужно передать упаковщику; UJMOD проверит пересечения BSS и стеков.

Минимальный пример исходника `MOD.MAC`, который только подтверждает init:

```asm
        .TITLE MOD
        .ASECT
        .=44000
INIT:   CLR R0
        RTS PC
IMMEND:
        .END INIT
```

Это демонстрация ABI, не ODT/драйвер. Для полезного модуля добавить код,
неизменяемые константы до IMMEND, а рабочую память после него. Инициализатор
очищает/заполняет эту память при **каждом** вызове, проверяет результат и
возвращает R0. Нельзя включать меняющееся состояние в проверяемую сумму,
иначе последующий cold boot отвергнет ранее работавший модуль.

После сохранения примера в `uJ11-fpga/build/module-example/MOD.MAC`, из корня
репозитория собрать native MACRO/LINK в новом каталоге:

```sh
python3 uJ11-fpga/tools/rt11_build.py uJ11-fpga/build/module-example/MOD.MAC --out uJ11-fpga/build/module-example/asm
```

Проверить `.LST/.MAP`, entry и диапазоны. `.SAV` — адресный memory image:
в файл модуля идёт срез **BASE..IMMEND**, не весь SAV. Для данного примера
IMMEND=`044004`; у реального модуля взять символ из его assembly listing.
У `module_image.py` нет CLI, используется Python API:

```python
from pathlib import Path
import sys
sys.path.insert(0, str(Path("uJ11-fpga/tools").resolve()))
from module_image import pack, decode

root = Path("uJ11-fpga/build/module-example")
base, immend = 0o44000, 0o44004  # только для примера выше
sav = (root / "asm/MOD.SAV").read_bytes()
image = sav[base:immend]
assert len(image) == immend - base
module = pack(base, image, memory_bytes=immend-base)
print(decode(module))
(root / "MOD.BIN").write_bytes(module)
```

`pack` добавляет header, image checksum и нулевой padding, `decode` независимо
проверяет полученный формат. Это ещё не тест исполнения. До загрузки на плату
проверить инициализатор в RTL, повторный reset, повреждение checksum и recovery;
пример существующих сценариев — [tb_modules.v](../tests/tb_modules.v).
Затем COPY `MOD.BIN` в `SY:`, `RUN UJMOD` → `MOD`, длинный RESET без ESC,
`RUN UJMOD` → `STATUS`. BASE вызывается как обычная подпрограмма независимо
от имени файла: тип модуля в таблице не появляется.

### Перенос между пространствами

ROM после cold reset ставит resident copier и **слово-указатель** `HALT[160]`.
Модуль в HALT может скопировать подготовленный блок в USER:
R1 — HALT-адрес сразу после блока, R5 — USER-адрес сразу после назначения,
R2 — положительное число слов. Вызов `JSR PC,@160` косвенный через resident
pointer; `JSR PC,@#160` имеет другой смысл и здесь неверен. Copier идёт назад,
читает HALT обычным MOV, пишет USER через MTUS и проверяет через MFUS.
Области должны быть чётными и вне I/O; это системная подпрограмма, а не
публичный загрузчик с полной проверкой произвольного входа. Ошибка copier
при доступе к памяти идёт через действующий HALT fault vector; несовпадение
readback ведёт в resident idle/fallback, а не возвращает R0 с кодом ошибки.
В последнем случае для восстановления может потребоваться длинный RESET/ESC.

Именно так [SDBOOT](../firmware/boot/SDBOOT.MAC.in) готовит USER `004000`,
пишет BOOTPC в `HALT[120]` и возвращается через `RTS PC`. Сам модуль не делает
START: после обхода всей таблицы это сделает resident.

Обратный путь USER→HALT при установке организован через signature HALT:
R4=`125061`, R5=USER source, R1=HALT destination, R2=1..64 слова. Resident
проверяет параметры и возвращается в USER через START. R2=0 — вызов helper,
предварительно установленного по `001000`. UJMOD читает файл средствами
RT-11 в USER и переносит/проверяет данные helper-операциями по 8 слов.
Между вызовами RT-11 снова может обслуживать IRQ. HALT helper/initializer
не вызывает RT-11 API: во время службы IRQ/RK assist отложены.
[Резидент и register contract](../history/README.md),
[helper/векторный ABI](../history/README.md).

Обычный возврат `RTS PC` из module init и служебный выход HALT→USER через
START/общий return `166` — разные уровни. Их нельзя взаимозаменять.


## Сборка и проверки

`make software` собирает ODT/SDBOOT/UJMOD/UJBOOT/FPP из `firmware/`.
Формат реализован в [module_image.py](../tools/module_image.py).
`make test-modules` проверяет формат, cold init, checksum, ESC, повторный
RESET и функции UJMOD на текущем RTL. [Все команды разработки](development.md).

## Сборка relocatable-образа

`tools/module_relocation.py` собирает один `.PSECT MODULE,I,RW` штатным
MACRO/LINK `/R`, читает документированные записи `.REL`, проверяет совпадение
при переносе на preferred BASE и упаковывает формат 4. Используется теми же
`build_software.py` и `build_fpp.py`; ручное редактирование BIN не требуется.
Абсолютный исходник/сборка сохраняются для контрольного сравнения и таблиц
символов тестов. Константы аппаратного ABI остаются абсолютными.
ODT ищет активный FPP по HALT-вектору и VALID-записи таблицы, затем проверяет
дескриптор внутри найденного образа: привязки к `060000` больше нет.

## Программный перезапуск UJBOOT

`RUN UJBOOT` из свободной background-консоли RT-11 заново выполняет
инициализацию FRAM-модулей и загружает RT-11. Команда завершает текущие
задачи, включая foreground CLOCK; перед ней закончить дисковые операции.
После загрузки при необходимости выполнить HGTIME и снова FRUN CLOCK.

Это обычный PDP-11 SAV, а не новая FPGA-прошивка. Он загружает через resident
проверяемую программу в HALT `001000`, которая очищает live ready/debug,
исполняет RESET периферии, восстанавливает штатные SDBASE, RESID и cold walker
из вложенных native-сборок с readback, затем передаёт управление resident.
Таблица, метаданные и образы модулей не стираются. Дальнейший путь тот же:
копирование в USER, окно UART ESC, проверка записей, init и SD bootstrap.
Ошибка восстановления удерживает CPU в HALT, не запускает частичный код.

UJBOOT не является аппаратным reset: он требует работающих CPU, RT-11 и
resident и не заменяет кнопку RESET при зависании. Независимое восстановление
через длинный RESET + UART ESC по-прежнему обеспечивается встроенным ROM.
Изменения существующего ROM, RTL или микрокода для UJBOOT не нужны.
