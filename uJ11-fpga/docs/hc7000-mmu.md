# Экспериментальная конфигурация MMU для HC7000

Профиль `CPU=mmu` отделён от выпущенной конфигурации `CPU=mmuless`.
Реализованы MMU, микрокодные ODT и FPP; RT-11FB/XM проверены в симуляции
и на физической плате 2026-09-27. MAP/PAR/TRACE проходят на 24 МГц.
JED записан во FLASH, SD постоянно загружает XM с 22-битной адресацией
и 2 МиБ памяти. Сбой возврата из обработчика FP-ошибки BASIC устранён:
ядро теперь выбирает режим и стек из PSW вектора, включая User/Supervisor.
Исправление проверено на физической плате, частота остаётся 24 МГц.
Экспорт JED требует прошедших и совпадающих по исходникам отчётов Diamond;
сам экспорт не программирует плату.

Готовый SD-комплект с XM, HGX, HGTIME, BASIC и справкой:
[образ для HC7000](sd-image-hc7000.md).

## Сборка

Из каталога `uJ11-fpga`:

```sh
make BOARD=hc7000-lcd-sram CPU=mmu hardware
make BOARD=hc7000-lcd-sram CPU=mmu test
make BOARD=hc7000-lcd-sram CPU=mmu test-rt11 OUT=build/test-mmu-xm
python3 tools/test_mmu_vm.py
make BOARD=hc7000-lcd-sram CPU=mmu synthesis OUT=build/mmu-new-run
make BOARD=hc7000-lcd-sram CPU=mmu export OUT=build/mmu-new-run
```

Synthesis требует Linux с Diamond 3.14, последняя команда — новый каталог
для каждого запуска. `prepare-synthesis` создаёт проект без запуска Diamond.
Те же ограничения SRAM и разводка платы применяются к обоим профилям;
кварцевый генератор 12 МГц, PLL выдаёт 24 МГц.

Для IOP нужен `riscv64-unknown-elf-gcc` либо проверяемый по исходникам кэш
`build/hc7000-mmu-iop`. Firmware занимает 1188 байт из 1536 доступных под код.
Загрузчик собирается штатным DEC MACRO/LINK; сохраняется проверенный кэш
`build/assembly/sdbase-*`. Сами исходники и инструменты mmuless не меняются.

Новые выходы — `build/hc7000-mmu-hardware`, `build/hc7000-mmu-iop`,
`build/test-mmu*` и выбранный `OUT`. Старые `build/hardware`,
`build/hc7000-hardware` и `build/hc7000-iop` остаются отдельными.
Обычный `make` по-прежнему выбирает HC1200/mmuless. Сочетание HC1200/mmu
отклоняется до запуска инструментов.

По умолчанию `test-rt11` использует `../lsi11/disks/rt11v5.3/system.dsk`.
Можно задать `MMU_SD_IMAGE=...`. SD-модель открывает исходный образ только
для чтения; гостевые записи попадают в временную RAM-копию секторов.

### Разделы SD и загрузочное меню SERV

Новый вариант выбирается явно: `CPU=mmu FPP=off IOP=storage`.
Он поддерживает до восьми RK07 в отдельных разделах SD и меню на основе
`lsi11/demo/boot_menu.asm`. Флаг `bootable` задаёт диск для автозагрузки
через 5 секунд; Enter загружает его сразу, другая клавиша отменяет таймер.
Без флага меню ждёт ручного выбора. `IOP=legacy` остаётся значением
по умолчанию и использует прежнюю карту без таблицы разделов.

[Формат карты, утилита и установка меню](serv-storage.md).
Новая конфигурация проверяется отдельно; наличие JED не означает прошивку платы.

### Временная конфигурация без FPP

Для работы над дисковым IOP доступен `FPP=off`; прежний вариант выбирается
через `FPP=microcode` и остаётся значением по умолчанию. Выбор относится только
к `CPU=mmu` на HC7000 и не меняет HC1200/mmuless:

```sh
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off hardware
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off test
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off test-rt11 OUT=build/test-nofpp-xm
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off synthesis OUT=build/mmu-nofpp-new
make BOARD=hc7000-lcd-sram CPU=mmu FPP=off export OUT=build/mmu-nofpp-new
```

При прямом запуске Python-инструментов используется
`UJ11_MMU_FPP=off`; допустимы только `off` и `microcode`.
Генерируемые MMU ROM-файлы общие для вариантов: переключение выполняет
повторную генерацию, а экспорт проверяет соответствие исходникам и ROM.
Одновременные сборки разных вариантов в одном каталоге не поддерживаются.

В отключённом варианте удаляются третий банк микрокода, EBR состояния FP
и арифметический блок. Константа из сгенерированного ROM связывает выбор
микрокода с декодером CPU и позволяет синтезатору удалить FPP. Все инструкции
группы `170000–177777` вызывают reserved-instruction trap по вектору `010`
до чтения операнда; `RTI` восстанавливает контекст. Команда ODT `F` отвечает
`?`. MMU, EIS, ODT, PSW, SRAM, диск и частота 24 МГц сохраняются.

Программы, требующие FP11, включая `B81FPU` и `B81FPD` из SD-комплекта,
потребуют включённого FPP или программного эмулятора; эмулятор здесь не добавлен.
Полный `test-sd-image` проверяет эти программы и требует `FPP=microcode`.
Сам XM-образ не требует изменения для загрузки в варианте без FPP.

MAP/PAR/TRACE `mmu-nofpp-01` (генератор 12 МГц, системный `clk` 24 МГц,
внешние тайминги SRAM проверены):

| Ресурс | Выпущенная MMU + FPP | MMU без FPP | Освободилось |
|---|---:|---:|---:|
| LUT4 | 5651 / 6864 | 3236 / 6864 | 2415 |
| EBR | 25 / 26 | 18 / 26 | 7 |
| FF | 1407 | 1069 | 338 |
| Fmax системного clk | 24.754 МГц | 26.183 МГц | — |

Свободны 3628 LUT и 8 EBR. Отчёты и JED находятся в
[hc7000-mmu-nofpp](../releases/hc7000-mmu-nofpp/README.md).
Повторная сборка включённого варианта `mmu-fpp-switch-01` также проходит
24 МГц: 5682 LUT, 25 EBR, Fmax 24.915 МГц. Таблица выше сравнивает отключение
с ранее выпущенной прошивкой, а не с этой повторной сборкой.

Сам по себе отдельный модуль FPP не гарантирует будущую экономию.
Для компактного возвращаемого FPP потребуется отдельный последовательный
вычислитель с узким трактом и собственным микрокодом.

2026-09-27 вариант без FPP записан во FLASH платы с успешной верификацией.
Проверены новая загрузка XM, 2 МиБ памяти, MMU, чтение каталога SD и
исполнение `SETF`: ожидаемая ловушка `010`, затем возврат к приглашению RT-11.
При этом `SHOW CONFIGURATION` всё ещё сообщает `Floating Point Microcode`
и FIS; эти строки в данном режиме не являются достоверным определением
возможностей CPU. Журналы и тестовая программа сохранены в
`releases/hc7000-mmu-nofpp/hardware/`. SD-образ не переписывался.

## Архитектура и карта памяти

Новый CPU находится в `rtl/mmu`, плата — в `boards/hc7000/mmu`.
Микрокод: `microcode/uj11-mmu.uasm`, `microcode/mmu/odt.uasm`,
`microcode/mmu/fpp.uasm`, `microcode/mmu/fpp-exec.uasm`; отдельный ассемблер — `microasm/uj11mmuasm.py`.

Реализованы K/S/U, current/previous mode, два набора R0–R5, отдельные SP,
PAR/PDR, MMR0–MMR3, 18/22-битная трансляция и выбор I/D. Доступы CPU к
операндам проходят через MMU; MMU CSR декодируются по физическому адресу.
PAR/PDR размещены в одном EBR. Есть защита страниц, W-бит, первый abort с
фиксацией MMR, дельты регистров, переходы через векторы, IRQ и RTI/RTT.
Безусловное соответствие всем особенностям DCJ11 пока не заявляется:
нужны дополнительные тесты restart, trace, стека и редких режимов.

| Физический адрес, восьмеричный | Назначение |
|---|---|
| 00000000–07777777 | Вся SRAM 2 МиБ |
| 10000000–17757777 | NXM |
| 17760000–17777777 | Каноническая I/O page; незанятые CSR дают NXM |
| 00004000–00004777 при холодном запуске | SD bootstrap ROM поверх читаемой SRAM |

Полный адрес проверяется до усечения до выводов SRAM. Служебного VM2
HALT-банка нет; команды и модули старого HALT ABI не используются.
Bootstrap стартует с PC=004000, читает два SD-сектора в низ RAM, затем
снимает ROM overlay. RESET не возвращает overlay; аппаратный reset
возвращает. SRAM очищается полностью только при включении/конфигурации FPGA.

RK611 исполняется на SERV одновременно с CPU. DMA обращается прямо к
нижним 256 КиБ физической RAM; CS1[9:8] содержит A17:A16. Перенос через
64 КиБ обновляет CS1/BA; на границе 256 КиБ адрес оборачивается. Таблицы
MMU CPU не участвуют. Прямой DMA во все 2 МиБ пока не предусмотрен.

## Микрокодный ODT

HALT и короткая кнопка входят в консоль. Команды вводятся через UART;
числа восьмеричные, команды просмотра/записи завершаются Enter.
Приглашение — `>`, ошибка доступа или ввода — `?`.

| Команда | Действие |
|---|---|
| `R n` | Физический слот регистрового файла: 0–5 основной банк, 10–15 второй, 7 PC, 20/21/23 KSP/SSP/USP; 40 PSW |
| `F n` | Слово FP state: 0 FPS, 1 FEC, 2 FEA, 4–7 AC0, 10–13 AC1 и далее по четыре слова на AC |
| `P addr` | Чтение 22-битного физического адреса |
| `M n` | Выбор виртуального пространства: 0/1 KI/KD, 2/3 SI/SD, 6/7 UI/UD |
| `V addr` | Чтение виртуального адреса в выбранном пространстве |
| `W value` | Запись по последнему выбору R/F/P/V с чтением результата |
| `C` | Продолжение, включая возврат в остановленный WAIT |
| `S` | Исполнение одной команды и останов на границе исполнения |

Изменение данных происходит только по W. Просмотр и ошибки доступа
не меняют PC/PSW и сохранённые MMR программы. Физическое чтение I/O имеет
обычные побочные эффекты устройства. Временные регистры микрокода закрыты
для команды R. Дизассемблер, breakpoint и интерфейс старого ODT.BIN пока
не перенесены. STEP при сложных сочетаниях trace/IRQ требует дальнейших тестов.

## Микрокодный FPP

FPS/FEC/FEA и шесть 64-битных AC находятся во внутреннем EBR.
Реализованы управляющие команды, LDF/STF, CLR/TST/ABS/NEG, CMP,
ADD/SUB/MUL/DIV/MOD, STEXP/LDEXP и преобразования I/L/F/D. Есть округление
и усечение, индивидуальные FP exceptions, FID и вектор 244.

Адресацией, памятью, нормализацией, циклами умножения/деления и фиксацией
результатов управляет микрокод uJ11. `rtl/mmu/uj11_mmu_fp_datapath.v` —
отдельный блок временных X/Y/Z и экспонент с одним 16-битным сумматором,
используемым за четыре такта для 64-битных операций. Он не декодирует
команды PDP-11 и не обращается к гостевой памяти. FP11.BIN не используется;
SERV обслуживает только диски.

R0–R6 auto-update при FP-доступе откладывается до успешного завершения;
при abort отклоняется. PC меняется при чтении instruction stream.
Многословное чтение завершается до изменения AC/FPS. При ошибке записи
уже записанные слова памяти видны, но FPS и отложенный auto-update
не фиксируются. У STEXP/STCFI отдельно соблюдаются CPU NZVC и приоритет
явной записи в PSW. Сохранение FP state и повтор D-ADD после page-length
abort проверяются реальным обработчиком вектора 250 и RTI.

Для закрытия timing непосредственные внутренние READ загружают RF через
MDR за дополнительный такт. Разрешение записи RF не зависит от готовности
арифметического блока на тактах, когда этот блок не участвует.

Возможное продолжение — собственный микросеквенсор FPU внутри HC7000
с более узким ROM. CPU тогда оставляет EA/MMU, обмен с памятью и точную
фиксацию AC/FPS/исключений; FPU получает буферизованные операнды и возвращает
результат. Это отдельная оптимизация, которой в текущей реализации нет.
Экономию LUT/EBR и ускорение следует измерять относительно этой версии;
для сохранения 24 МГц такой перенос уже не требуется.

## Проверки и ресурсы

`make ... CPU=mmu test` проверяет изоляцию профилей, ассемблер, 786432
случая трансляции, 3375 проверок MMU-транзакций, CPU/ODT/FPP и повтор после MMU abort,
физическую SRAM-шину и SERV с моделью SD по выводам. Отдельно проверены
ROM/APR/FP EBR с моделями DP8KC установленного Diamond, включая все
3072 слова и удержание выходов ROM при выключенном clock-enable.
`test-mmu-fpp` выполняет 444420 дифференциальных случаев / 17601544
проверки: все FP-коды/адресации, F/D, округление, границы, исключения и
инъекции ошибок памяти. Эталон — общий адаптированный DCJ11 oracle;
математические поправки и ручные DEC-ожидания помечены в существующих
`tests/reference_fpp.c` и `tools/fpp_reference.py`.
`test-rt11` проверяет загрузку, UART по выводам, каталог и SHOW MEMORY;
`test_mmu_vm.py` добавляет копирование на VM: и двоичное сравнение файла.

| Diamond MAP/PAR/TRACE | HC7000 mmuless (`ff11711`) | HC7000 MMU + FPP |
|---|---:|---:|
| LUT4 | 2184 | 5651 / 6864 |
| EBR | 11 | 25 / 26 |
| FF | — | 1407 |
| Microstore | 1024×36 | 3072×54, 1883 слова занято |
| Рабочая частота | 24 МГц | 24 МГц, TRACE Fmax 24.754 МГц |

Отчёты исправленной сборки: `build/mmu-trap-modes-08/{inputs,result}.json` и
`impl1/*.mrp`, `*.par`, `*.twr`. Все входные файлы, включая микрокод,
генераторы и firmware, совпадают по SHA-256 с локальными исходниками.
В 25 EBR входят 18 microstore, APR, FP state, bootstrap и четыре блока
дискового процессора/буфера. Частота генератора платы остаётся 12 МГц,
частота системы — 24 МГц. Проекты `mmu-fpp-area-03/04` сохраняют отчёты
предыдущих вариантов, не прошедших timing; их нельзя экспортировать.

Образ `lsi11/disks/rt11v5.3/system.dsk` (SHA-256
`9350c62f50e2713f56904b7222f2d829f6bf020cd67e28562e3252a48b6993dd`)
загружает XM. ОС определяет всю SRAM, MEMTOP=10000000₈. VM: использует
память выше 01000000₈; копирование RT11XM.SYS с SD в VM:MMUTST.SYS и
BINCOM возвращают `No differences found`. Исходный SD-образ не изменяется.
Строка STARTX.COM `ASSIGN RK0: BAS:` сообщает об отсутствующем RK0;
рабочий системный диск RK611 доступен как DM0.

Полная регрессия `make test CPU=mmuless` проходит. Все 170 исходников
и генерируемых образов прежнего HC1200/HC7000 совпадают с контрольными
хэшами (`build/mmu-baseline/unchanged-final.json`).

На физической плате прошит `mmu-fpp-final-06_impl1.jed`; Programmer
подтвердил FLASH Erase/Program/Verify. На установленной SD уже были XM/DMX,
поэтому замена образа и файлов не потребовалась. После пробного
`BOOT RT11XM` выполнено `COPY/BOOT SY:RT11XM.SYS SY:`. И `BOOT SY:`,
и холодный старт после повторной конфигурации FPGA загружают DM0:RT11XM.
ОС показывает 22-битную адресацию, 2048KB и MEMTOP=10000000₈.
Копирование файла с SD на VM: и двоичное сравнение прошли без различий.
В отличие от симуляционного образа выше, STARTX.COM установленной SD
содержит только `SET TT SCOPE,NOCRLF` и `SET SL ON`; он не менялся.

На исходной сборке 06 B81FPU и B81FPD прошли по 29 числовых сравнений
на плате, B81DBL — проверку точности double. Но `PRINT 1/0` в B81FPU
после сообщения об ошибке привёл к HALT в мониторе вместо READY.
Состояние ODT и исходный неуспешный сеанс сохранены в базовом релизе;
исправление и результаты повторной проверки описаны ниже.

Дополнительный контроль SIMH 3.12-3, CPU 11/73 (определяется как 11/73A),
2048KB, Floating Point Microcode, EIS, MMU, 50 Гц: отдельная копия FB-диска
переведена на постоянную загрузку XM через COPY/BOOT. B81FPU/B81FPD прошли
числовые тесты и обработку исключений как в FB, так и после холодной
загрузки XM; деление на ноль возвращает READY, затем `2+2` даёт 4.
На этой модели SIMH сбой платы не воспроизведён. Команда воспроизведения:
`python3 tools/test_mmu_basic_simh.py --out build/xm-basic-new`.
SIMH дополнительно объявляет Cache Memory и имеет устройства DU/MU;
это контроль на копии исходного FB-образа, не на полном клоне SD платы.

Сбой устранён в `mmu-trap-modes-08`: при входе через вектор Current Mode
ошибочно принудительно обнулялся. Вектор TRAP BASIC задаёт PSW=140000₈;
обработчик должен работать в User mode, но запускался с Kernel SP.
После исправления выбора режима прошли 66 проверок CPU (включая новые
User→User/User→Supervisor и RTI), весь дифференциальный FPP, полный RTL
BASIC и повтор на плате. В обоих BASIC ошибки возвращают READY, затем
`2+2` даёт 4. PSW по 177776₈ уже был реализован и не являлся причиной.
Подробности и прошитый JED: [исправление TRAP](../releases/hc7000-mmu-trap-fix/README.md).

Остаётся расширение покрытия редких особенностей CPU: стековые ограничения,
сочетания trace/IRQ и другие специфические случаи DCJ11. Факт запуска XM
не заменяет эти проверки.

Сохранённая база для сравнения с будущим отдельным FPU:
[`releases/hc7000-mmu-microcoded`](../releases/hc7000-mmu-microcoded/README.md).
