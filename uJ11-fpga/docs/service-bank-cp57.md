# CP57: первый служебный банк без MMU

2026-09-12. Отдельный экспериментальный профиль `--service-cp57` на точных
исходниках установленной CP56a. Default RTL/ROM и прошивка платы остаются
прежними. Этот checkpoint реализует механизм и тестовую PDP-11 firmware;
полные ODT, FP11 и файловый загрузчик RT-11 ещё не готовы.

## Память и контекст

Логический адрес CPU остаётся 16-битным. Один бит `service_mode` выбирает
нижнюю/верхнюю FRAM. Переключение не меняет PSW J-11 и не включает MMU.
Обычные обращения обоих банков сохраняют общую I/O page. Явный физический
доступ обходит все CSR/ROM overlays и охватывает все 65536 байт каждого банка.
RK DMA сохраняет нижний банк. CP56 оставляет read stream только в нижнем
банке; верхний читается обычными SPI-транзакциями без bank-tag/cursor hit.

В окончательном варианте этого checkpoint копии находятся в **верхней
физической FRAM**: CPC — `000100`, CPSW — `000102` (адреса восьмеричные).
Адреса формирует существующая ALU через T5; отдельного контекстного
address/data mux нет. Системные векторы `000004`, `000010`, `000170`,
`000174`, `000274` не пересекаются с копиями. Область `000000..000377`
резервируется для системного ABI; тестовый обработчик начинается с `000400`.

Вход FP11/HALT устанавливает служебный режим, затем микрокод записывает
PC после opcode и полный 16-битный PSW. До первого firmware opcode обе
записи завершены. Стек гостя не используется; R0–R6 общие. Firmware сохраняет
нужные регистры прямыми обращениями к верхнему банку и устанавливает свой SP.
Микрокод использует T0/T4/T5; временные регистры RF не являются частью ABI.

Векторы — два слова PC/PSW верхнего банка: FP11 `000010/000012`,
ODT `000170/000172`. Тестовая firmware загружает их до активации ready.
Весь класс opcode `17xxxx` направляется в FP handler: проверка точного
opcode/режима и исключений FP11 должна выполняться будущим эмулятором.
Это синхронный вход, не маскируемый IPL. FIS остаётся прежним микрокодом.

Во время службы не принимаются IRQ, включая unmasked RK assist, и trace.
START восстанавливает CPC/CPSW, меняет банк и проверяет отложенные IRQ/trace
до следующего opcode гостя. Нельзя вызывать RT-11/disk routines из служебной
firmware: RK assist отложен до возврата. UART/панель обслуживаются polling.
`WCPC` позволяет эмулятору учесть extension words, `WCPS` — обновить PSW.

## Инструкции ABI checkpoint

Все opcode в таблице восьмеричные. Ни одна команда не меняет NZVC сама
по себе, кроме восстановления полного CPSW при START. Чтения возвращают
слово в R0; R1–R4/R6 не меняются. R5 меняется только у MFUS/MTUS.

| Opcode | Доступ | Действие |
|---|---|---|
| `000010..000013` | Только служба | START: восстановить CPC/CPSW и нижний банк |
| `000020` | Только служба | RSEL: R0=`000200`, если FP ready=0, иначе 0; vector base=0 |
| `000021` | Только служба | MFUS: R0=логическое guest[R5], затем R5+=2 при успешном чтении |
| `000022..000023` | Только служба | RCPC: R0=CPC |
| `000024..000027` | Только служба | RCPS: R0=CPSW |
| `000031` | Только служба | MTUS: R5-=2, затем логическое guest[R5]=R0 |
| `000032..000033` | Только служба | WCPC: CPC=R0 |
| `000034..000037` | Только служба | WCPS: CPSW=R0 |
| `000040` | Оба режима | UJRD: R0=верхняя физическая FRAM[R5] |
| `000041` | Оба режима | UJWR: верхняя физическая FRAM[R5]=R0 |
| `000042` | Оба режима | UJCFG: ready={R0[1] FP, R0[0] ODT} |
| `000043` | Оба режима | UJSTAT: R0[7]=!FP ready, R0[1:0]=ready, остальные биты 0 |
| `000044` | Только служба | UJGRD: R0=нижняя физическая FRAM[R5] |
| `000045` | Только служба | UJGWR: нижняя физическая FRAM[R5]=R0 |

UJRD/UJWR/UJGRD/UJGWR не изменяют R5, работают со словом и требуют чётный
адрес. Эти ранее reserved opcode являются явным расширением uJ11. Это
установочный интерфейс, не механизм защиты от пользовательского кода.
HALT-only команды в обычном режиме дают прежний reserved trap `000010`.

UJCFG заменяет оба ready-бита. При обновлении одного модуля загрузчик
сначала читает UJSTAT, сохраняет ready другого модуля и снимает ready
обновляемого **до первой записи**. Затем переносит файл, делает readback /
checksum, публикует векторы и устанавливает ready последним действием.
Пока файлового `.SAV` loader нет, тесты выполняют этот перенос небольшими
PDP-11 программами, не записывая служебное состояние через testbench.

Cold reset снимает оба ready и служебный режим, но не стирает FRAM. Команда
PDP-11 RESET сбрасывает периферию и сохраняет установку. Без ODT ready HALT
использует прежний стековый restart CP56. Без FP ready FP-класс использует
прежний reserved trap. Загрузка RT-11 не требует установленных служб.

## Явные пределы первого checkpoint

Это ещё не полный перенос HALT ВМ2:

- CPC/CPSW фиксируются при входе; непрерывное обновление копий и H/P tracking
  ВМ2 не реализованы. PSW J-11 не переопределён как 9-битный PSW ВМ2.
- STEP `000014..000017` пока reserved. Его нельзя выдавать за START с T-bit.
- Единственный контекст. Повторный HALT/FP в службе останавливает ядро без
  перезаписи копий. Вложенные системные входы ещё не реализованы.
- Любая memory fault в службе пока терминальная. Успешные MFUS/MTUS проверены,
  но точная обработка их ошибок через SEL004, включая MFUS R5+=2 при неудаче,
  остаётся следующей работой. При ошибке самих первоначальных context writes
  копии могут быть частичными; firmware не запускается, гостевой SP не тронут.
- Изменение T в CPSW проверяется при возврате; pending IRQ/trace нельзя
  принимать внутри сохранения, firmware и восстановления.
- Полного FP11 arithmetic emulation/exception0244 и ODT UI нет. Файловый
  формат/ABI version, checksum, прерванная загрузка с диска и RT-11 `.SAV`
  будут проверяться при реализации loader, а не объявлены готовыми сейчас.
- Клавиша панели сама по себе не останавливает исполняющегося гостя.
  Отдельный stop request и арбитраж HG/клавиатуры остаются в TODO.

## Воспроизведение

```sh
python3 tools/build_service_cp57.py
python3 tools/run_service_cp57.py
python3 tools/run_service_board_cp57.py
python3 tools/check_service_cp57_fis.py
python3 tools/run_board.py --service-cp57 --tag cp57-cold
python3 tools/checkpoint_board.py cp57new --service-cp57
```

Последняя команда требует Linux/Diamond и нового имени каталога реализации.
Генератор проверяет SHA-256 frozen CP56a, сохраняет каждое прежнее слово и
label базового микрокода/FIS, размещает расширение в свободных местах и
проверяет коллизии decode для всех 65536 opcode. Generated RTL/ROM/listing/
labels/manifests находятся в `build/cp57-service`; исходники —
`microcode/service_cp57.uasm`, `experimental/cp57/engine-state.vh` и
`tools/build_service_cp57.py`. Сам microstore остаётся 1024×36, четыре EBR.

## Результат gate и проверки

Выбран **CP57e: 1260 LUT, 342 FF, 6 EBR, 635 slices, Fmax 31,982 MHz**,
1000/1024 microinstructions. От CP56a +76 LUT/+3 FF/+0 EBR/−0,014 MHz.
Первые три варианта не прошли MAP (1303/1293/1297 LUT); их отчёты сохранены.
Свободны только 20 LUT и 5 slices, поэтому это экспериментальный proof-of-fit,
а не новый production default. [Пять измерений](synthesis-cp57.json).

Проверено: 44 CPU scenarios × logic/ROM/vendor modes, 10 full-board scenarios
× portable/vendor SPI/EBR, включая FIS внутри служебной firmware; 23840
exact FIS portable и 645 vendor cases (каждый 37-й исходный case). На CP57d
все 23840 FIS cases также прошли в обоих вариантах. 18 assembler и 5 FIS/linker
unit tests прошли. Девять full-board workloads × 2 сохранили все counters CP56.
Cold RT-11FB+DIR — 173379163 clocks, 3270 UART bytes, побайтно как CP56.
EDIF audit: 3180 nets без конфликтующих drivers/необъяснённых floating nets;
три повреждения netlist обнаружены negative controls.

Проверки включают отсутствие/частичную переустановку FP, сохранение ODT ready,
word alignment, RSEL, HALT-only aliases, IRQ7/RK deferral, CPSW16 и trace,
контекст при nested entry, fault при первоначальной записи CPC и FIS в службе.
Ошибка загрузчика с нечётным адресом даёт guest bus/address trap без записи
в верхний банк. Это не заменяет будущие тесты файлового RT-11 loader.

На полном SPI bus вход занимает 258 clocks от commit ENTER до первого
запроса opcode handler; START без pending trap — 120 clocks от первой его
микрокоманды до следующего guest opcode request. Завершение opcode fetch и
исполнение самого handler в эти интервалы не включены.
[Все исходные результаты и hashes](verification-cp57.json).

Плата не перепрошивалась. Внутренний TRACE прошёл при 29,56 MHz; полный
анализ внешних FRAM delays, OSCH duty/jitter и аппаратные измерения для
новой разводки ещё не выполнены. Продолжение: fault/STEP semantics ВМ2,
затем `.SAV` loader и firmware, с контролем оставшихся ресурсов.
