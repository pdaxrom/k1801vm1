# CP64a: проверка конца строки при прокрутке

2026-09-13. Отдельное программное исправление ODT; отсутствие реакции PREV/NEXT
на реальной плате было связано с подключённым к общим пинам JTAG. Пользователь
подтвердил прокрутку после его отключения. Это аппаратное наблюдение относится
к исходной сборке CP64.

При расширении теста найден другой дефект. После `D 143042` и `R 0` команда
`>` могла сдвинуть короткую строку `R0=052525`. Старый обработчик проверял
только байт `RESULT+16+SCROLL`; за ранним NUL там оставался старый текст.
Регрессионный тест на исходном CP64 завершился ошибкой: offset 1 вместо 0.

Теперь обработчик проверяет строку от начала до правой границы предлагаемого
окна и останавливается на первом NUL. Дополнительного состояния нет; сканируются
только байты кэшированного результата в HALT RAM. USER RAM не перечитывается.
Новый payload — **7632 байта**, полное размещение — **8416 байт**, свободно
**3872 байта**. Прирост относительно CP64 — **6 байт**, размер ODT.BIN прежний,
16 дисковых блоков. Пересобран согласованный активатор UJON.

## Проверки

Расширенный электрический стенд исполняет production ODT на CP63 CPU.
Он задаёт замыкания матрицы и собирает 640 бит с выводов HDSP, включая порядок
двух модулей. Проверяются текст и весь поток шрифта для каждого окна:

- Строка с фото: `143042: 004567 177324  JSR R5,142372`.
- Все смещения в обе стороны и повторные нажатия на краях, PREV/NEXT и UART `<`/`>`.
- Удержание NEXT без автоповтора, переназначение функций через K.
- ENTER после команды с extension word, сброс смещения при смене результата.
- Дополнение короткой строки пробелами и отсутствие сдвига за её конец.
- Сохранность R0–R7, PSW, stop metadata и всей USER RAM; отсутствие USER bus
  transactions при прокрутке, отсутствие повторной печати результата в UART.

**97 окон, 3051 проверка, 25966766 clocks — PASS.** Общий направленный тест
монитора: **187 проверок, 175 команд, 5255740 clocks — PASS** (sync ROM).
Logic/vendor варианты для этой программной правки повторно не запускались.

Полный RT-11 → UJLOAD → UJON → stop/step/edit/panel/continue → повторная
активация → cold boot: **83 проверки, 331142525 clocks, 1531 UART bytes,
58 HDSP frames — PASS**, RX overruns=0 при прежнем проверенном темпе ввода.
Оригинальный системный диск не изменялся. [Архив](../tb/reports/cp64a/),
[машиночитаемые результаты](verification-cp64a.json),
[пара ODT/UJON](../demos/rt11/service/cp64a/).

Проверка hardware SHA подтвердила точное совпадение с CP63b. Ресурсы не меняются:
**1230 LUT / 381 FF / 6 EBR**, 1005 слов микрокода; прежний TRACE Fmax
**32,246 MHz**, номинальная частота платы **29,56 MHz**. Нового synthesis нет.

## Воспроизведение

```sh
python3 tools/build_odt_cp64.py --out build/cp64-odt-scroll-fix
python3 tools/check_odt_cp64.py --odt build/cp64-odt-scroll-fix
python3 tools/test_odt_panel_cp64.py --odt build/cp64-odt-scroll-fix --out build/cp64-panel-scroll-fix
python3 tools/test_odt_cp64.py --odt build/cp64-odt-scroll-fix --out build/cp64-core-scroll-fix
python3 tools/run_odt_cp64.py --odt build/cp64-odt-scroll-fix --out build/cp64-rt11-scroll-fix
python3 tools/archive_odt_cp64.py --patch --odt build/cp64-odt-scroll-fix --panel build/cp64-panel-scroll-fix --core build/cp64-core-scroll-fix --rt11 build/cp64-rt11-scroll-fix
```

Использовать свежий каталог для полного RT-11 прогона. Исходная запись CP64
сохранена; `--patch` создаёт отдельные release/report CP64a и не перезаписывает
исторические результаты трёх режимов ROM.

Установка на плату отслеживается отдельно в [журнале](board-bringup-cp64.md);
результат simulation сам по себе не означает установки обновления.
