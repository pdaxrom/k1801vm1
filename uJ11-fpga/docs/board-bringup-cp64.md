# CP64 на HC1200: прошивка CP63b и загружаемый ODT

2026-09-12. По запросу пользователя **CP63b записана во FLASH платы** на
`sash@192.168.1.108`. Lattice Programmer выполнил **FLASH Erase,Program,Verify**
без ошибок. Загрузилась **RT-11FB (S) V05.03**; DIR вывела 117 файлов,
2292 занятых и 51364 свободных блока, затем вернула приглашение.

## Аппаратная сборка

- Профиль `--debug-cp63`: HALT FRAM, кнопка короткого/длинного RESET, STEP,
  FIS и периферия. MMU и FP11 отсутствуют.
- **1230 LUT / 381 FF / 6 EBR**, 1005 слов микрокода.
- Номинальные CPU и FRAM SCK — **29,56 MHz**. **32,246 MHz** — прежний
  результат внутреннего TRACE CP63b, не измерение частоты платы.
- [Точный прошитый JED](../synth/releases/cp63b/design.jed), checksum **EFA7**.
- SHA256: `06b5c627287bb484cea49f6221126282dae791a546b8c02ab0efa6be1a2a0673`.
- Input revision: `ebdbccaf22c452cdf68a6a44dcb94ff6d20f9f16f18dff29008eee3373186341`.

Diamond экспортировал JED из сохранённой routed CP63b. Повторного synthesis
или PAR не было. Проверены исходники и отчёты по исходному manifest,
PRF/EDIF совпали с архивом CP63b. NCD/PRF/EDIF и отчёты не изменились при
экспорте; их hashes до/после сохранены. Утилита `export_board.py` теперь
корректно проверяет также `generated:build.tcl` в новых manifests.

JTAG ID и цепочка проверены до записи. XCF создан из фактического JED,
его timestamp и checksum. UART `/dev/ttyUSB1` захвачен вокруг прошивки:
**3882 байта**, включая boot и DIR. Picocom PID 135981 временно приостановлен,
termios восстановлены, процесс возобновлён и проверен. После прошивки
пользователь подтвердил перевод JTAG_EN в GPIO.

[Журналы и provenance](../tb/reports/cp64-hardware/program/),
[машиночитаемое состояние установки](../tb/reports/cp64-hardware/deployment.json).
Предыдущий [CP56a JED](../synth/releases/cp56a/design.jed) сохранён.
Default сборки остаётся CP52a; для установленной версии выбирается CP63b.

## Установка ODT

Через HG передаются только три файла: прежний CP62 `UJLOAD.SAV` и согласованные
CP64 `ODT.BIN`/`UJON.SAV`. Используется существующий HG.SYS на SD и host daemon
на проверенных 1000 Hz. Образ SD целиком не заменяется. После записи средствами
RT-11 файлы копируются обратно на HG для проверки SHA256; HG должен освободить
общие pins до работы пульта ODT. Все три обратные копии совпали
с исходниками по SHA256. RT-11 выполнила UNLOAD HG, наш daemon остановлен.
UJLOAD сообщил `!UJLOAD-I-ODT READY`, UJON —
`!UJON-I-CP64 DEBUG ENABLED; SHORT RESET ENTERS ODT`.

Монитор занимает **8410 из 12288 байт HALT FRAM**. Ничего дополнительного
в FPGA ROM/EBR не записывается. [Журналы установки и readback](../tb/reports/cp64-hardware/install/).

После длинного RESET или включения питания нужны повторные `RUN UJLOAD`,
ввод `ODT`, затем `RUN UJON`; три файла уже сохранены на SD. Новая прошивка
для повторной установки не требуется. Короткий RESET должен входить в ODT.

Команды и ограничения монитора: [CP64](odt-cp64.md).

## Повторная активация и проверка RESET, 2026-09-13

После перезагрузки платы UART отвечал из RT-11. Повторно выполнены
`RUN UJLOAD`, `ODT`, `RUN UJON`; получены `!UJLOAD-I-ODT READY` и
`!UJON-I-CP64 DEBUG ENABLED; SHORT RESET ENTERS ODT`. Затем пользователь
подтвердил работу входа в ODT по короткому RESET.

При разборе сообщения о неработающих PREV/NEXT пользователь обнаружил,
что JTAG оставался подключён к пинам клавиатуры. Для пульта нужно освободить
общие TMS/TCK/TDI/TDO от программатора, а не только выбрать GPIO в FPGA.
RTL, раскладка и программа ODT по этому сообщению не менялись.
После отключения JTAG пользователь отдельно подтвердил: «прокрутка работает».
Прокрутка HDSP кнопками PREV/NEXT таким образом проверена на реальной плате.

Вход по короткому RESET подтверждён пользователем; полный тест длительного
нажатия и поклавишное соответствие физических надписей кодам отдельно
пройденными не объявляются.

Программное исправление [CP64a](odt-cp64a.md) отдельно собрано и прошло
simulation, но на плату в этом сеансе не загружалось. Текущая установленная
пара ODT/UJON — исходный CP64 с SHA256 из журнала установки выше.
