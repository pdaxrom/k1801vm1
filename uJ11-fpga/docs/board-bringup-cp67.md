# CP67b: прошивка платы и retained FRAM modules

2026-09-13. **CP67b записана во FLASH HC1200**, Lattice Programmer выполнил
FLASH Erase,Program,Verify без ошибок. До записи отдельно проверены JTAG-цепочка
и ID LCMXO2-1200HC. Использован готовый JED из финального CP67b; повторных
synthesis/PAR/export не было.

- JED SHA256: `d2e9000c47477c0ad8e8b4167338c74f274f2650dc46d8f1378446bb467e710d`.
- JEDEC checksum: `84CC`.
- **1244 LUT / 381 FF / 7 EBR**, 1005 микрокоманд.
- Архивный TRACE Fmax: **32,032 MHz**; номинальные CPU/FRAM SCK: **29,56 MHz**.
- Свободны 36 LUT, 12 slices, 0 EBR. MMU и FP11 выключены; FIS сохранён.

На UART `/dev/ttyUSB1` сервера `sash@192.168.1.108` зафиксирована загрузка
**RT-11FB (S) V05.03**. Команда DIR завершилась приглашением: 121 файл,
2329 занятых и 51327 свободных блоков. Сохранены 4010 байт UART.
Picocom PID 169780 после захвата возобновлён; состояние `S` проверено.

[Сырые журналы прошивки и UART](../tb/reports/cp67-hardware/program/).

Пользователь подтвердил перевод JTAG_EN в GPIO перед установкой через HG.
Каталог HG доступен на прежних 1000 Hz. Новые ODT/SDBOOT/UJMOD установлены;
самоинициализация обоих модулей после длинного RESET проверена через UART.

## Файлы и передача

На сервер переданы только готовые ODT.BIN, SDBOOT.BIN и UJMOD.SAV — 17408 байт.
Используется отдельный каталог `/tmp/uj11-cp67b-20260913/program-cp67b/install/share`.
Образ SD целиком не заменяется. Прежний ODT сохранён через RT-11 как
`HG:OLDODT.BIN`; его SHA256 совпал с установленным CP66:
`54e765644c19fb52a9fdb5b5f2599294bdc6b92cf7ee1bda140faa3eab1460a2`.

Резервное COPY превысило 90-секундный таймаут UART helper; сама операция
продолжалась. Скрипт не отправил следующую команду. После пассивного ожидания
получены завершённый файл, совпадающий SHA256 и отдельное приглашение RT-11.
Незавершённый UART-сеанс сохранён отдельно от успешного окончания операции.
Следующие COPY используют 300-секундное ожидание.

Все три файла скопированы на SD, затем обратно на HG. Каждая обратная копия
побайтно равна исходному файлу:

| Файл | Readback | Байты | SHA256 |
|---|---|---:|---|
| ODT.BIN | ODCHK.BIN | 11776 | `3a9151c68fd372abdf005a7b9622530a25fa865e498dc36c27600a6a2dfa8d4a` |
| SDBOOT.BIN | SDCHK.BIN | 1024 | `201c1c0707bfad7d0a6b766d4c9f54baa8bdcd518bcdfa3acd3f631d95257a23` |
| UJMOD.SAV | MDCHK.SAV | 4608 | `7195501e4674fb2d5362b9b0a1876404824b788d3382ad4147268750e1da1f97` |

Выполнено `UNLOAD HG`; созданный daemon PID 173542 остановлен, пины пульта
освобождены. Исходная таблица UJMOD содержала восемь нулевых записей.
`RUN UJMOD` → `ODT`, затем `RUN UJMOD` → `SDBOOT` завершились сообщением
`!UJMOD-I-DONE`. Загрузчик проверил readback и checksum FRAM. Итоговый STATUS:

```text
0: 010000 012427 076367 140403
1: 006000 000342 053365 140403
```

Остальные шесть записей нулевые. `140403` означает VALID + AUTO: инициализаторы
ещё должны быть вызваны следующим обычным холодным запуском.

## Холодная самоинициализация

Пользователь выполнил длинный RESET без ESC. В пассивном UART-захвате получен
новый баннер RT-11FB V05.03. Затем выполнен только `RUN UJMOD` → `STATUS`;
повторной загрузки образов и UJON не было:

```text
0: 010000 012427 076367 140407
1: 006000 000342 053365 140407
```

BASE/LENGTH/CHECKSUM сохранились, к VALID + AUTO добавился OK у обоих модулей.
Тем самым аппаратно подтверждены сохранение записей и образов во FRAM,
проверка суммы cold walker, вызов обоих инициализаторов и загрузка RT-11.

## ODT после автоматической активации

Пользователь подтвердил короткий RESET после холодной загрузки. Непосредственный
баннер входа не попал в 45-секундное окно пассивной записи. Последующие
UART-команды подтвердили работающий отладчик:

- `R`: выведены R0..R7 и PSW; PC=`142774`, PSW=`040010`, затем `ODT>`.
- `D`: `142774: 005765 000036  TST 000036(R5)`, затем `ODT>`.
- `C`: `CONTINUE`; следующая пустая строка вернула приглашение RT-11.

Повторных UJMOD-загрузок или UJON между длинным RESET и входом в ODT не было.
На завершении плата находится в RT-11 с автоматически включённым ODT,
HG остановлен, picocom возобновлён и проверен. Рабочие бинарные файлы оставлены
на SD; прежний ODT дополнительно сохранён в архиве установки.

В этом аппаратном сеансе не проверялись ESC-восстановление, отключение питания
посреди записи и полный набор команд пульта. Их simulation-проверки не заменяют
отдельные аппаратные испытания.

Позднее **ESC-восстановление проверено отдельным проходом**: RT-11 с обходом
ODT, сохранность таблицы и возврат ODT после обычного RESET без переустановки.
