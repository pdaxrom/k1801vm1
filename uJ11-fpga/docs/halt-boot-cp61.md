# CP61: ROM → HALT RAM → USER RAM

Реализована уточнённая пользователем последовательность начального пуска.
Это отдельный экспериментальный профиль `--boot-cp61`, без MMU. На плате
остаётся CP56a, default сборки CP52a. ODT и FP11 firmware ещё не реализованы.
Старый файловый UJLOAD ABI1 остаётся рабочим для CP60; миграция его файлового
протокола на резидентные векторные вызовы — следующий этап.

Все адреса и коды ниже восьмеричные, размеры в байтах десятичные.

## Последовательность

1. Cold reset устанавливает `service_mode=1`, готовность ODT/FP11 равна нулю.
   RF инициализируется прежним микрокодом. Вместо первого FETCH он вызывает
   существующий reader вектора с T4=0: PC=`010652`, PSW=`000340` из HALT
   `000000/000002`. Формат PSW J-11 сохраняется; HALT — отдельный признак.
2. 50-байтная ROM-процедура копирует исходный SD bootstrap (426 байт) в
   HALT `004000..004651`, затем резидентный код (164 байта) в
   `000200..000443`. Используются обычные MOV, каждый записанный word
   сравнивается с ROM. При несовпадении пуск остаётся в ROM/HALT.
3. Исполнение переходит в HALT RAM по `000322`. Код устанавливает векторы
   и собственный SP=`001000`, затем вызывает через адресный вектор `000160`
   процедуру `000422`: `JSR PC,@000160`.
4. Эта процедура переносит bootstrap **из HALT RAM в USER RAM**, с теми же
   адресами `004000..004651`: MOV читает HALT, MTUS пишет USER, MFUS читает
   записанное USER-слово обратно. Копирование идёт от конца к началу;
   используются R1/R5/R2. Несовпадение оставляет процессор в HALT.
5. После возврата устанавливаются CPC=`004000`, CPSW=0. START выбирает
   USER и восстанавливает PC/PSW. Первая команда SD bootstrap и весь его
   дальнейший код читаются **из нижней FRAM**, а не из ROM.
6. Прежний SD bootstrap читает два сектора в USER RAM и запускает их с
   адреса 0. RT-11 загружается своим прежним способом.

Начальная установка и последующее копирование не исполняют UJRD/UJWR.
Существующий START внутри микрокода читает CPC/CPSW физическими обменами
из верхнего банка; это не перенос payload и не новая команда копирования.

## ROM и RAM

Один прежний firmware EBR, 512×16 посредством двух byte-портов:

| Физические байты EBR | Содержимое | Байты |
|---|---|---:|
| 0..425 | Исходный SD bootstrap, побайтно CP60 | 426 |
| 426..475 | Начальная ROM-процедура | 50 |
| 476..479 | Свободно | 4 |
| 480..511 | Прежние RK CSR | 32 |
| 512..859 | RK recovery firmware CP60, побайтно без изменений | 348 |
| 860..1023 | Резидентная firmware и HALT→USER copier | 164 |

ROM при холодном старте виден только в HALT `010000..011777`. Это окно
отдельно от RAM назначения `004000`. Старые USER ROM-перекрытия начального
JMP, trap-векторов и маленького ODT удалены из CP61. После завершения SD
bootstrap прежний release-механизм закрывает boot overlay. Private RK ROM
в USER `160000..160777` работает как в CP60.

| HALT RAM | Назначение |
|---|---|
| `000004/000006` | Fault vector; до окончания переноса USER ведёт в idle |
| `000100/000102` | CPC/CPSW |
| `000160` | Адрес подпрограммы HALT→USER, без PSW; обычный косвенный JSR |
| `000170/000172` | HALT-вектор `000200/000340` |
| `000200..000443` | Резидентный код |
| `000776` | Слово возврата на собственном HALT-стеке |
| `004000..004651` | Копия SD bootstrap; после завершения старта может переиспользоваться |

Первые 512 байт верхней RAM резервируются под систему. Их размещение
отличается от файлового ABI1 CP60. Cold reset восстанавливает resident и
bootstrap, снимает ready; прочие данные FRAM сохраняются. Обычная команда
RESET периферии не запускает заново начальное копирование.

## Вызов из USER

Проверочный интерфейс CP61: R4=`125061`, R5=адрес буфера USER, R1=назначение
HALT, R2=1..64 слова, затем HALT. Диспетчер по `000170` проверяет диапазоны
и копирует через MFUS + MOV с readback каждого слова. R0=0 означает успех,
R0=1 — неверные параметры, bus error либо readback mismatch. Изменяются
R0/R1/R2/R3/R5, R4 и SP сохраняются, START восстанавливает исходный PSW.
При ошибке после начала записи часть блока уже может быть перенесена.

Допустимы чётные диапазоны целиком ниже `160000`, назначение не ниже `001000`.
Копирование не оборачивает адрес и не задевает I/O page. Для последних 8 КиБ
физической FRAM будущая файловая служба должна применять уже имеющийся
HALT-only физический доступ; обычные MFUS/MTUS/MOV имеют логическую семантику.

Без сигнатуры HALT сохраняет контекст и остаётся в idle. Полноценный ODT,
его переключение с копированием и внешний HALT ещё впереди.

В финальном CP61g команды `000040..000045` доступны только в HALT.
`UJLOAD.SAV` ABI1 проверяет `000043` до любых записей верхнего банка, получает
reserved trap и сообщает об отсутствии интерфейса. Это исключает случайную
перезапись resident старым загрузчиком. Векторный файловый загрузчик ещё
нужно реализовать; `HBTEST.SAV` — именно диагностическая программа.

## Ресурсный gate

| Вариант | LUT | FF | EBR | Slices | Fmax MHz | Результат |
|---|---:|---:|---:|---:|---:|---|
| CP61a | 1293 | 343 | 6 | 649 | — | Не помещается |
| CP61b | 1284 | 343 | 6 | 645 | — | Prefix decoder, не помещается |
| CP61c | 1266 | 343 | 6 | 636 | 31,624 | Старый прямой ROM→USER запуск; timing FAIL |
| CP61d | 1283 | 343 | 6 | 643 | — | Новая RAM→RAM цепочка, не помещается |
| CP61e | 1227 | 343 | 6 | 616 | 32,125 | Удалены USER ROM overlays; PASS |
| CP61f | 1229 | 343 | 6 | 616 | 32,087 | HALT-only установочные команды; PASS; выражение уточнено для lint |
| **CP61g** | **1229** | **343** | **6** | **616** | **32,087** | **Выбран; strict lint, MAP/PAR/TRACE PASS** |

Во всех вариантах microstore 1002 слова: изменилось одно слово reset,
новых микрокоманд нет. От CP60b: −22 LUT, −13 slices, без роста FF/EBR.
Осталось 51 LUT, 24 slices, 1 EBR, 22 microinstructions; до цели ≤1100 LUT
ещё нужно освободить 129 LUT. Номинальные CPU/SCK остаются 29,56 MHz.
Gate 31,824 MHz учитывает прежние допуски и FRAM budgets; PCB delays и
физическая ширина импульсов SCK ещё не измерены. Остальные I/O этим gate
полностью не покрыты. Нового JED и прошивки платы нет.

## Проверки и время

17 directed cold-start/copy сценариев на portable и настоящих Lattice EBR
моделях: обе копии bootstrap, все векторы, полная проверка двух банков,
границы, выравнивание, wrap, SP/PSW, ошибки обмена и запрет записи отдельно
в HALT и USER. Во время boot нижний банк меняется только в диапазоне
bootstrap. Эти тесты выполнены на CP61e; для CP61g доказано побайтное
равенство остального RTL/ROM и перебраны 524288 opcode/mode/ready сочетаний:
единственное изменение dispatch — запрет четырёх старых USER установочных
команд. Negative control с прежним декодером обнаруживается.

Полный CP61e RTL: два cold boot RT-11FB V05.03, восемь вызовов из HBTEST,
два переноса по 512 байт, восстановление повреждённого resident после reset,
сохранение прочей FRAM и DIR. 294800833 clocks, 720 RK commands,
402 timer edges, 3534 UART wire bytes, 332 SD reads / 16 writes.
На финальном CP61g отдельно проверен отказ исходного UJLOAD до изменения
верхней памяти и последующий успешный HBTEST/DIR: 104427836 clocks,
408 RK commands, 128 timer edges, 310 UART wire bytes, 190 SD reads / 8 writes.
RK recovery: 28 CSR beats
× portable/vendor и отрицательная проверка CCLR.

Начальная цепочка до перехода в USER: **223912 clocks**, около 7,575 ms
при 29,56 MHz. Вызов USER→HALT с проверками и readback: 2862 clocks для
одного слова, 34930 для 64 слов (около 1,182 ms). Последнее измерено от
service ENTER до LEAVE; ожидание следующего opcode сюда не входит.
На этом интервале IRQ отложены. Непрерывный входной поток UART требует
отдельной проверки допустимого размера блока; 64 слова — текущий максимум
контракта, не доказательство отсутствия потерь UART при любом трафике.

## Воспроизведение

```sh
python3 tools/build_halt_boot_cp61.py
python3 tools/test_halt_boot_cp61.py
python3 tools/check_boot_guard_cp61.py
python3 tools/rt11_build.py tb/rt11/HBTEST.MAC --out build/cp61-asm
python3 tools/run_halt_rt11_cp61.py --legacy-guard
python3 tools/checkpoint_board.py cp61new --boot-cp61 --clock-mhz 31.824 --fram-timing
```

Assembler и RT-11 runs требуют свежих output directories. Readable `.asm`,
бинарные результаты, listings и hashes находятся в `firmware/cp61`.
`--assemble` использует существующий microasm11 read-only и пишет результаты
только в uJ11; обычная сборка использует проверенные по hashes бинарники.
Default RTL и архивы предыдущих checkpoints не переписываются.
