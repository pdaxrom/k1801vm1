# Работа с uJ11 CP67b

Руководство для установленной HC1200: RT-11FB V05.03, FIS, 128 КиБ FRAM
с отдельными USER/HALT банками, ODT и SDBOOT с автозапуском. MMU и FP11
в этой конфигурации нет. [Устройство](system-cp67.md),
[сборка и прошивка](development-cp67.md), [индекс документации](README.md).

Адреса, opcode и числа команд по умолчанию **восьмеричные**. Размеры файлов,
частоты и номера битов в пояснениях — десятичные. Точки `.` и приглашения
`ODT>`/`UJMOD>` в примерах печатает система: вводить нужно только команду.

## Включение и RESET

Терминал: **115200 baud, 8N1, без flow control**. На стенде Linux
`sash@192.168.1.108` UART — `/dev/ttyUSB1`; после переподключения USB проверить
имя устройства. Одновременно читать UART должен один терминал/скрипт.

| Действие | Результат |
|---|---|
| Включение или длинный RESET, около 2 секунд | Аппаратный cold reset, проверка FRAM-модулей, их инициализация, загрузка RT-11 |
| Короткий RESET после загрузки | Остановка USER-программы и вход в активированный ODT |
| Короткий RESET внутри ODT | Отмена незавершённого ввода; сохранённый USER-контекст не заменяется |
| Длинный RESET, затем UART ESC | Обход всех FRAM-модулей, встроенный резервный bootstrap |
| PDP-11 инструкция RESET | Сброс периферии; не холодный запуск таблицы модулей |

После отпускания длинного RESET есть окно UART ESC около 2,18 с номинально,
затем обычная загрузка. Значение получено в модели, не секундомером на плате.
Не посылайте ESC при штатном старте: он намеренно оставит ODT выключенным.

После нормального cold boot ODT уже включён: повторный `UJON` не нужен.
Сохраняются файлы и код во FRAM, но инициализатор начинает **новый сеанс**:
очищает контекст, точки останова, очереди и настройки OCT/HEX/прокрутки.
Отлаживаемую USER-программу после перезапуска RT-11 нужно загрузить заново.

Для клавиатуры/HG перевести **JTAG_EN в GPIO и физически отключить
программатор от общих JTAG-пинов**. Одного переключателя может быть недостаточно:
подключённый кабель уже мешал клавиатуре на этой плате. Во время прошивки,
наоборот, нужен JTAG. HDSP и клавиатура используют программный драйвер.

## Установка и обновление модулей

Готовый согласованный пакет: [service/cp67](../demos/rt11/service/cp67/README.md).
Нужны `UJMOD.SAV`, `ODT.BIN`, `SDBOOT.BIN`. Старые `UJLOAD/UJON` обслуживали
другой ABI и для CP67 не используются. Замена только программы во FRAM не
требует перепрошивки FPGA.

Сначала доставить файлы на системный диск RT-11, затем зарегистрировать их
в HALT FRAM через UJMOD. Это две разные операции: COPY на SD сам по себе
не обновляет исполняемый модуль во FRAM.

### Передача через HG

На Linux запустить `hgfsd --directory <каталог-с-файлами> --clock 1000`
для подключённого HG. Требуются установленный host tool и RT-11 `HG.SYS`;
их источники и запуск описаны в [development](development-cp67.md).
На действующем системном диске `DK:` указывает на системный том `SY:`.
Если рабочее устройство DK менялось, явно используйте SY.

В RT-11, последовательно дожидаясь приглашения после каждой команды:

```text
.SET SL OFF
.LOAD HG
.DIR HG:
.COPY DK:ODT.BIN HG:OLDODT.BIN
.COPY HG:ODT.BIN DK:ODT.BIN
.COPY HG:SDBOOT.BIN DK:SDBOOT.BIN
.COPY HG:UJMOD.SAV DK:UJMOD.SAV
.COPY DK:ODT.BIN HG:ODCHK.BIN
.COPY DK:SDBOOT.BIN HG:SDCHK.BIN
.COPY DK:UJMOD.SAV HG:MDCHK.SAV
.UNLOAD HG
```

Строка OLDODT — резервная копия при наличии старого ODT; используйте свободное
имя, если такая копия уже есть. Для других заменяемых файлов аналогично
сохранить нужную предыдущую версию. Сравнить SHA256 трёх обратных копий
с исходными файлами, затем остановить свой hgfsd, освободив пины пульта.
Не смешивать несовместимые версии загрузчика/образов.

HG на 1000 Hz медленный: в реальной установке копирование ODT занимало
порядка трёх минут. Таймаут UART-скрипта не означает отмену COPY на PDP-11.
В таком случае пассивно дождаться завершения/приглашения и проверить файл,
а не посылать новую команду поверх работающей передачи.

### Запись в HALT FRAM

UJMOD принимает **одну команду за запуск** и возвращается в RT-11:

```text
.RUN UJMOD
UJMOD> ODT
!UJMOD-I-DONE; long RESET without ESC initializes enabled modules
.RUN UJMOD
UJMOD> SDBOOT
!UJMOD-I-DONE; long RESET without ESC initializes enabled modules
.RUN UJMOD
UJMOD> STATUS
```

Имя 1–6 букв/цифр, без расширения; файл ищется как `SY:имя.BIN`.
UJMOD проверяет заголовок, диапазоны, checksum и readback FRAM, затем публикует
запись. Совпадающий BASE заменяется в прежнем слоте. Установка выключает живые
службы, поэтому короткий RESET до нового cold boot не обязан открывать ODT.

После записи **длинный RESET без ESC**, дождаться RT-11, снова выполнить
`RUN UJMOD` → `STATUS`. Для нынешних образов в изначально пустой таблице:

```text
0: 010000 012427 076367 140407
1: 006000 000342 053365 140407
```

Поля: `слот: BASE LENGTH CHECKSUM STATUS`; LENGTH — **слова**, не байты.
Слоты 0/1 не закреплены за типами: при другой истории установок номера могут
отличаться. BASE/CHECKSUM также изменятся после новой сборки.

| STATUS, octal | Значение |
|---|---|
| `140403` | Файл установлен и AUTO включён; cold init ещё не подтверждён |
| `140407` | Инициализация успешна в последнем обычном cold boot |
| `140413` | Ошибка проверки или инициализации |
| `140401` | Зарегистрирован, автозапуск выключен |
| `140402` | Незавершённая установка; walker пропускает |
| `000000` | Пустая запись |

После ESC таблица не обходится: прежний OK может остаться от прошлого
старта и **не подтверждает** активацию сейчас. Это STATUS таблицы UJMOD,
а не PSW и не одноимённая служебная инструкция CPU.

### Отключение, удаление, восстановление

`RUN UJMOD` → `OFF0` выключает AUTO слота 0, сохраняя его размещение.
`DEL0` освобождает запись, но не стирает байты FRAM. Доступны номера 0–7;
сначала определить нужный слот через STATUS. Обе операции отключают живые
службы; после них длинный RESET инициализирует оставшиеся AUTO-модули.
Для повторного включения загрузить имя модуля заново — команды ON нет.

Если загрузчик/инициализатор завис или мешает запуску:

1. Удерживать RESET около 2 секунд и отпустить.
2. Сразу послать **ESC через UART**, при необходимости несколько раз в окне
   старта. Кнопка MEM и историческая «ESC» из KEYDEM этого не заменяют.
3. Дождаться RT-11 от встроенного bootstrap. ODT в этом старте выключен.
4. Через UJMOD отключить, удалить или заменить плохую запись.
5. Сделать обычный длинный RESET без ESC.

Восстановление обходит даже модуль с правильной суммой, но неисправным кодом.
Автоматического watchdog такого модуля нет. ESC не стирает FRAM; встроенный
bootstrap тоже требует исправной SD/дисковой загрузки. Аппаратная проверка
ESC ещё остаётся в TODO; сценарий проверен в RTL, включая зависший модуль.

## ODT через UART

Коротко нажать RESET, дождаться `ODT>`. Вход/шаг печатает контекст и текущую
команду; PC относится к USER-программе. `C` возвращает её к выполнению.
Для остановленной на приглашении RT-11 после `C` можно нажать Enter, чтобы
снова увидеть точку. Регистр PSW выбирается номером `10` в OCT или `8` в HEX.

| Команда | Действие |
|---|---|
| `H` | Справка |
| `R` | Все R0–R7, PSW и его поля сразу, отдельными строками |
| `R n` / `R n value` | Один регистр / изменение регистра |
| `M addr [count]` / `B addr [count]` | Слова / байты USER RAM; до `20` восьмеричных элементов |
| `W addr value` / `V addr value` | Запись слова / байта с readback |
| `D [addr [count]]` | Адрес, opcode, extension words, дизассемблированный текст; до `20` команд |
| `L` / `N` | Предыдущая / следующая известная команда просмотра |
| `S [count]` | STEP IN, до `100` восьмеричных шагов |
| `T` | STEP OVER: JSR до возврата и исходного SP; для иной команды один STEP |
| `T limit` | Отдельный режим: ограниченный цикл одиночных STEP, 1..`177777` шагов |
| `C` | CONTINUE из сохранённого/изменённого контекста |
| `G addr` | Новый PC, снятие сохранённого WAIT/старого trace, запуск |
| `P addr` / `P` | Задать постоянную точку / показать точки; максимум четыре |
| `Z addr` / `Z` | Снять одну / все точки, повторить неудавшееся восстановление |
| `U addr` | RUN TO с одной временной точкой |
| `O` / `X` | Восьмеричный / шестнадцатеричный ввод и вывод |
| `A` / `A 0` / `A 1` | Переключить / выключить / включить автопрокрутку HDSP |
| `<` / `>` | Сдвинуть окно HDSP вручную, без изменения команды |
| `K m p n e` | Назначить MEM/PREV/NEXT/ENTER различным кодам `20..23` OCT |
| ESC / CTRL-C | Отмена ввода, остановка dump между строками |

Обычные чтение/запись ограничены USER RAM `000000..157777`; слова должны быть
выровнены. RAW HALT и явного просмотра I/O CSR сейчас нет. Дизассемблер читает
opcode/extension words, не значения операндов. FP11/неизвестное кодирование
может выводиться как `.WORD` — это не подтверждение исполнения FP11.

Пример просмотра без изменения памяти:

```text
ODT> O
ODT> R
ODT> R 10
ODT> D
ODT> N
ODT> L
ODT> C
```

### Шаги и точки останова

`S` использует аппаратный STEP: обычные IRQ и trace отложены, синхронные
ошибки/ловушки сохраняются. WAIT не превращается в выполнение следующей
команды. `T limit` тоже откладывает IRQ/trace; IRQ-зависимая подпрограмма
может не завершиться в таком режиме.

`T` **без числа** и `U` используют обычный RUN с IRQ и временным HALT-патчем.
Для JSR монитор учитывает всю длину команды и исходный SP, включая рекурсивные
вызовы. Остановить такой RUN — коротким RESET: UART/клавиатура в это время
принадлежат гостю, ESC как команда ODT не принимается. Для ограниченного
`T limit` отмена через UART или новое нажатие панели остаётся доступной.

Постоянные/временные патчи допустимы по чётным адресам `001000..157776`,
если исходный opcode не HALT. Выбирать начало команды **своей программы**:
ODT не распознаёт автоматически данные, extension words или RT-11 overlays.
На приглашении ODT оригинальные слова восстановлены. `C` с PC на постоянной
точке выполняет оригинал один раз и снова включает точки. Гостевые BPT/trace
векторы не подменяются. При `?BP` и неудавшемся восстановлении нельзя продолжать,
пока проблема не устранена и `Z` не завершит восстановление.
[Подробный механизм и ограничения](odt-cp66.md).

ODT не замораживает UART, таймер и внешнее время. Старые непрочитанные символы
гостя могут потеряться при захвате консоли. Команды вводить последовательно;
сплошная вставка больших пачек на 115200 baud не квалифицирована.
Host helper посылает по 10 символов/с и сохраняет UART-журнал.

## ODT с пульта

Физическая раскладка:

```text
  7     8     9     C     MEM
  4     5     6     D     PREV
  1     2     3     E     NEXT
  0     A     B     F     ENTER
```

| Кнопка вне числового ввода | Команда |
|---|---|
| 8 | STEP IN (`S`) |
| 9 | STEP OVER (`T` без лимита) |
| A | Просмотр регистров с R0 |
| B | Ввести адрес просмотра памяти |
| C | Ввести адрес дизассемблирования |
| D | Ввести адрес запуска (`G`) |
| E | CONTINUE (`C`) |
| F | OCT/HEX |

При вводе HEX кнопки 8–F — цифры, при вводе OCT они игнорируются.
Удержание 8/9 не повторяет шаг: сначала отпустить клавишу.

| Экран | PREV / NEXT | ENTER | MEM |
|---|---|---|---|
| Регистры | Предыдущий / следующий R0–R7, PSW | Редактировать выбранный | Меню |
| Память | Соседнее слово/байт | Редактировать | Меню |
| Дизассемблер | Предыдущая / следующая команда | Следующая команда | Меню |
| Меню | Выбрать пункт | Выполнить | Меню/отмена |
| Ввод числа | PREV — стереть последнюю цифру | Подтвердить | Отменить |

Регистры показываются **по одному с ожиданием нажатия только на пульте**.
UART `R` по-прежнему печатает весь набор сразу. В меню есть WORD/BYTE,
регистры/память/дизассемблер, STEP/CONTINUE/GO, OCT/HEX, постановка/снятие/список
точек и RUN TO. Список точек на панели пока показывает последнюю строку;
полный список доступен по UART `P`.

Строка длиннее 16 символов автоматически идёт до конца и обратно, с паузами
на краях. PREV/NEXT листают **команды**, а не двигают окно. История содержит
32 известные границы; `HISTORY START` означает её начало. Задать более ранний
адрес можно через `D addr`/кнопку C: угадывания «PC−2» нет.

Действие панели выводится в UART как `[PANEL] ...`, результат — целиком.
Сдвиги HDSP не повторяют чтение/запись и не засоряют консоль. Ввод/удержание
клавиши приостанавливает анимацию. Вся эта логика — программа ODT во FRAM,
дополнительные ресурсы FPGA для неё не используются.

Одновременные клавиши не являются сочетаниями команд: драйвер рассчитан
на одиночные нажатия. При несовпадении надписей MEM/PREV/NEXT/ENTER проверить
коды и при необходимости `K`; стандарт — `20 21 22 23` OCT.
[Схема, коды и пределы подтверждения](panel-keyboard.md).

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Короткий RESET не открывает ODT | CP67b, установленный ODT, обычный cold boot без ESC, STATUS; после UJMOD нужен длинный RESET |
| RT-11 работает, клавиатура нет | GPIO/JTAG_EN, физически отключённый JTAG, `UNLOAD HG` и остановленный hgfsd |
| ODT по UART работает, HDSP не обновляется | Панель могла быть пропущена при входе из-за занятого HG TDO; освободить HG, выйти `C` и войти заново |
| PREV сообщает HISTORY START | Нет более ранней известной границы; задать адрес через D |
| Строка не движется | Длина ≤16, A 0, незавершённый ввод или удержанная клавиша |
| Число отвергается | OCT/HEX, чётность слова, USER-диапазон, предел count; в OCT нет цифр 8/9 |
| После длинного RESET пропали точки/HEX | Это нормальная холодная инициализация, сохраняется код модуля, не сеанс |
| Нет RT-11 после установки нового модуля | Длинный RESET + UART ESC, затем OFF/DEL/замена через UJMOD |
| COPY превысил host timeout | Дождаться UART-приглашения и проверить readback, не запускать вторую передачу поверх первой |

Фактически выполненные аппаратные проверки и ещё не выполненные проверки
перечислены в [журнале CP67](board-bringup-cp67.md). Это руководство описывает
реализованное поведение; оно не объявляет каждый сценарий новым hardware test.
