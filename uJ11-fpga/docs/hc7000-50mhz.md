# HC7000 MMU at 50 MHz

For slow 2.9BSD console output, first apply the verified
[terminal delay setting](bsd-console.md): `stty nl0 cr0`.
The subsequent [PAR/PDR cache and microcode changes](hc7000-cpu-performance.md)
have a separate resource and workload comparison; the baseline below is preserved.
The optional [hardware status display](hc7000-diagnostics.md) scans one segment
at a time with weak output drive; it is disabled by default and its peak LED
current has not yet been measured on the resistorless board.

The HC7000 MMU profile can select 24 or 50 MHz at build time. The external
oscillator remains **12 MHz**. HC1200 and the MMU-less CPU retain their existing
sources and clock configuration. The default MMU build remains 24 MHz.

```sh
make CPU=mmu BOARD=hc7000-lcd-sram FPP=off IOP=storage MMU_CLOCK_MHZ=50 synthesis
make CPU=mmu BOARD=hc7000-lcd-sram FPP=off IOP=storage MMU_CLOCK_MHZ=50 export
```

The export gate requires matching source hashes, complete routing, the selected
clock constraint and passing setup/hold analysis. A timing experiment with a
50 MHz constraint applied to a 24 MHz PLL is not an exportable 50 MHz build.

## Clock and peripherals

`uj11_pll50.v` is a separate SCUBA-generated PLL configuration: 12 MHz input,
600 MHz VCO, 60 MHz CLKOP feedback and 50 MHz CLKOS system clock. The original
24/30 MHz PLL file is unchanged. UART remains 115200 baud, the system tick
remains 50 Hz, and the button sampling/long-reset duration is preserved.
SERV's millisecond timer follows the selected clock. SD initialization stays
at 200 kHz; normal SPI transfers use 12.5 MHz at the 50 MHz system clock.

The IS61WV102416BLL-10T controller retains its setup, two access, hold and
release phases. At 50 MHz the read capture occurs 40 ns after OE is launched.
The timing budget is 10 ns FPGA output + 10 ns SRAM + 2 ns assumed PCB flight
time, leaving 18 ns setup at the input pad. Hold analysis remains enabled with
zero external hold. Address/control output is constrained to 10 ns and DQ to
15 ns. These PCB budgets are assumptions; no oscilloscope measurement is claimed.
`tests/tb_sram50.v` exercises all four combinations of minimum/maximum modeled
output delays, including byte writes and reset during every active write phase.

## CPU and SERV changes

The 50 MHz CPU spends one clock preparing RF operands, the microinstruction,
control decode and D operand before execution. Memory requests retain their
ready/abort handshake. Direct loads use the completed MDR value. This is a
preparation/execution split, not overlap between independent PDP-11 instructions.
The 24 MHz profile bypasses these registers and retains its previous cycle count.

The MMU-specific opcode decoder folds privilege and MMU cases into the opcode
groups, avoiding the old VM2 decode followed by J11 overrides. Exhaustive tests
compare all 65536 opcodes in four processor modes, with both CSM and FPP settings.
The HC1200 decoder is unchanged. Microcode contents and its nine EBR allocation
are unchanged. Sparse-ROM region validation is decoded after the address register
in the 50 MHz profile. All 3072 visible words are checked with Lattice EBR models.

MMR1 displacement is obtained directly from the ADD/SUB D operand; the assembler
requires `delta=1` operations to have `pair=AD`, `dst=RF` and `a=b`. Kernel stack
checking compares the old SP and decrement without traversing the ALU writeback
mux. Internal PSW writes acknowledge locally. The MMU response register identifies
faults without a long path through the current READ/request decode.

SERV remains RV32IC with the same 10515-byte firmware. At 50 MHz an extra
instruction-response register separates the EBR bank mux from RV32C expansion.
The acknowledgement includes a gap for the aligner's second fetch of a
straddling instruction. Disk-controller emulation remains in software; no new
controller register banks or EBRs were added.

## Routed result and workload measurements

The preserved build is `frequency50-real08`, in
[the 50 MHz release snapshot](../history/releases/hc7000-50mhz/README.md).

| Metric | Previous 24 MHz CPU-events build | Current sources at 24 MHz | 50 MHz build |
|---|---:|---:|---:|
| LUT4 | 4173 / 6864 | 4057 / 6864 | 4137 / 6864 |
| Flip-flops | 1205 | 1205 | 1348 |
| EBR | 26 / 26 | 26 / 26 | 26 / 26 |
| Routed Fmax | 26.263 MHz | 25.505 MHz | 51.459 MHz |
| Requested clock | 24 MHz | 24 MHz | 50 MHz |

The extra pipeline costs 80 LUT and 143 flip-flops relative to the current
24 MHz configuration. Decoder and control-path simplifications offset that
cost relative to the previously qualified release. Both current configurations
pass their own clock and external SRAM constraints.

The fast strategy tries up to five placement seeds and stops on timing closure.
Seed 2 passed setup and hold, with 0.567 ns worst setup slack. Constraints are not
relaxed for internal CPU or SERV paths.

`tools/test_cpu_perf_mmu.py` compares fixed guest loops using the same six-cycle
external-memory response. It excludes reset and RF initialization. These are RTL
workloads, not measurements taken on the physical board or an OS benchmark.

| Workload | Clocks at 24 MHz | Clocks at 50 MHz | Elapsed-time speedup |
|---|---:|---:|---:|
| ADD / XOR / ROR / SOB | 45149 | 54217 | 1.735× |
| Memory ADD / INC / XOR / SOB | 82149 | 110217 | 1.553× |
| MOV / MUL / DIV / ASH / SOB | 44821 | 81497 | 1.146× |

The extra preparation clock costs most in long EIS microcode loops. The clock
increase therefore does not imply a 2.08× increase in PDP-11 instruction speed.
