# CP67: самоинициализирующиеся модули в HALT FRAM

CP67 сохраняет загруженные модули между холодными RESET. Доверенный код из
FPGA ROM проверяет таблицу и вызывает инициализаторы. Тип модуля ему неизвестен:
ODT, bootstrap и будущие расширения используют один ABI. MMU и FP11 не добавлены.
CP67b позднее записана во FLASH с Verify; RT-11FB/DIR проверены.
[Аппаратная установка и проверки](board-bringup-cp67.md) учитываются отдельно
от приведённых ниже simulation/synthesis результатов.

[Пошаговая установка, STATUS и восстановление](user-guide-cp67.md),
[полная карта системы](system-cp67.md), [сборка](development-cp67.md).

## Таблица и адреса

Все адреса ниже восьмеричные, относятся к верхним 64 КиБ HALT FRAM.
Основная USER RAM остаётся отдельными нижними 64 КиБ.

| Область | Назначение |
|---|---|
| `000000..005777` | Векторы, resident, стек, helper, копия резервного bootstrap, cold walker |
| `006000..006777` | 512 байт для малого модуля; сейчас SDBOOT |
| `007000..007077` | Восемь записей по четыре слова |
| `007100..007777` | Системный резерв, запрещён для образов |
| `010000..157777` | Исполняемые образы; ODT использует `010000..037777` вместе с данными |
| `160000..177777` | Общая I/O page при обычных обращениях; не исполняемый образ |

| Смещение записи | Поле | Единицы |
|---:|---|---|
| `0` | BASE | Байтовый адрес начала, одновременно точка входа инициализатора |
| `2` | LENGTH | Число 16-битных слов неизменяемого образа |
| `4` | CHECKSUM | Сумма этих слов по модулю 65536 |
| `6` | STATUS | Cookie и флаги |

Образ должен целиком лежать в одном разрешённом диапазоне. Адрес и длина
проверяются до чтения кода: чётность, ненулевая длина, переполнения и I/O.
Загрузчик отвергает перекрывающиеся образы и повторяющиеся BASE.

STATUS: старшие биты `C100` hex, младшие `VALID=1`, `AUTO=2`, `OK=4`, `ERROR=8`.
Иные биты не принимаются. Значения:

| Hex | Octal | Значение |
|---|---|---|
| C102 | 140402 | Запись ещё не опубликована |
| C103 | 140403 | Проверенный образ, включён автозапуск |
| C107 | 140407 | Инициализация в этом обычном старте успешна |
| C10B | 140413 | Ошибка контрольной суммы, диапазона или инициализации |
| C101 | 140401 | Образ зарегистрирован, AUTO выключен |

Нулевые/стёртые/неизвестные записи пропускаются. При обычном старте прежние
OK/ERROR очищаются у распознанных VALID-записей, включая выключенные AUTO.
При принудительном ESC-старте таблица вообще не обрабатывается: её прежние
результаты остаются историческими, `HALT[000074]=1` отмечает recovery.

## ABI инициализатора

Вход — обычный `JSR PC` на BASE, в HALT-пространстве, IPL 7, R0=0.
Возврат — `RTS PC`, R0=0 при успехе, ненулевой при ошибке. R1..R5 можно менять;
SP должен вернуться в исходное состояние. Cold walker сохраняет собственный
стек и курсор независимо от рабочих регистров модуля. Инициализатор не делает
START/STEP и не заменяет принадлежащий walker вектор ошибки `004/006`.

Инициализатор сам очищает изменяемое состояние, устанавливает его ненулевые
начальные значения и проверяет запись векторов. Готовность публикует последней.
При ошибке walker восстанавливает предыдущие ready/debug bits и BOOTPC,
ставит ERROR и продолжает со следующей записью. Произвольные записи модуля в
память автоматически не откатываются: инициализатор отвечает за собственные
побочные эффекты и совместимость с ранее вызванными модулями.

Контрольная сумма включает код, константы, шрифты, раскладку и сам инициализатор.
Изменяемые регистры, breakpoint records, очереди, буферы и стек находятся после
IMMEND и не входят в LENGTH. Их размещение — контракт конкретного модуля.
Таблица из четырёх полей не описывает BSS: автоматического распределителя
рабочей памяти сейчас нет, совместимость её диапазонов проверяется при сборке.

Образы этой версии **абсолютные**, не relocatable. ODT собран с `010000`,
SDBOOT — с `006000`. PDP-11 PC-relative операнды сами по себе не устраняют
абсолютные адреса в константах и векторах. Произвольное размещение потребует
позиционно-независимого кода либо файла с relocation records. Во втором случае
UJMOD сможет вычислять CHECKSUM после relocation без изменения четырёх полей
таблицы. Такой формат ещё не реализован.

## Заменяемый bootstrap и независимое восстановление

ROM всегда устанавливает свой resident, cold walker и резервный USER bootstrap
по `004000`. До любого вызова из FRAM он принимает UART ESC. После отпускания
длинного RESET нужно отправить ESC через UART; удобно посылать его повторно.
Окно примерно 2,18 s при номинальных 29,56 MHz, по симуляции CPU/SPI, без
измерения секундомером на физической плате. Иные символы не продлевают окно.
Пульт/ODT/JTAG GPIO для этого не требуются.

ESC пропускает **все** модули и запускает встроенный bootstrap. Это работает и
для модуля с правильной суммой, который зависает или ошибочно выбирает загрузку.
Автоматического watchdog для произвольного зависшего инициализатора нет:
нужно сделать длинный RESET и выбрать ESC. Содержимое FRAM при обходе не стирается.

Перед инициализацией `HALT[000120]` (BOOTPC) получает `004000`.
Обычный модуль может подготовить другой bootstrap в USER RAM и записать его
точку входа в BOOTPC, затем вернуть управление. Walker проверяет чётность и
границу I/O; resident выполняет обычный START с выбранным PC и PSW=0.
При ошибке инициализации выбор откатывается. Это соглашение не вводит тип модуля
в таблицу. `HALT[000122]=007000` — программная метка установленного CP67 walker,
не аппаратная идентификация версии FPGA.

SDBOOT содержит проверенный 426-байтный SD bootstrap CP63b и свой инициализатор:
всего 452 байта. Инициализатор копирует код через resident-вектор `000160`
в USER `004000`, выбирает BOOTPC и возвращается. Образ можно заменить расширенным;
если он больше малого 512-байтного окна, его следует собрать для свободного
диапазона основного пула. Встроенная ROM-копия от этого не меняется.

## Файлы и UJMOD

Файл `.BIN`: 512-байтный заголовок, затем неизменяемые слова и нулевое дополнение
до границы блока. Первые восемь слов: magic `045125,030461`, version=2, ABI=3,
BASE, LENGTH в словах, CHECKSUM образа, checksum заголовка. Сумма первых 16 слов
заголовка должна быть нулём; все неиспользуемые байты заголовка/хвоста нулевые.
Лишние или отсутствующие RT-11 блоки отвергаются. Старый UJLOAD/ABI2 не подходит.

`RUN UJMOD` принимает имя файла без расширения, `STATUS`, `OFF0`..`OFF7`,
`DEL0`..`DEL7`, `EXIT`. Файлы ищутся как `SY:имя.BIN`; длина имени 1–6 символов.
OFF снимает AUTO, сохраняя размещение; DEL забывает запись, не стирая образ.
Обе операции выключают живые службы; следующий обычный холодный старт
переинициализирует оставшиеся включённые модули.

Установка сначала проверяет заголовок и таблицу. Совпадающий BASE заменяется
в прежней записи, иначе выбирается первая свободная; выключенные VALID-записи
продолжают резервировать свои неизменяемые диапазоны. Затем:

1. Выключить службы, записать и прочитать обратно C102 в STATUS.
2. Копировать слова блоками через HALT helper с немедленным readback.
3. Проверить сумму входного файла, нулевое дополнение и повторно прочитать весь
   записанный образ для независимого суммирования.
4. Записать BASE/LENGTH/CHECKSUM с readback, последним записать C103.

После загрузки нужен длинный RESET без ESC. UJMOD не вызывает инициализатор
непосредственно из RT-11. Прерывание копирования оставляет неподтверждённую
запись, которую cold walker пропускает. Этот порядок не заменяет физические
испытания при отключении питания в середине SPI-записи.

ODT при cold init очищает старый сеанс, не применяет сохранённые breakpoint
патчи к новому USER-коду. Прежнюю отлаживаемую программу после reset нужно
загрузить заново. Включение debug-вектора происходит после readback всех данных.
Неизменяемый образ ODT — 10798 байт, всё размещение — 11860, свободно 428 байт
в прежнем 12-КиБ окне. Пользовательские команды отладчика сохранены.

## Как написать свой модуль

Выбрать BASE с учётом **полного** размещения уже установленных модулей.
Текущий ODT с BSS/стеком резервирует `010000..037777`, SDBOOT — малое окно
`006000..006777`. Начало `040000` подходит для следующего модуля лишь если
эта память не занята другим расширением; UJMOD не знает чужих BSS.

Минимальный пример исходника `MOD.MAC`, который только подтверждает init:

```asm
        .TITLE MOD
        .ASECT
        .=40000
INIT:   CLR R0
        RTS PC
IMMEND:
        .END INIT
```

Это демонстрация ABI, не ODT/драйвер. Для полезного модуля добавить код,
неизменяемые константы до IMMEND, а рабочую память после него. Инициализатор
очищает/заполняет эту память при **каждом** вызове, проверяет результат и
возвращает R0. Нельзя включать меняющееся состояние в проверяемую сумму,
иначе последующий cold boot отвергнет ранее работавший модуль.

После сохранения примера в `uJ11-fpga/build/module-example/MOD.MAC`, из корня
репозитория собрать native MACRO/LINK в новом каталоге:

```sh
python3 uJ11-fpga/tools/rt11_build.py uJ11-fpga/build/module-example/MOD.MAC --out uJ11-fpga/build/module-example/asm
```

Проверить `.LST/.MAP`, entry и диапазоны. `.SAV` — адресный memory image:
в файл модуля идёт срез **BASE..IMMEND**, не весь SAV. Для данного примера
IMMEND=`040004`; у реального модуля взять символ из его assembly listing.
У `module_image_cp67.py` нет CLI, используется Python API:

```python
from pathlib import Path
import sys
sys.path.insert(0, str(Path("uJ11-fpga/tools").resolve()))
from module_image_cp67 import pack, decode

root = Path("uJ11-fpga/build/module-example")
base, immend = 0o40000, 0o40004  # только для примера выше
sav = (root / "asm/MOD.SAV").read_bytes()
image = sav[base:immend]
assert len(image) == immend - base
module = pack(base, image)
print(decode(module))
(root / "MOD.BIN").write_bytes(module)
```

`pack` добавляет header, image checksum и нулевой padding, `decode` независимо
проверяет полученный формат. Это ещё не тест исполнения. До загрузки на плату
проверить инициализатор в RTL, повторный reset, повреждение checksum и recovery;
пример существующих сценариев — [tb_modules_cp67.v](../tb/tb_modules_cp67.v).
Затем COPY `MOD.BIN` в `SY:`, `RUN UJMOD` → `MOD`, длинный RESET без ESC,
`RUN UJMOD` → `STATUS`. BASE вызывается как обычная подпрограмма независимо
от имени файла: тип модуля в таблице не появляется.

### Перенос между пространствами

ROM после cold reset ставит resident copier и **слово-указатель** `HALT[160]`.
Модуль в HALT может скопировать подготовленный блок в USER:
R1 — HALT-адрес сразу после блока, R5 — USER-адрес сразу после назначения,
R2 — положительное число слов. Вызов `JSR PC,@160` косвенный через resident
pointer; `JSR PC,@#160` имеет другой смысл и здесь неверен. Copier идёт назад,
читает HALT обычным MOV, пишет USER через MTUS и проверяет через MFUS.
Области должны быть чётными и вне I/O; это системная подпрограмма, а не
публичный загрузчик с полной проверкой произвольного входа. Ошибка copier
при доступе к памяти идёт через действующий HALT fault vector; несовпадение
readback ведёт в resident idle/fallback, а не возвращает R0 с кодом ошибки.
В последнем случае для восстановления может потребоваться длинный RESET/ESC.

Именно так [SDBOOT](../firmware/cp67/SDBOOT.MAC.in) готовит USER `004000`,
пишет BOOTPC в `HALT[120]` и возвращается через `RTS PC`. Сам модуль не делает
START: после обхода всей таблицы это сделает resident.

Обратный путь USER→HALT при установке организован через signature HALT:
R4=`125061`, R5=USER source, R1=HALT destination, R2=1..64 слова. Resident
проверяет параметры и возвращается в USER через START. R2=0 — вызов helper,
предварительно установленного по `001000`. UJMOD читает файл средствами
RT-11 в USER и переносит/проверяет данные helper-операциями по 8 слов.
Между вызовами RT-11 снова может обслуживать IRQ. HALT helper/initializer
не вызывает RT-11 API: во время службы IRQ/RK assist отложены.
[Резидент и register contract](halt-boot-cp61.md),
[helper/векторный ABI](vector-loader-cp62.md).

Обычный возврат `RTS PC` из module init и служебный выход HALT→USER через
START/общий return `166` — разные уровни. Их нельзя взаимозаменять.

## Измерения и воспроизведение

CP67a — первый прототип дополнительного firmware EBR, ещё до окончательной
реализации ESC/BOOTPC: **1244 LUT, 381 FF, 7 EBR, 628 slices, Fmax 32,032 MHz**.
MAP/PAR/TRACE 31,824 MHz с внешними FRAM constraints — PASS. Микрокод прежний,
1005/1024 слов. Это +14 LUT, +10 slices и +1 EBR к CP63b. Свободны 36 LUT,
12 slices, 0 EBR. [Исходные отчёты](../synth/reports/cp67a/result.json).
Окончательный CP67b прошёл отдельный synthesis и дал те же цифры:
**1244 LUT / 381 FF / 7 EBR / 628 slices / 32,032 MHz**, fully routed, timing
31,824 MHz с FRAM constraints — PASS.
[Отдельные первичные отчёты CP67b](../synth/reports/cp67b/result.json).
JED экспортирован из этой source-matched сборки; SHA256
`d2e9000c47477c0ad8e8b4167338c74f274f2650dc46d8f1378446bb467e710d`,
JEDEC checksum `84CC`. Экспорт не означает прошивку платы.

ROM расширен с 512x16 до 1024x16: два 1024x9 EBR, по одному на каждый байт.
Это избегает 16-битного мультиплексора двух ROM-банков. HALT overlay расширен
до `013777`; cold walker работает из FRAM `005000` и снимает только HALT overlay
записью `000076`. Прежний протокол SD boot_complete остаётся независимым.
Microcode/core/ALU/RF/IRQ не изменены; профиль `--modules-cp67` включается явно.

Команды из корня репозитория:

```sh
python3 uJ11-fpga/tools/build_software_cp67.py
python3 uJ11-fpga/tools/test_modules_cp67.py
python3 uJ11-fpga/tools/test_modules_cp67.py --vendor
python3 uJ11-fpga/tools/test_modules_cp67.py --full-window
python3 uJ11-fpga/tools/run_modules_cp67.py --out uJ11-fpga/build/cp67-rt11-new
python3 uJ11-fpga/tools/checkpoint_board.py cp67new --modules-cp67 --clock-mhz 31.824 --fram-timing
```

Сборка использует DEC MACRO/LINK в RT-11 на частной копии диска. `microasm11`
не используется. Длинные функциональные тесты сокращают только два literal
счётчика окна UART; отдельный full-window тест исполняет производственные
значения. Directed portable tests: **30 сценариев, 249 проверок — PASS**,
включая настоящие ODT/SDBOOT, повторный reset, ошибки и ESC перед бесконечным
модулем. Прежняя breakpoint-регрессия ODT: **112 checks, 103 commands — PASS**.
Vendor Lattice DP8KC ROM: те же **30 сценариев, 249 проверок — PASS**, с теми же
тактовыми отсчётами. Прежняя core-регрессия: 187 checks / 175 commands; пульт:
2699 checks / 85 окон — PASS. Собранные native UJMOD RANGE/VALID/SELECT/PUTCHK:
38 сценариев / 49 checks — PASS. Формат файла: шесть Python tests с негативными
подслучаями — PASS. Полный RT-11FB V05.03 install/reset/recovery тест:
**55 checks / 1 023 462 941 такт / 3983 байта UART — PASS**. Проверены установка
ODT/SDBOOT, повторная холодная инициализация, повреждённые образы, пересечения,
OFF/DEL, RESET во время копирования, сохранение следующей исправной записи,
ESC-обход зависающего bootstrap с правильной checksum и возвращение к обычному
старту. Каждый выходной байт UART сверен с последовательным сигналом;
исходный и рабочий дисковые образы сохранили SHA256.
