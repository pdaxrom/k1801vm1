# CP79: программная эмуляция FPP DCJ11

Цель по запросу пользователя — программно воспроизвести FPP **DCJ11/J‑11**.
FP11-A больше не является поведенческим профилем текущего модуля. Имя
`FP11.BIN` сохранено: FP11 — также общепринятое имя набора инструкций.
Отдельный ускоритель FPJ11, его временные характеристики и аппаратные
особенности не моделируются.

Модуль — обычные PDP-11 инструкции в HALT FRAM, с входом через уже
имеющийся FP service, возвратом USER-контекста и исключениями через 244.
Загрузчик UJMOD, таблица модулей, checksum, cold init, FIS в микрокоде,
bootstrap и FPGA CP67b используются прежние. Новых LUT/FF/EBR/uwords нет.
Аппаратные эксперименты PSW CP78 независимы: все три не прошли MAP.
Программная версия **установлена на плату 2026-09-15**: SD readback,
cold init, 43 аппаратных STEP и native FPTST прошли.
[Отдельный аппаратный журнал](board-fpp-cp79.md).

## Основание

DEC *DCJ11 Microprocessor User's Guide*, EK-DCJ11-UG-PRE, October 1983,
chapter 7: [локальный PDF](../../doc/EK-DCJ11-UG-PRE_J11ug_Oct83.pdf),
[копия DEC PDF](https://www.bitsavers.org/pdf/dec/pdp11/1173/EK-DCJ11-UG-PRE_J11ug_Oct83.pdf).
SHA256 локального PDF: `479e33a206ddf713793acc016a935e0ef6ab0473d2dc4c5930d7dc1c10080acd`.
Главы 7.2/7.3 задают F/D и FPS; 7.6 — точность; 7.7 — отдельные операции.
Общие руководства FP11-A использованы в исторических CP71–78 и не имеют
приоритета над этим описанием J‑11.

| Вопрос | CP77, профиль FP11-A | CP79, профиль DCJ11 | Страницы DEC |
|---|---|---|---|
| TST с memory FIUV | Меняет FN/FZ перед исключением | Сохраняет FPS NZVC | 7-31 |
| ABS/NEG с memory FIUV | Пишет ноль, меняет flags, затем trap | Не пишет operand, сохраняет flags | 7-12, 7-23 |
| LDF/LDD с memory FIUV | Flags отражают fetched −0 | AC и condition codes не меняются | 7-18/19 |
| LDCDF/LDCFD с memory FIUV | Flags отражают fetched −0 | Отмена до конверсии и flags | 7-16/17 |
| LDC без FIUV, exponent=0 | Нулевой результат мог сохранять FN от source | Точный положительный ноль, FZ=1, FN=0 | 7-17 |
| ADD/SUB при потере младших битов выравнивания | Семь guard bits с отбрасыванием, FP11-A error bound | Сохраняет признак отброшенных единиц; точное усечение/округление результата | 7-9/10, 7-13, 7-30 |

FIUV относится к отрицательному exponent-zero **в памяти**, включая
immediate. Операнды AC не вызывают FIUV. FID подавляет вектор, но не
возобновляет отменённую операцию: FER/FEC/FEA фиксируются, operand/flags
сохраняются. Уже успешно вычисленный EA update сохраняет прежний контракт
J11; неуспешный memory access имеет отдельный bus-abort путь.

Общие с прежней версией правила проверены по той же главе: шесть 64-битных
AC, FD/FL/FT, округление половины от нуля, F-mode сохраняет младшую
половину destination AC, обнуление при выключенных FIV/FIU, циклический
exponent при включённых, STCfi возвращает ноль и C/FC при conversion error.
MOD сохраняет документированные 59 бит D-произведения (7-21/22);
это не исключительная особенность FP11-A, удалять её не требуется.

## Реализация и эталоны

[FP11.MAC](../firmware/fp11/FP11.MAC) 00.11 убирает отложенные unary FIUV
writes и обновления load flags. При выравнивании ADD/SUB младший рабочий
бит становится sticky: если вправо вышла единица, он остаётся единицей.
При exponent gap >=64 ненулевой меньший operand представлен этой единицей.
Так учитывается даже очень малый вычитаемый operand в режиме FT.
Рабочие AMAN/BMAN остаются прежними четырьмя 16-битными словами.

Независимый Python эталон складывает точные целые произвольной длины,
сохраняет все биты при любом exponent gap и округляет единственный раз
до 24/56 бит. Это не копия firmware алгоритма. C helper с jammed alignment
проверяется против него, затем его результаты служат для RTL fixtures.
**250200 сравнений PASS**, включая все 255 exponent gaps, знаки, отмену,
малые разности, F/D и оба FT. Совпадение с физическим J‑11 по
недокументированным особенностям этим не утверждается.

[Адаптер эталона](../tools/fp_reference_cp79.py) сохраняет CPU/EA и FPP
dispatch нашего C-эмулятора. Из него удалены все FP11-A unary/load overrides.
Числовые ADD/SUB заменены на проверенный exact reference, MUL/DIV сохраняют
128-битный эталон CP74; MOD helper прежний. Ранее найденные ошибки
store-conversion CPU carry и порядка flags при bus abort исправлены
в частной копии, исходный `core/` не меняется.
Это **адаптированный**, а не неизменённый DCJ11 oracle. Field128 отдельно
отмечает ещё три класса manual expectations: invalid AC trap, immediate
read abort, unary write abort. Прежние A-specific классы 4/5 удалены.

Полная матрица содержит 444420 случаев и 4037 кодировок: 3949 допустимых
и 88 invalid-AC. Пять управляющих команд входят; 59 reserved control кодов
покрываются направленными событиями. В матрице 31952 operand fault
injections и 7524 odd-address probes. Относительно CP76 удалились 1304
попытки ошибки записи после FIUV: J‑11 не выполняет эти записи; добавлено
1280 arithmetic boundary случаев. Проверка ожидает **точную последовательность
всех USER stores**, поэтому лишняя запись в отменённой операции не скрывается.

Преобразования отдельно проверены на 251328 точных Python/C сравнениях,
включая все 65536 коротких целых и все 65536 значений LDEXP.
Directed portable и Lattice DP8KC: по 111 cases / 4174 checks — PASS.
Logic decode: **215760 cases / 15037488 checks — PASS**; 2602 случая
отмечены как manual expectations. Полный sync: **444420 cases / 30934144 checks — PASS**, 2656 manual
expectations. Все четыре части завершились без ошибок.

Полная RT‑11/UJMOD/ODT/FPP/SPI FRAM/SD симуляция: **99 checks /
832783650 clocks / 9776 UART bytes — PASS**. Проверены загрузка модулей,
43 FP шага, UART F и descriptor, самостоятельная FPTST, возврат в RT‑11,
cold init и отключение FP при сохранённом ODT. Это прежний board RTL
CP67b, без PSW adapter. Только literal-счётчики окна ESC сокращены до 1,
как в CP77/78; производственный bootstrap не менялся.

## Размещение и установка

Absolute module CP67 ABI3 / format2. INIT `060000`, immutable code до
`070232` exclusive: **4250 байт / 2125 слов**. BSS/stack 268 байт;
полное резервирование **4518 байт**, до `070646` exclusive.
FPS/FEC/FEA: `070232/070234/070236`; AC0–AC5 начинаются с `070240`.
После модуля до HALT I/O page свободны **28250 байт**.
ODT получает эти адреса из прежнего descriptor v1 по `060010`.

Загружать через RT‑11/UJMOD так же, как [пакет CP77](../demos/rt11/service/cp77/README.md),
используя новые файлы CP79. Слоты определять через STATUS. Прежний модуль
FP11-A заменяется по тому же base, cold init очищает FP state. FPGA
перепрошивать для этого не требуется. Пакет не содержит MMU или hardware FPU.

Полная J‑11 совместимость всей системы не заявляется: рабочая CP67b пока
не имеет CPU-local PSW 177776. Обращения FP-операндов к USER PSW требуют
отдельной программной обработки сохранённого CPSW. Эти ограничения
сохраняются в TODO. Проходы диагностик DFFPA/B/C на прежнем FP11-A в CP78
не переименовываются в квалификацию текущего J‑11 FPP.

## Воспроизведение

Из корня репозитория, с зависимостями [CP67](development-cp67.md):

```sh
python3 uJ11-fpga/tools/test_fp_math_cp79.py
python3 uJ11-fpga/tools/test_fp_conversions_cp79.py
python3 uJ11-fpga/tools/test_fp_paths_cp79.py --mode logic
python3 uJ11-fpga/tools/test_fp_paths_parallel_cp79.py --mode sync --workers 4
python3 uJ11-fpga/tools/test_fp_events_cp79.py
python3 uJ11-fpga/tools/test_fp_events_cp79.py --vendor
python3 uJ11-fpga/tools/run_fp11_rt11_cp79.py --out uJ11-fpga/build/cp79-rt11
```

Полный sync набор исполняется четырьмя независимыми процессами. Границы
частей кратны восьми случаям, поэтому фаза ACK-delay 0–3 сохраняется
в точности. Итоговые cases/checks суммируются только после PASS всех частей;
исходные векторы и глобальные номера случаев сохраняются. Частичные
metrics не выдаются за один последовательный benchmark.

Последний каталог должен быть новым: тест не перезаписывает диск
существующего прогона. Для отдельной сборки — `build_fp11_cp79.py`.

[Готовый пакет RT‑11](../demos/rt11/service/cp79/README.md),
[замороженный архив](../tb/reports/cp79/archive.json).
Проверка архива: `python3 uJ11-fpga/tools/verify_cp79.py --current`.
В архиве полные vectors хранятся один раз; отдельные части ссылаются
на проверяемые SHA256 диапазоны строк. Исторические CP71–78 не переписаны.
