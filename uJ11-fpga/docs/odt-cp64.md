# CP64: загружаемый ODT для UART и пульта

В [CP65](odt-cp65.md) добавлены автоматическая прокрутка, PREV/NEXT по командам,
клавиши 8–F и программный STEP OVER; регистры на пульте показываются по одному,
UART сохраняет полный dump. Ниже описана исходная версия CP64,
которая пока установлена на плате.

Обновление [CP64a](odt-cp64a.md) исправляет границу прокрутки короткого
результата. Команды и ABI прежние; новая согласованная пара доступна в
[service/cp64a](../demos/rt11/service/cp64a/). Размеры и исходные отчёты CP64
ниже сохранены как baseline; факт установки смотрите в журнале платы.

Программный монитор в HALT FRAM поверх **CP63b**, без MMU. RTL, decode,
firmware ROM и microstore не меняются. Это первый рабочий программный этап
[плана отладчика](odt-debugger-plan.md); точки останова и STEP OVER остаются
следующими этапами. FP11 не добавлен, FIS остаётся в микрокоде.

## Установка из RT-11

Нужна FPGA-прошивка с профилем `--debug-cp63`. CP56a не содержит нужного HALT ABI.
После программного этапа CP64 на плату установлена CP63b; аппаратные результаты
и состояние загрузки монитора — в [журнале установки](board-bringup-cp64.md).

Скопировать согласованную пару `ODT.BIN` и `UJON.SAV` и прежний CP62 `UJLOAD.SAV`
на системный диск RT-11. Исходники и готовые файлы: [service/cp64](../demos/rt11/service/cp64/).

```text
.RUN UJLOAD
UJLOAD> ODT
!UJLOAD-I-ODT READY
.RUN UJON
!UJON-I-CP64 DEBUG ENABLED; SHORT RESET ENTERS ODT
```

UJLOAD читает файл средствами RT-11, переносит его через HALT helper,
проверяет записи, checksum, BSS и wrapper. Его ABI2 и бинарник не изменены.
UJON отдельно проверяет capability CP63, ODT ready, общие переходы, wrapper,
сигнатуру и checksum неизменяемого кода/текстов конкретной сборки.
Только затем вызывает `ACTV=010004` через штатный резидент. ENABLE повторно
проверяет capability/ready, записывает и перечитывает вектор `110/112`,
включает debug последним и возвращается в RT-11. Новый firmware EBR не нужен.

Пара ODT/UJON должна происходить из одной сборки. Повторный UJON после работы
монитора допустим: контекст, буферы и другие изменяемые данные не входят в его
проверку кода. Полный payload, включая шрифт и исходные данные, проверяет UJLOAD
при загрузке. После cold reset ready и debug enable сняты; устаревшая FRAM
автоматически не исполняется. После повторной загрузки/отключения любого модуля
старым UJLOAD нужно снова выполнить UJON: старый CONFIG очищает debug enable.

## Команды UART

Числа по умолчанию **восьмеричные**, без знака, не более 16 бит. X выбирает HEX,
O возвращает OCT. В OCT регистр PSW имеет номер `10`, в HEX — `8`.
Команда разбирается целиком до изменения состояния; лишние аргументы,
переполнение числа, недопустимый диапазон и незавершённый ввод не выполняются.

| Команда | Действие |
|---|---|
| `H` | Полная справка |
| `R` | R0–R7, PSW, T, IPL, NZVC отдельными строками |
| `R n` / `R n value` | Просмотр / изменение регистра или PSW |
| `M addr [count]` | Слова USER RAM, до `20` восьмеричных за запрос |
| `B addr [count]` | Байты USER RAM, включая нечётные адреса |
| `W addr value` | Запись слова, чтение обратно и сравнение |
| `V addr value` | Запись байта с сохранением соседнего байта, readback |
| `D [addr [count]]` | Адрес, исходные слова и дизассемблированная команда |
| `S [count]` | Настоящий STEP; до `100` восьмеричных шагов |
| `C` | CONTINUE с исходным/отредактированным контекстом |
| `G addr` | Изменить PC, снять сохранённый WAIT/старый trace и продолжить |
| `O` / `X` | OCT / HEX для отображения и ввода |
| `<` / `>` | Прокрутить только окно HDSP |
| `K m p n e` | Привязать MEM/PREV/NEXT/ENTER к различным кодам `20..23` |
| ESC / CTRL/C | Отменить ввод; длинный dump проверяет отмену между строками |

При изменении печатаются прежнее и новое значения. На входе и после каждого
шага выводятся причина `DEBUG`/`HALT`, WAIT при наличии, весь контекст и текущая
команда. PC — следующая гостевая команда, не PC монитора. Для opcode HALT это
явно указано в сообщении. Аппаратная причина «кнопка» и «завершение STEP» имеют
один debug-вектор; монитор не заявляет отсутствующий аппаратный cause register.

Нормальный просмотр и запись ограничены USER RAM `000000..157777`.
Автоматического доступа к I/O CSR нет. RAW HALT/явный I/O просмотр в этот этап
не входят. Дизассемблер читает только opcode и необходимые extension words,
не разыменовывает операнды. Покрыты основные integer инструкции, EIS, FIS,
SPL/PSW, все способы адресации, PC/immediate/absolute, branch/SOB targets.
Неименованные сочетания CC и неизвестные/FP11 encodings выводятся `.WORD`;
это не реализация FP11. Если extension word недоступен, выводятся известное
слово и отметка ошибки вместо выдуманного значения операнда.

## Пульт HDSP и 20 клавиш

Перед проверкой клавиатуры выбрать GPIO и отключить программатор JTAG от
общих TMS/TCK/TDI/TDO. Подключённый программатор может мешать чтению клавиш
даже при выбранном GPIO; такой случай обнаружен на плате 2026-09-13.

Используется [исходная раскладка](panel-keyboard.md), один общий обработчик
команд с UART. Команды, выполненные с панели, печатаются как `[PANEL] ...`,
а результат выводится полностью, без ограничения 16 символами. Запись/шаг
исполняется один раз. HDSP показывает окно уже сформированного результата;
прокрутка не делает новых чтений памяти и ничего не печатает в UART.

| Экран | MEM | PREV / NEXT | ENTER |
|---|---|---|---|
| Регистры | Меню | Соседний R0–R7/PSW | Редактировать |
| Память | Меню | Соседнее слово/байт | Редактировать |
| Команда | Меню | Сдвиг 16-символьного окна на один знак | Следующая команда |
| Меню | Меню/отмена ввода | Выбор пункта | Выполнить |
| Ввод числа | Отменить | PREV удаляет последнюю цифру | Подтвердить |

Меню: регистры, адрес памяти, адрес дизассемблирования, STEP, CONTINUE,
GO, OCT/HEX, WORD/BYTE. После выбора STEP повторный ENTER делает ещё шаг.
Цифры 0–F служат только вводу: в OCT 8–F не принимаются. Редактирование пока
последовательное, без перемещения курсора внутри числа. Автоповтор удерживаемой
клавиши и история адресов дизассемблирования остаются в TODO.

Драйвер сохраняет proven serial order и шрифт PNLDRV. HALT-вариант не вызывает
RT-11 и не использует WAIT/IRQ для задержек. Полный скан матрицы отвергает
несколько одновременно замкнутых пересечений; debounce требует двух повторных
подтверждений кандидата после смены кода. Это число сканов, не измеренная на
плате длительность. Изначально MEM/PREV/NEXT/ENTER назначены кодам `20/21/22/23`;
их соответствие надписям нужно подтвердить на плате, при необходимости K меняет
привязку без пересборки. Фрагмент схемы не заменяет этой проверки.

У ввода один владелец. При редактировании с панели UART-команда получает BUSY,
ESC отменяет редактирование. При незавершённой UART-строке цифры панели
игнорируются, MEM отменяет эту строку. Короткий RESET внутри монитора очищает
незавершённый ввод и очередь; новый аппаратный контекст не создаётся.

## Контекст и периферия

Вход сохраняет R0–R6 прямыми MOV до установки собственного SP, затем копирует
CPC/CPSW. Ошибка MFUS/MTUS идёт через SEL004 и восстанавливает программный
стек монитора, не портя гостевой контекст. Общий ABI2 выход по 166 не меняется;
монитор имеет собственные согласованные выходы START и STEP с восстановлением
SEL004, CPC/CPSW и регистров. STEP сохраняет семантику WAIT; несколько шагов
на уже ожидающем WAIT не исполняют следующую команду. Изменение PC снимает WAIT.

Нечётный гостевой SP можно просмотреть и исправить. ODT не подменяет его
автоматически: продолжение с нечётным SP при pending IRQ закономерно может
закончиться двойной ошибкой CPU. В тестовой программе неверный SP используется
только под IPL7; перед разрешением IRQ программа восстанавливает нормальный SP.
Терминальная двойная ошибка остаётся случаем для длинного RESET, как CP63.

UART переходит во владение монитора. IE и TX BREAK сохраняются, на время ODT
снимаются и восстанавливаются при выходе. Старые непрочитанные символы гостя
нельзя обещать сохранить: аппаратно имеется один holding register. Программная
очередь 64 байта обслуживается при выводе и при сдвиге битов панели.
При overflow/ошибке RX очередь отбрасывается до нового корректного CR;
обрезанная строка не становится командой записи. Для конечного сообщения
CONTINUE учитывается различие TX-ready и конца передачи: после освобождения
holding register выдерживается не менее 4096 clocks, больше одного кадра UART.

В полном тесте ввод идёт с интервалом около 1,77 ms между началами символов,
не непрерывной вставкой на 115200 baud. Скорость произвольной вставки ещё не
квалифицирована. Pending IRQ, UART и таймер продолжают существовать; ODT
не замораживает внешнее время и не сбрасывает периферию.

Если при входе CSR панели показывает владение TDO со стороны HG (bit7),
монитор не сканирует клавиатуру и не обновляет HDSP; UART остаётся доступным.
При обычном захвате панельного интерфейса сохраняется и возвращается сырой
выходной CSR. Предыдущее изображение HDSP и содержимое внешнего shift-register
не восстанавливаются. Полноценный сеанс HG во время ODT не проверен.

## Размер и аппаратный baseline

Окончательная сборка: payload **7626 байт**, всего с данными/буферами/стеком
**8410 байт из 12288**, свободно **3878 байт**. Файл ABI2 занимает 16 блоков
(8192 байта). Стек монитора — 256 байт. Сборка выполняется настоящими
RT-11 MACRO/LINK в SIMH; microasm11 не меняется и не используется этой сборкой.

Hardware остаётся точным CP63b: **1230 LUT / 381 FF / 6 EBR**, 618 slices,
Fmax **32,246 MHz**, 1005 microinstructions. Это прежний измеренный результат,
а не новая оценка по размеру программы. Повторный synthesis для программы в
загружаемой FRAM не нужен; checker сравнивает все аппаратные выходы генератора
с архивом успешного CP63b MAP/PAR/TRACE. Номинальные CPU/SCK — 29,56 MHz.

## Проверки и воспроизведение

Окончательные счётчики и SHA — в `verification-cp64.json` и `tb/reports/cp64`.
Проверки выполняют production PDP-11 код на RTL, без подмены регистров CPU.
Быстрый стенд задаёт память и UART bus model; полный стенд загружает файлы
из RT-11 через настоящий SPI FRAM/SD, проверяет UART start/data/stop и полный
640-bit поток glyphs, включая порядок двух модулей HDSP. Исходный системный
диск и backing копии не меняются после старта simulation.

```sh
python3 tools/build_odt_cp64.py --out build/cp64-new
python3 tools/test_odt_cp64.py --odt build/cp64-new --out build/cp64-test-new
python3 tools/test_odt_cp64.py --odt build/cp64-new --mode logic --out build/cp64-logic-new
python3 tools/test_odt_cp64.py --odt build/cp64-new --mode vendor --out build/cp64-vendor-new
python3 tools/test_odt_panel_cp64.py --odt build/cp64-new
python3 tools/run_odt_cp64.py --odt build/cp64-new --out build/cp64-rt11-new
```

Нужны существующие SIMH `pdp11`, `lsi11/rt11tool`, Verilator, Icarus Verilog
и сохранённые vendor simulation models для `--mode vendor`. Неизменённые
Lattice DP8KC/GSR/PUR запускаются в Icarus; logic/sync — в Verilator.
Каждый assembler/full-RT11
прогон использует новый каталог и частную копию диска.
