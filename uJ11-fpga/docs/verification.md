# Проверки текущего дерева

Реструктуризация 2026-09-22 сохраняет установленное поведение. Аппаратный
baseline — CP67b; программный — ODT CP77, FPP J‑11 CP80, SDBOOT/UJMOD ABI3.
Последняя проверка физической платы — 2026-09-20. При очистке плата
не перепрошивалась, новый Diamond MAP/PAR/TRACE не выполнялся.

## Проверка сохранения реализации

`make verify` сравнивает действующие исходники с зафиксированным релизом:

- SHA256 всех файлов исходного аппаратного snapshot.
- Код RTL и сгенерированных EBR после удаления комментариев/пробелов;
  разрешена только известная замена пути `build/cp67-modules/` на `build/hardware/`.
- Все слова microstore 1024×36, dispatch 1024×9 и firmware 1024×16.
- Побайтное совпадение пересобранных ODT.BIN, SDBOOT.BIN, UJMOD.SAV и FP11.BIN.
- SHA256 готовых файлов релизов, включая BASIC и прошитый JED.

Результат — PASS. Firmware собирается DEC MACRO/LINK из нормальных исходников;
архив релиза используется только для сверки. Это проверка сохранённого
baseline, не разрешение пропускать synthesis после будущих изменений RTL.

Команды — в [руководстве разработчика](development.md). Сводка и hashes сохранены в [cleanup.json](../releases/cleanup.json).
Все новые логи,
материалы компиляции и manifests создаются в игнорируемом `build/`.
Счётчики полного RT-11 сценария включают загрузку, UART, SD и ожидания;
это не CPI одной инструкции и не новая оценка Fmax.

В RT-11-тестах сокращено только окно UART ESC; значения замены явно
записаны в `inputs.json`. Тест конфигурации самостоятельно создаёт внешний
FRAM-образ из текущих BIN и ABI3-таблицы. Он не зависит от сохранённого
состояния прежней симуляции; CPU запускает обычный cold bootstrap.
Поэтому clocks/UART size этого прогона отличаются от исторического CP82,
где исходным было сохранённое содержимое внешней памяти.

При переносе исправлены устаревшие ожидания тестов: приветствие ODT
теперь проверяется для CP77, меню учитывает четырнадцатый пункт FP.
Исполняемый код ODT при этом не менялся. BASIC-runner переводит исходные
BAS из LF в CRLF только в копии для SD, как ожидает RT-11; исходники
остаются обычными текстовыми файлами. Неожиданный вход в ODT во время
числового BASIC-теста завершает прогон ошибкой вместо бесконечного ожидания.

## Границы результата

Полные числовые FPP sync/logic/vendor матрицы, прежние ISA/EA/EIS/FIS,
fault/IRQ и hardware pin suites остаются в [снимке до очистки](../history/README.md).
Стенды старых экспериментальных datapath/memory profiles не включены в
текущий Makefile. Их исторический PASS не является новым прогоном
перенесённого дерева. Текущие полные FPP и vendor-команды сохранены; при очистке повторялись
числовая выборка и направленные сценарии, включая события с vendor EBR.

Не заявляются новый routed timing, измерения PCB/OSCH, полный физический
проход каждой кнопки, внешняя полная диагностика J‑11 или MMU/RT-11XM.
Незавершённые функции и квалификация перечислены в [TODO](../TODO.md).
