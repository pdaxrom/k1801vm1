# CP60: загрузчик служб из RT-11

`UJLOAD.SAV` — обычная программа PDP-11 под RT-11FB V05.03. Она читает
файлы с системного диска через ОС и устанавливает их в верхнюю FRAM через
инструкции CP58/CP59. Полные ODT и FP11 пока не реализованы: используемые
при проверке маленькие обработчики — только тестовые файлы.

CPU и его микрокод сохраняют CP59d, 1002 слова. Проверка загрузчика выявила
ошибки аварийного пути RK611, поэтому board decoder и дисковая firmware
исправлены отдельным профилем `--rk-cp60`. Полный HC1200 **CP60b**:
**1251 LUT / 343 FF / 6 EBR / 629 slices / Fmax 32,807 MHz**;
31,824 MHz и прежние FRAM constraints проходят. Файловые данные и сам
UJLOAD не добавляются в EBR/JED. [Исправление RK и synthesis](rk-recovery-cp60.md).
На установленном CP56a нет служебного интерфейса: для аппаратной загрузки
нужна отдельная установка FPGA-профиля с этим интерфейсом.

## Работа в RT-11

```text
.RUN UJLOAD
UJLOAD> ODT
!UJLOAD-I-WRITING; target disabled
!UJLOAD-I-ODT READY

.RUN UJLOAD
UJLOAD> FP11
!UJLOAD-I-WRITING; target disabled
!UJLOAD-I-FP11 READY

.RUN UJLOAD
UJLOAD> STATUS
ODT=1 FP11=1
```

Вводится базовое имя файла: 1–6 заглавных латинских букв/цифр, без
расширения. Например, `ODT` означает `SY:ODT.BIN`. Тип устанавливаемого
модуля берётся из проверенного заголовка, а не из имени. В этой версии
произвольные устройства и пути не поддерживаются; системный обработчик
SY уже находится в памяти. `OFFODT` и `OFFFP` независимо снимают ready,
не стирая FRAM. `EXIT` завершает программу. Каждое выполнение обрабатывает
одну команду; `.GTLIN` позволяет использовать и командный файл RT-11.

Перед вводом команды программа временно устанавливает обработчик reserved
instruction, проверяет UJSTAT и восстанавливает прежний вектор. На обычном
DCJ11 выводится сообщение об отсутствии инструкций, затем управление
возвращается ОС. Проба не различает версии CP57/CP58: документированная
предпосылка этой firmware ABI — **CP58 SEL004**. Для проверенного возврата
после ошибок SD нужен **CP60b**: на CP58/CP59 аварийный путь RK зависает.
Установочные
инструкции доступны гостю и не являются механизмом защиты памяти.

Файловые вызовы следуют DEC: `.LOOKUP` открывает именованный файл и
возвращает размер в блоках; `.READW` синхронно читает слова с блоковым
смещением; `.CLOSE` освобождает канал; `.GTLIN` получает строку с терминала
или из командного файла. Указатели, число слов и обработка carry сверены
с [RT-11 System Macro Library Manual](https://bitsavers.org/pdf/dec/pdp11/rt11/v5.6_Aug91/AA-PD6LA-TC_RT-11_System_Macro_Library_Manual_Aug91.pdf),
разделами 2–128, 2–147 и 2–215; сам код собран макросами **V5.03** из
исходного системного образа. Собственного драйвера SD/файловой системы нет.

## Файл ABI1

Little-endian слова. Первый блок — 512 байт заголовка; следующие блоки —
payload с нулевым дополнением до 512 байт. Индексы слов в таблице десятичные.

| Слово | Поле |
|---:|---|
| 0–1 | Байты `UJ11`, слова `0x4A55`, `0x3131` |
| 2 | Версия файлового формата = 1 |
| 3 | Версия firmware ABI = 1 |
| 4 | Тип: 1 ODT, 2 FP11 |
| 5 | Фиксированный адрес начала своего участка |
| 6 | Размер payload в байтах, ненулевой и чётный |
| 7 | Полный размер памяти модуля в байтах, чётный, ≥ payload |
| 8–9 | Чётные адреса entry и SEL004 handler внутри исполняемого payload |
| 10 | Сумма слов payload modulo 65536 |
| 11 | Дополнение суммы 16 слов заголовка до нуля modulo 65536 |
| 12–15 | Flags/reserved = 0 |

Остальная часть блока заголовка и padding последнего блока данных должны
быть нулевыми. Размер файла в RT-11 должен быть **ровно**
`1 + ceil(payload_bytes / 512)` блоков. Это позволяет отвергать обрезанные
файлы и лишние блоки. Контрольная сумма предназначена для обнаружения
повреждения, не для аутентификации; host-артефакты дополнительно имеют SHA-256.

Участки верхнего банка, адреса восьмеричные:

| Область | Диапазон | Размер |
|---|---|---:|
| Системный ABI, копии и переходы | `000000..000377` | 256 байт |
| ODT: код, данные, собственный стек | `000400..037777` | 15872 байта |
| FP11: код, данные, собственный стек | `040000..177777` | 49152 байта |

Граница последнего участка — физические 65536 байт, без переполнения
16-битного расчёта. Обычные instruction fetch и стек должны оставаться
ниже `160000`: выше находится общая I/O page. Верхние 8 КиБ физического
участка FP11 пригодны для данных через raw UJRD/UJWR; загрузчик умеет
заполнять и проверять их до слова `177776` включительно. Это не линейные
128 КиБ для RT-11 и не MMU/RT-11XM.

Память между концом payload и полным размером модуля обнуляется и
проверяется. Там могут находиться BSS, FP state, сохранённые регистры и
стек. Остаток своего участка за объявленным размером не изменяется.

## Независимые ready и SEL004

До принятия заголовка никакая верхняя память или ready не меняется.
Отсутствующий файл, неправильный ABI/размер/адрес сохраняют старую службу.
После принятия заголовка снимается только ready целевого модуля. Каждый
записанный word немедленно читается обратно и сравнивается; затем отдельно
читается весь payload для повторной суммы и вся BSS для проверки нулей.
При ошибке или CTRL/C после начала переноса цель остаётся выключенной.
Прежняя служба другого типа и её память сохраняются.

Системная часть firmware ABI:

| Адрес | Содержание |
|---|---|
| `000100/000102` | Аппаратные CPC/CPSW, загрузчик их не пишет |
| `000104` | Текущий адрес SEL004 handler |
| `000004/000006` | Общий SEL004 vector: `000200 / 000340` |
| `000200` | `JMP @000104`, PC-relative deferred |
| `000204` | Аварийный `BR .` до выбора обработчика; требуется reset |
| `000220` | Вход ODT: `MOV #fault,@#104; JMP @#entry` |
| `000240` | Такой же вход FP11 |
| `000170/000172` | ODT vector: `000220 / 000340` |
| `000010/000012` | FP11 vector: `000240 / 000340` |

Общие константы и fallback инициализируются только когда другая служба
выключена. Если она включена, пять общих слов сначала проверяются; при
несовпадении установка отвергается до изменения ready. Для восстановления
повреждённого общего ABI можно выключить обе службы и загрузить заново.
Только после payload/BSS/readback публикуются переход и вектор целевого
модуля, затем последним установочным действием выставляется ready.

Переходы не меняют R0–R6 и не используют стек гостя. MOV в переходе меняет
NZV текущего служебного PSW; модуль не должен считать эти флаги флагами
прерванной программы. Гостевой PSW находится в CPSW. Firmware сохраняет
нужные общие регистры/старый SP, выбирает собственный стек и возвращается
через START. Внутри службы нельзя вызывать RT-11 или её дисковые функции:
прерывания и RK assist отложены до возврата. Заголовок не подменяет эти
обязанности firmware. Параллельные экземпляры установщика не поддерживаются.

Cold reset снимает ready и не стирает FRAM. Старые данные не активируются
автоматически. RESET периферии сохраняет ready согласно CP59. Ограничения
HALT ВМ2, включая SEL174/274 и внешний HALT для STEP, остаются прежними.

## Сборка и проверка

Из `uJ11-fpga`:

```sh
python3 tools/rt11_build.py demos/rt11/service/UJLOAD.MAC tb/rt11/UJCHEK.MAC --out build/cp60-asm-new
python3 tools/run_loader_cp60.py --asm-dir build/cp60-asm-new --tag cp60new
python3 -m unittest discover -s tb -p test_service_image.py
python3 tools/test_loader_compat_cp60.py --asm-dir build/cp60-asm-new --out build/cp60-compat-new
```

Сборщик использует установленный SIMH `pdp11` и оригинальные MACRO/LINK
на отдельной writable копии RK07. Исходный диск остаётся неизменным;
`microasm11` не изменяется и для этой сборки не требуется. Нужны новые
каталоги сборки/прогона. Заготовки из `loader_fixtures_cp60.py` предназначены
только для тестового диска, не являются полноценными ODT/FP11.

Пакетирование настоящего модуля после его разработки:

```sh
python3 tools/service_image.py build/ODT.BIN --payload build/odt-code.bin --kind odt --memory-bytes 0x2000 --entry 0o400 --fault 0o600
python3 tools/service_image.py build/ODT.BIN
```

Адреса в этом примере условные: должны соответствовать реальному коду.
Host CLI требует префиксы `0o`/`0x`, если значение не десятичное. Firmware
загрузки хранится отдельным `.SAV`; в JED она не включается.

## Полученные результаты

Финальный прогон `cp60e` на точных RTL/firmware входах измеренного **CP60b**
прошёл: **42 file/command cases + CTRL/C + cold reboot**. Проверяются все
65536 байт верхнего банка; после вызова служб аппаратные CPC/CPSW исключены
из сравнения с константами, их семантику отдельно покрывают прежние service
tests. Изоляция raw FRAM от UART/SD/timer/panel/RK проверяется при каждом
физическом обращении. UART сравнивается побайтно на выводе, с проверкой
start/data/stop bits, а не только на стороне CSR.

Покрыты установка обоих типов и повторная загрузка, 12 неверных заголовков
и размеров, payload checksum/padding, ошибка чтения реального файла с
восемью повторами DM.SYS, защита записи FRAM, повреждение после первого
readback, отказ общего SEL004 ABI и восстановление после отключения обеих
служб. После CTRL/C целевой FP11 остаётся выключенным, другой участок
сохраняется; повторная установка работает. Cold reset сохраняет содержимое
FRAM, снимает оба ready и вновь запускает RT-11.

`UJCHEK.SAV` проверил HALT → SEL004 → START и FP11 → START с сохранением
R0/R1/SP; независимый scoreboard проверил маркеры входов обработчиков.
Это проверка механизма вызова firmware, не арифметики полного FP11.

Сборка оригинальными MACRO/LINK V5.03 дала **0 ошибок**, размер UJLOAD —
3584 байта (7 блоков), code/data — 2960 байт. Шесть host unit tests формата
PASS. В SIMH 11/73 загрузчик корректно сообщает об отсутствии служебных
инструкций; последующий DIR работает. Создание отдельного диска с UJLOAD
и прежнего четырёхфайлового panel/HG диска проверено извлечением файлов
и сравнениями SHA-256, базовый системный образ не изменялся.
