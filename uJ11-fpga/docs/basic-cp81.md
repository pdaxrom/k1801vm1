# CP81: DEC BASIC-11 на uJ11 без аппаратного PSW 177776

Проверен оригинальный **DEC BASIC-11/RT-11 V2.1** из локального образа
`lsi11/disks/rt11v5.3/basic.dsk`. Исходный диск не изменялся; его SHA256:
`f68488b0da8106153a95fc1178198d687c227c1521b6506d07054207daf06b11`.
Полный комплект содержит настройщик SUCNFG и библиотеки арифметики FIS/FPU.
Готовая BASIC.SAV из комплекта использует программную арифметику, поэтому
для проверки процессора были собраны отдельные варианты.

## Сборки и эталон

Оригинальные SUCNFG/LINK создают B81FIS (FIS single), B81FPU (FPU single),
B81FPD (FPU double). Все используют overlay type 2 и одинаковые остальные
опции. FIS double в этом дистрибутиве не поддерживается.
[Команды сборки, готовые SAV и запуск](../demos/rt11/basic/README.md).

Две независимые сборки в свежих копиях диска дали одинаковые SAV, COM и MAP.
Три undefined globals при отключённом CALL предусмотрены SUCNFG;
других ошибок LINK нет. Контрольные суммы образов-доноров сохранились.
Другие проекты и microasm11 для сборки не изменялись.

| Вариант | SAV | Transfer address | High limit в MAP |
|---|---:|---|---|
| B81FIS | 27136 байт | `012304` | `060172` |
| B81FPU | 26624 байта | `011030` | `056716` |
| B81FPD | 27136 байт | `012410` | `060276` |

Адреса восьмеричные. Размер SAV на диске не равен всему рабочему
пространству BASIC: при исполнении дополнительно нужны программа и данные.

Эталон SIMH: 11/03 с EIS+FIS для B81FIS, 11/73 для B81FPU/B81FPD.
В каждом варианте **29 сравнений / 0 ошибок**. B81FPD дополнительно
прошёл тест младших разрядов double. Три ожидаемые ошибки — деление на ноль,
отрицательный аргумент SQR и переполнение — возвращают READY, после чего
`PRINT 2+2` снова даёт 4. Это 12 дополнительных команд в трёх вариантах.

## Полный RTL

Стенд загружает ту же RT-11 через SPI SD, использует настоящую модель
128 КБ SPI FRAM и устанавливает ODT/SDBOOT/FP11 через UJMOD. После cold init
все сервисы активны. Процессорные регистры, шины и результаты команд не
подменяются. Единственное ускорение — одна итерация окна выбора recovery
вместо производственной задержки. CPU/микрокод — frozen CP67b;
программный FPP — CP80, семантика DCJ11.

Полный проход: **22 проверки стенда / 1322444008 clocks / 1223 UART bytes,
PASS**. Внутри каждого BASIC отдельно выполнены 29 числовых сравнений.
Дополнительный B81DBL тоже прошёл. Проверки ожидаемых арифметических ошибок
из предыдущего раздела выполнялись отдельно в SIMH и не включены в этот
RTL-сценарий.

| Сеанс BASIC | Clocks | FIS | FPP opcodes | Входы HALT FPP | USER 177776 |
|---|---:|---:|---:|---:|---:|
| B81FIS + B81TST | 204015076 | 654 | 0 | 0 | 0 |
| B81FPU + B81TST | 364565396 | 0 | 4117 | 4117 | 0 |
| B81FPD + B81TST + B81DBL | 507545495 | 0 | 5782 | 5782 | 0 |

FIS: FADD 397, FSUB 15, FMUL 107, FDIV 135. Счётчики подтверждают
исполнение выбранных инструкций, а не только наличие библиотек в LINK.
Clocks включают запуск BASIC, чтение SD, UART, тесты и BYE; это **не** CPI
отдельной FP-инструкции и не чистое время численного алгоритма.
В double-сеансе дополнительно запускается вторая программа, поэтому
его время нельзя напрямую сравнивать с single.

## Физическая плата и найденная несовместимость FIS BASIC

Через HG установлены три SAV и два BAS. Пять обратных копий с SD
совпали с исходниками; BAS дополнены только нулями до границы блока.
B81FPU и B81FPD прошли по 29 сравнений, double-тест и обработку деления
на ноль, отрицательного SQR, переполнения с последующим `2+2 = 4`.
Все три FRAM-модуля до/после этих проверок имеют STATUS `140407`.

У исходного B81FIS числовой тест прошёл, но `PRINT 1/0` дал
`FLOATING UNDERFLOW`, затем возврат в RT-11; в первом проходе был также
`MON-F-Trap to 4 000010`. Сбой сохранён в `hardware/04-tests` и
`hardware/06-fis-fresh`; он не помечен как успешный тест.

Полный RTL воспроизвёл тот же дефект стека, сообщив `FLOATING OVERFLOW`.
FIS правильно записал `PSW=000013` и `PC=006464` в `000760/000756`.
Первое существенное отличие от SIMH 11/03 находится в RT-11: по адресу
`142650` монитор проверяет `BIT #100,120652`, а затем в `142660`
исполняет `STST -(R4)`. На uJ11 признак FPP включён; в SIMH 11/03 он
выключен. В результате пользовательский .SFPA-обработчик получает ещё
два слова FEC/FEA. Старый BSOT1S.FIS считает первое из них сохранённым PC,
а второе — PSW. Содержимое прежнего FEC/FEA объясняет разные сообщения;
арифметика FIS и транспорт FRAM не являются причиной этого расхождения.

DEC явно описывает дополнительные слова и способ их удаления в
[System Macro Library Manual, .SFPA, стр. 2–246/247](https://forum.maxiol.com/index.php?act=Attach&id=10292&s=8beb42d7d3957926994cb0e21684e360&type=post).
Проверяются `$SYPTR=54`, `$CNFG1=300`, `HWFPU$=100`, как в примере DEC.

## Адаптер B81FIJ

[FISABI.MAC](../demos/rt11/basic/FISABI.MAC) добавляет **26 байт** в
resident-часть BASIC. Он сохраняет R0, при наличии FPP удаляет FEC/FEA,
восстанавливает R0 и передаёт управление прежнему обработчику FIS.
Без FPP исходный стек передаётся без изменений. Вектор `244`, глобальная
конфигурация монитора, CPU, микрокод и FPP-модуль не изменяются.

MACRO создаёт relocatable OBJ; LINK пересчитывает BASIC и overlays.
После LINK драйвер сверяет точную структуру процедуры `IFPMP` и меняет
**одно слово** её .SFPA argument block на адрес `FIADPT` из MAP.
Обе процедуры адресуются по символам, а не по зашитому адресу сборки.
Неизвестная структура библиотеки останавливает сборку. Исходный SAV
сохраняется отдельно; все изменения относятся к новому `B81FIJ.SAV`.
Две независимые сборки дали одинаковые OBJ/SAV/COM/MAP.

На SIMH 11/03 новый вариант прошёл 29 сравнений и семь команд ошибок/
восстановления, включая underflow и повторное деление на ноль.
Полная модель CP67b с SPI FRAM/SD/UART: **17 checks / 384497709 clocks /
668 UART bytes, PASS**. Выполнены cold boot с retained-модулями, 29
числовых сравнений, семь команд ошибок/восстановления и BYE. До исключений
сеанс использовал 654 FIS и ни одного FPP opcode; при исключениях RT-11
штатно вызывает STST программного FPP. Это не эмуляция FIS через FPP.

**B81FIJ установлен и проверен на физической плате 2026-09-20.** Новый SAV
записан через HG отдельным файлом; исходный B81FIS сохранён. Обратная копия
с SD совпала побайтно: 27136 байт, SHA256
`5601be5c721ab5657ed6b7d177f719342c5164e177134441c24a58c624f5a349`.
После выгрузки HG новый BASIC прошёл **29 сравнений / 0 ошибок**, затем
семь команд: деление на ноль, отрицательный SQR, overflow, `2+2`, underflow,
повторное деление на ноль и ещё одно `2+2`. Сообщения совпали с SIMH;
каждая команда вернулась в READY, оба вычисления дали 4. До/после сеанса
ODT/SDBOOT/FPP имеют STATUS `140407`. Плата оставлена в RT-11, picocom
восстановлен, созданный для установки процесс HG остановлен.

Итого на плате проверены B81FIJ, B81FPU, B81FPD: три набора по 29 сравнений,
отдельный double-тест и **15 команд ошибок/восстановления**. Сохранены все
шесть обратных копий установленных файлов; установка и новый UART-прогон
находятся в `hardware/08-adapter-install` и `hardware/09-adapter-tests`.

В [CP82](modules-cp82.md) дополнительно проверено на плате: после OFF FPP
и холодного старта исходный B81FIS проходит арифметику и обработку ошибок
без модификаций. После возврата FPP для FIS снова используется B81FIJ.

## Область совместимости и ресурсы

По решению пользователя обычный CPU-local PSW `177776` и общий
NXM→HALT assist **отложены**. CP78 остаётся сохранённым экспериментом.
MFPS/MTPS, PSW в контексте trap/RTI и обработка PSW-операндов внутри
программного FPP CP80 сохраняются. MMU в текущем аппаратном профиле нет.

Успех прикладных тестов не означает полной совместимости со всеми
J-11 программами. Код, который обращается обычными integer-инструкциями
к memory-mapped PSW, по-прежнему не поддержан. PEEK/POKE произвольной
периферии и все редкие команды BASIC этим набором не проверяются;
внешняя полная диагностика J-11 FPP остаётся отдельной задачей.

FPGA в CP81 не перепрошивалась. Ресурсы прежней CP67b: **1244 LUT, 381 FF,
7 EBR, 628 slices**, TRACE **32,032 МГц**, nominal **29,56 МГц**,
microcode **1005/1024 слова**. Новый synthesis не выполняется,
прирост ресурсов от BASIC — **0**. Установленные четыре SAV и два BAS
занимают **216 блоков SD** (из них B81FIJ — 53 блока);
тесты работают в USER RAM и используют уже установленный FP11 в HALT FRAM.

## Архив и воспроизведение

[Каталог результатов](../tb/reports/cp81-basic/) содержит воспроизводимые
сборки, карты LINK, UART-журналы и контрольные суммы. Проверка архивных
свидетельств:

```sh
python3 uJ11-fpga/tools/verify_basic_cp81.py
```

Эта команда не обращается к плате и не заменяет новое исполнение тестов.
Manifest хранит `adapter_installed: true`; verifier проверяет SD readback,
реальные UART-ответы всех трёх рабочих вариантов, завершение HG и
контрольные суммы архива. Исходный сбой B81FIS сохранён отдельно и не
засчитывается как успешный аппаратный тест.
Для повторного запуска программ достаточно команд из руководства BASIC.

Для повтора именно замороженного RTL-прогона распаковать
`tb/reports/cp81-basic/rtl/source.tgz` в **отдельный** каталог. Файл
`test.dsk.gz` распаковать там в `build/cp81-basic/rtl-a/test.dsk`.
`replay.json` содержит массивы аргументов `compile` и `run`; выполнить их
из корня распакованного дерева (например, через `subprocess.run`). Перед
компиляцией создать `build/cp81-replay`. Результаты будут в этом новом
каталоге. Архив проверен отдельно `verilator --lint-only`; основной
simulation PASS получен первоначальным полным прогоном, без повторного
исполнения всех 1,32 млрд тактов при упаковке.

Скрипт `hardware_basic_cp81.py` запускается на Linux-хосте платы, временно
приостанавливает выбранный picocom, проверяет отдельный ответ на каждую
команду и восстанавливает picocom при завершении или ошибке. До/после
тестов он проверяет STATUS трёх retained-модулей. Файлы должны быть уже
установлены; скрипт не меняет FPGA или образы модулей.


Для повторения адаптера использовать `adapter/rtl/source.tgz`, его
`test.dsk.gz` и `replay.json` по той же схеме. Образ диска распаковать в
`build/cp81-basic/rtl-fis-abi/test.dsk`, создать `build/cp81-fis-replay`.
Стенд загружает сохранённые **байты внешней FRAM** с зарегистрированными
модулями, затем выполняет аппаратный reset и настоящий bootstrap. Состояние
CPU не задаётся. Весь initial FRAM включён в source archive; replay lint
прошёл. Отдельные `diagnosis` сохраняют исходный сбой и корректный FIS trap
frame, а `adapter` — новые MACRO source/OBJ/LST, SAV до/после изменения
одного указателя и MAP.
