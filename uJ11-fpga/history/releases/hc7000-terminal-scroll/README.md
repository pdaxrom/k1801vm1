# HC7000: исправление прокрутки PAL, JED 54D2

> Историческая запись: `releases/hc7000-terminal-scroll/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../README.md).


2026-10-01. Сборка `terminal-scroll-50-04` установлена на HC7000:
LCMXO2-7000HC-4TG144C, SRAM IS61WV102416BLL-10T, генератор 12 МГц.
MMU / SERV storage / FPP off / FIS / diagnostics / PAL / terminal.
CPU работает на 50 МГц, PAL на 64 МГц; экран 640×240 / 80×30 символов.

В предыдущей JED 3428 SERV откладывал `YORIGIN` до завершения всех dirty-ячеек
и не рисовал при непустой очереди. Несколько переводов строки накапливались,
а новые символы могли появляться в прежней верхней строке перед общим скачком.
Повторное изменение ячейки также сохраняло слишком широкую dirty-область.

Теперь сдвиг публикуется сразу, на каждом поле PAL (20 мс). Парсер ждёт
подтверждения сдвига и очистки новой нижней строки; остальные dirty-ячейки
можно рисовать во время ожидания. Очистка использует 640 равномерных записей
пикселей, проверяет дисковые запросы каждые 16 слов и возобновляется после них.
Автоматический перенос сохраняет новый символ. Полный framebuffer не копируется.
Очередь сохраняет байты и при заполнении задерживает консольный вывод.

## Размещение и память

| Показатель | Результат |
|---|---:|
| LUT | **5897 / 6864**, свободно 967 |
| FF | 2020 / 7209 |
| EBR / PLL | 26 / 26; 2 / 2 |
| Изменение относительно 3428 | +3 LUT, +1 FF, +0 EBR |
| Fmax CPU / PAL | 50,633 / 64,927 МГц |
| Код и константы SERV | 14743 байта |
| BSS | 1068 байт |
| Запас перед стеком / cold bank | 1980 / 512 байт |
| Резерв стека | 640 байт |

Ограничения CPU 50 / PAL 64 МГц, SRAM и четырёх CDC bundles прошли без
отрицательного slack; все соединения разведены. Для разрыва пути RV32C
aligner → проверка адреса → enable EBR добавлен один регистр запроса выборки
инструкции SERV. Он добавляет один такт выборки только терминальному профилю
50 МГц. SERV удерживает адрес до ACK; отдельная копия адресной шины не нужна.
Датапуть и частота J11 не менялись.

Для гостевой ОС доступны 1936 КиБ SRAM. Текст и видео сохраняют резерв
112 КиБ; NXM защищает его от обычного CPU и дискового DMA. Профили HC1200,
MMU-less и PAL без терминала сохраняют прежнее поведение.

## Проверки

- Хостовый парсер: немедленная публикация сдвига, сохранение байта и прежних
  пикселей до ACK, очистка нижней строки, dirty-диапазон одной ячейки,
  символ после автоматического переноса.
- Реальный SERV / UART / PAL / SRAM: **111673 проверки**, 430 байт провода,
  шесть отдельных сдвигов по 8 пиксельных строк, ACK за ≤20 мс + 10 тактов,
  стабильный адрес выборки SERV до ACK, сохранение PAL после гостевого RESET,
  отсутствие underrun. Стек 272 / 640 байт.
- DMA / резерв: **7238 проверок**, NXM без записи на SD, восстановление
  после ошибки. RL NOP во время ожидания сдвига: 22121 такт (0,442 мс),
  во время очистки: 25993 (0,520 мс); обычный контроль: 29965 (0,599 мс).
  Стек 336 / 640 байт; исходный SD-образ не изменён.
- PAL без терминала, 200 строк: 13 кадров / 11507200 пикселей под конкурирующими
  CPU и дисковым DMA; строковый EBR и RGB332 encoder прошли отдельные проверки.
- Проверка production HC1200 прошла: сохранены RTL/EBR, три ROM, BASIC и JED.
- Физическая плата: Flash Erase/Program/Verify, BSD RL0, XP0 `/usr`, multiuser,
  root, `ls -l /usr`, шесть отдельных переводов строки и `sync` прошли.
  **Визуальное подтверждение исправленной прокрутки пока ожидается.**
  [Аппаратные логи](validation/hardware-20261001/README.md).

В нагруженном UART/PAL стенде ожидание очереди составило 47438060 тактов
(0,949 с): сохранение порядка каждого видимого сдвига ограничивает вывод
50 строками/с. Это измерение консольного потока, а не общей скорости CPU.
Начальный framebuffer побайтно совпал с проверенным изображением JED 3428.

Повторные загрузки RT-11 V4 / XM и RSX на этой версии не запускались;
их сохранённые результаты относятся к [исходному выпуску терминала](../hc7000-terminal/README.md).
