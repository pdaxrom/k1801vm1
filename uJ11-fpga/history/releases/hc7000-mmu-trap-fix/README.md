# HC7000 MMU: исправление режима и стека обработчика TRAP

> Историческая запись: `releases/hc7000-mmu-trap-fix/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../README.md).


2026-09-27, ветка `uJ11-hc7000`. Исправление базового MMU-профиля
[`hc7000-mmu-microcoded`](../hc7000-mmu-microcoded/README.md).

## Причина

После `PRINT 1/0` B81FPU печатал `?DIVISION BY ZERO`, затем RT-11 XM
останавливался в ODT. На плате прочитаны PC=116452₈, PSW=000344₈;
116446₈ — RESET, 116450₈ — HALT, 116452₈ — BR на HALT.
Полный RTL воспроизводит тот же останов (`validation/before`).

Первое существенное нарушение — обработка BASIC-инструкции TRAP
по адресу 007144₈. ODT подтвердил установленный вектор:
034₈=010762₈, 036₈=140000₈. Новый PSW требует **User mode**.
Однако `uj11_mmu_cpu.v` при загрузке PSW из вектора принудительно обнулял
Current Mode. Обработчик получал PSW=030000₈ и Kernel SP вместо
PSW=170000₈ и User SP. Работа BASIC на неправильном стеке в итоге
приводила к нечётному PC, trap 4 и аварийному останову RT-11.

Теперь Current Mode берётся из PSW вектора; Previous Mode по-прежнему
берётся из прерванного контекста. Чтение самого вектора остаётся в Kernel
Data space. Это соответствует [обработке trap/interrupt в SIMH](https://github.com/simh/simh/blob/master/PDP11/pdp11_cpu.c).
Арифметический FPP и микрокод не менялись.

PSW по адресу 177776₈ уже был реализован в MMU-профиле: CPU перехватывает
физический адрес 17777776₈, поддерживает слова и обе байтовые полосы.
На плате чтение этого адреса через ODT совпало с `R 40` (000344₈).
В прежнем MMU-less-профиле этот регистр отсутствует; профиль не менялся.

## Проверки

- Новый CPU-тест до исправления воспроизводит неправильный режим;
  журнал — `validation/before-unit/tb_cpu.log`.
- После исправления: 66 проверок CPU, включая User→User и User→Supervisor
  через вектор, выбор стека и RTI; 786432 трансляции, 3375 MMU-транзакций,
  263704 проверки арифметического datapath. Повторено с моделями EBR Diamond.
- Дифференциальный FPP: 444420 случаев, 17601544 проверки, PASS.
- Полный CPU/SERV/SD/SRAM/UART с XM: B81FPU и B81FPD проходят по 29
  сравнений; B81DBL проходит проверку double. Деление на ноль (включая
  повторное), отрицательный SQR и overflow возвращают READY; после каждого
  исключения `PRINT 2+2` даёт 4. 4580 проверок стенда, 326456690 тактов,
  160222 DMA-слова. Исходный образ диска не изменён.
- Проверка изоляции профилей: 8 тестов; SHA-256 всех 170 контрольных
  исходников и выходов MMU-less/HC1200 совпадают с исходной базой.

Воспроизведение RTL:

```sh
python3 tools/test_mmu.py --out build/mmu-trap-unit-new
python3 tools/test_mmu_fpp.py --out build/mmu-trap-fpp-new
python3 tools/test_mmu_basic_simh.py --out build/mmu-basic-image-new
python3 tools/test_mmu_basic.py --out build/mmu-basic-rtl-new \
  --image build/mmu-basic-image-new/fb-to-xm.dsk
```

Каталоги с образами и полными RTL-прогонами должны быть новыми.
## Синтез и физическая плата

Сборка `mmu-trap-modes-08`, LCMXO2-7000HC-4TG144C, генератор 12 МГц,
система **24 МГц**: 5651 LUT / 6864, 1407 FF, 25 EBR / 26;
TRACE Fmax **24.754 МГц**, setup/hold и внешние ограничения SRAM проходят.
Относительно прежней сборки: +64 LUT, число FF/EBR не изменилось.

JED: `synthesis/impl1/mmu-trap-modes-08_impl1.jed`, checksum `1070`, SHA-256
`affea6f15e0d516dd9e10f858a95658d2309e31282ea950286f586187ecf806c`.
Входы и отчёты сверены по SHA-256; `synthesis/source.tgz` сохраняет исходники.

**Записано во FLASH и проверено на плате 2026-09-27.** Programmer подтвердил
Erase/Program/Verify. Свежий старт загрузил DM0:RT11XM, 22-битная адресация,
2048KB, MEMTOP=10000000₈. B81FPU/B81FPD прошли по 29 сравнений, B81DBL —
double-тест. В обоих BASIC `PRINT 1/0`, `PRINT SQR(-1)` и
`PRINT 1E30*1E30` выдают ожидаемую ошибку и возвращают READY; последующий
`PRINT 2+2` даёт 4, BYE возвращает в XM. Логи — `hardware/fixed-08/`.
Плата оставлена в XM, picocom возобновлён.

Попытка записи сборки 07 была остановлена до Programmer: параллельный
vendor-тест обновил время генерируемого ROM, из-за чего Diamond повторил
сборку при экспорте, изменив отчёты относительно зафиксированных хэшей.
Сборка 08 прошла синтез и экспорт последовательно; перед записью все
хэши совпали. Проверка согласованности не отключалась.
