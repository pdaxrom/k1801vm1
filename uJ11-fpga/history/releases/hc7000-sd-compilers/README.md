# RT-11 XM с BASIC, Pascal и FORTRAN на общей SD HC7000

> Историческая запись: `releases/hc7000-sd-compilers/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../README.md).


29 сентября 2026 года к SD с BSD, RSX и RT-11 V4 добавлены пять разделов
из `lsi11/disks/rt11v5.3`. Системный диск загружает RT-11XM V05.03.
Для запуска после RESET отменить таймер любой клавишей, кроме Enter,
выбрать **2 (RH11/HK)**, затем **0**. По таймеру и Enter загружается BSD RL0.

| Раздел SD | Назначение в RT-11 | Содержимое | Начальный LBA | Секторов |
|---|---|---|---:|---:|
| RH0 | DM0:, SY: | system.dsk, RT-11 XM | 1679360 | 53790 |
| RH1 | DM1:, VOL: | storage.dsk, рабочий диск | 1734656 | 53790 |
| RK1 | RK1:, BAS: | basic.dsk | 1789952 | 4872 |
| RK2 | RK2:, PAS: | pascal.dsk | 1796096 | 4872 |
| RK3 | RK3:, FOR: | fortran.dsk | 1802240 | 4872 |

RK0 занят RT-11 V4 и сохранён. Остальные прежние разделы — RL0/RL1, XP0,
RQ0/RQ1 — также сохранены. Полная разметка из 11 разделов и хеши находятся
в [card.json](card.json). `bootable` установлен только у RL0; ручной выбор
RH0 не требует этого флага. При первоначальной записи этих разделов
прошивка FPGA и SERV не изменялась. Последующее исправление идентификации
UNIBUS и переноса карты DMA в SERV находится в отдельном релизе
[7AE8](../hc7000-serv-unibus/README.md); штатный Pascal с RK2 уже проходит
полный цикл компиляции, линковки и исполнения в RTL этой сборки и на плате.
7AE8 установлена и проверена 29 сентября; аппаратный прогон BASIC,
Pascal XM с LIBEIS и FORTRAN с FORLIB завершён успешно без патчей драйверов.

## Назначения дисков и подготовка

В `STARTX.COM`, `STARTF.COM`, `STARTS.COM` системного диска:

```
ASSIGN DM1: VOL:
ASSIGN RK1: BAS:
ASSIGN RK2: PAS:
ASSIGN RK3: FOR:
```

`DM1: VOL:` уже соответствовало выбранной разметке. Три номера RK
изменены в каждом startup-файле: всего девять байтов системного образа.
Загрузочные блоки, каталог и остальные файлы сохранены. Образы RK05
дополнены нулями до 4872 секторов; исходные данные не менялись.

Подготовить свежие копии, находясь в `uJ11-fpga`:

```
python3 tools/build_sd_compilers.py --out build/compiler-media-new
```

Инструмент пишет только в новый каталог, не обращается к физической SD
и проверяет неизменность исходников. [Манифест](media/manifest.json)
содержит исходные и итоговые SHA-256, а `media/START*.COM` — итоговые
startup-файлы. Полные образы находятся в
`build/sd-rt11-compilers-20260929/media/`.

При физической записи сохранены резервные копии прежних секторов,
пять новых образов прочитаны обратно с проверкой SHA-256, хеши всех шести
существовавших разделов до и после совпали. Разметка опубликована после
проверки данных: сначала резервная копия, затем основная. Обе копии
согласованы, sequence 6 → 11, меню CRC16 `5bb3` и остальные резервные
секторы неизменны.

Резервные копии `original-prefix.img.gz` и `original-new*-range.img.gz`:

* Linux: `/home/sash/Work/FPGA/uj11-serv-compact-20260928/uJ11-fpga/build/sd-rt11-compilers-20260929/card/`;
* локально: `uJ11-fpga/build/sd-rt11-compilers-20260929/card/`.

`append-compilers.py` — сохранённый сценарий этой записи, привязанный
к проверенному состоянию карты с шестью разделами и diskseq 104.
Повторно применять его к уже изменённой карте не нужно.

## Проверка программ без FPP

Эталонный прогон на частных копиях дисков: SIMH 3.12-3, CPU 11/70,
2 MiB, NOFPP. У модели 11/73 этой версии SIMH нельзя отключить FPP.
XM загрузилась с DM0, показала 22-битную адресацию, прочитала каталоги
дисков с новыми назначениями. [Журнал](simh/uart.txt) и
[результат](simh/session.json).

Проверено:

* `RUN BAS:BASIC`, выбор `A`, `PRINT 2+3` → `5`, `BYE`;
* Pascal XM скомпилировал `VOL:ADDER.PAS`, LINK собрал его с `PAS:LIBEIS`,
  программа для ввода `2 3` выдала `2.000000E+00 3.000000E+00 5.000000E+00`;
* FORTRAN IV V02.1-1 скомпилировал тест, LINK собрал с `FOR:FORLIB`,
  программа вывела строку через логическое устройство 7 и завершилась.

Для Pascal без FPP использовать `LIBEIS`, а не `LIBFPP`. Проверенная
последовательность (`*` — приглашение программы, `Ctrl-C` нажимается):

```
.RUN PAS:XM
*VOL:CTPAS,VOL:CTPAS=VOL:ADDER
.R LINK
*VOL:CTPAS,VOL:CTPAS=VOL:CTPAS,PAS:LIBEIS
*Ctrl-C
.RUN VOL:CTPAS
2 3
```

Компилятор Pascal после компиляции возвращается в монитор `.`.
В первой попытке сценарий ошибочно ждал ещё одно `*`; исходник был
скомпилирован без ошибок. Этот журнал сохранён в `attempt-pascal-prompt/`.

FORTRAN для терминального вывода проверен с `WRITE(7,10)`. Первая проба
с `WRITE(6,10)` не дала ответа на терминале и завершена по таймауту
сценария; журнал — `attempt-fortran-unit6/`. Первый символ FORMAT
используется для управления строкой: в эталонной пробе `'FORTRAN OK'`
получилось `ORTRAN OK`, поэтому для полной строки нужен ведущий пробел:

```
      PROGRAM CTFORT
      WRITE(7,10)
   10 FORMAT(' FORTRAN OK')
      END
```

```
.RUN FOR:FORTRA
*VOL:CTFORT,VOL:CTFORT=VOL:CTFORT
*Ctrl-C
.R LINK
*VOL:CTFORT,VOL:CTFORT=VOL:CTFORT,FOR:FORLIB
*Ctrl-C
.RUN VOL:CTFORT
```

## Аппаратная проверка и ограничение RKX

На HC7000 с установленной JED `9DF6` загрузка RH0 прошла: RT-11XM V05.03,
DM0, 2 MiB, 22-битная адресация. Меню сохранило все контроллеры и Default RL0.
Каталоги VOL, BAS, PAS, FOR прочитаны с ожидаемым содержимым.
[Журнал загрузки](hardware-boot/uart.txt).

BASIC вычислил `2+3 = 5`. FORTRAN с RK3 скомпилировал тест на VOL, LINK
собрал его с FOR:FORLIB, получены `FORTRAN OK` и штатный STOP.
На этой прежней прошивке прямой запуск `RUN PAS:XM` с RK2 завершается
`?MON-F-Ovly err 001070`.
Копия того же файла на RH1 (`COPY PAS:XM.SAV VOL:PTEMP.SAV`) запускается,
компилирует ADDER, линкуется с PAS:LIBEIS и правильно складывает `2 3`.
Это диагностическая копия, а не исправление прямого запуска с RK2.
Альтернативный `RUN PAS:SJ` сообщил `Insufficient memory` в нижней памяти.
[Журнал диагностики](hardware-diagnostics/uart.txt).

В исходном DEC `RK.MAC` перед записью RKWC/RKCS выполняется проверка:

```
MOV #3,-(SP)                 ; разрешить два старших бита адреса RK11
MOV @#54,R1
BIT #100,370(R1)             ; признак QBUS$ в CONFG2 монитора
BEQ 47$
CLR (SP)                    ; для Q-bus разрешено только 16 бит
47$: BIC (SP)+,R2
BNE HERROR                  ; ошибка до запуска контроллера
```

SERV уже формирует 18-битный адрес из RKBA и RKCS[5:4], см.
`firmware/storage/rk05.c`. В отказавшем случае драйвер не отправляет
контроллеру команду чтения оверлея; расширение DMA в SERV не устраняет
эту программную проверку.

После уточнения пользователя выполнен отдельный полный прогон SIMH
**11/40 + FIS + MMU, без FPP**, 248 KiB доступной памяти. Эта версия SIMH
не допускает FIS у модели 11/70; у 11/40 FPP отсутствует по модели.
BASIC, компиляция/линковка/исполнение Pascal и FORTRAN прошли.
[Итоговый FIS-прогон](simh-fis/uart.txt), [результат](simh-fis/session.json).
Отсутствие FPP не следует путать со строкой `FPU support` в списке
возможностей собранного монитора.

Отдельно на том же SIMH 11/40 + FIS выставлен только QBUS$ в CONFG2
работающей RT-11: `000434 → 000534`. После этого `RUN PAS:XM` получил
тот же `Ovly err 001070`. [Диагностический журнал](simh-qbus-diagnosis/uart.txt).
Это искусственная проверка условия драйвера, не эмуляция J11 с FIS.
Последовавшая экспериментальная работа с SIPP завершилась ошибкой сценария:
после Ctrl-Y не был передан Return. Этот сеанс не считается проверкой
исправленного драйвера; использованные копии дисков не устанавливались.

Предложена замена одного слова RKX.SYS по файловому смещению 001214
(`005016`, CLR (SP), на `000240`, NOP), сохраняющая проверку 18-битной
границы. После возражения пользователя изменение отложено: **на физической
SD RKX не менялся**, воспроизводимый сборщик также оставлен без этой правки.
В последующей сборке 7AE8 прямой запуск PAS:XM исправлен на стороне SERV
и проверен в RTL и на физической плате; RKX остаётся исходным.

Дополнительная проверка конфигураций показала различие исходного стенда:
`lsi11/disks/rt11v5.3/boot.ini` задаёт SIMH 11/94, `boot84.ini` — 11/84.
Это системы с UNIBUS, тогда как прошивка HC7000 9DF6 определялась как 11/73/Q-bus.
Наши успешные прогоны компиляторов на 11/70 и 11/40 также не воспроизводят
это различие шин. UNIBUS map уже существовал и в `lsi11/ubmap.c`, и в аппаратном блоке
HC7000 `uj11_mmu_ubmap.v`. Прежний вывод об отсутствии карты был ошибкой
поиска только в каталоге CPU. Предложение патчить RKX было преждевременным:
ошибка идентификации шин исправляется в SERV; туда же перенесены таблица
карты и трансляция DMA. Сборка и последующая проверка этого исправления
описаны в [hc7000-serv-unibus](../hc7000-serv-unibus/README.md).

SHOW CONFIGURATION на плате также напечатал `Floating Point Microcode`
и `60 Cycle System Clock`. Эти строки сохранены в журнале; они не являются
подтверждением включения FPP или измерением частоты таймера. Профиль
установленной JED собран с FPP off; прошивка в этом сеансе не менялась.

По завершении первоначальной проверки плата была оставлена на приглашении
RT-11, UART освобождён. На VOL сохранены
диагностическая копия PTEMP.SAV и тесты CTPAS/CTFORT; исходные файлы ADDER
не заменены. Результат этого аппаратного сеанса с 9DF6 частичный из-за
прямого запуска Pascal XM с RK2. Текущий статус исправления и установки
7AE8 указан в отдельном релизе выше.
