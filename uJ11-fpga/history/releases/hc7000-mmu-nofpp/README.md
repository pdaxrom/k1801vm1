# HC7000 MMU без FPP

> Историческая запись: `releases/hc7000-mmu-nofpp/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../README.md).


Временный вариант для расширения SERV IOP. Сборка `CPU=mmu FPP=off`
сохраняет MMU, микрокодный ODT, 2 МиБ SRAM и системную частоту 24 МГц.
FP11-инструкции вызывают reserved-instruction trap по вектору `010`;
ODT `F` сообщает `?`. Программный эмулятор FP11 не добавлен.
HC1200/mmuless не изменяется, `FPP=microcode` остаётся вариантом по умолчанию.

## Реализация и ресурсы

Diamond MAP/PAR/TRACE `mmu-nofpp-01`: 3236/6864 LUT4, 1069 FF, 18/26 EBR;
Fmax 26.183 МГц при требуемых 24 МГц, включая проверку внешних таймингов SRAM.
Относительно выпущенного `mmu-trap-modes-08` освобождены 2415 LUT и 7 EBR.
Третий банк микрокода и EBR FP-состояния исключены, арифметика FPP удаляется
синтезатором по константе выбранного ROM.

Повторная сборка `FPP=microcode`, `mmu-fpp-switch-01`: 5682 LUT, 1407 FF,
25 EBR, Fmax 24.915 МГц; gate 24 МГц также проходит. Её отчёты находятся
в `fpp-enabled-synthesis/`, отчёты отключённого варианта — в `synthesis/`.

Экспортирован `synthesis/impl1/mmu-nofpp-01_impl1.jed`, checksum `D989`, SHA-256:

```text
c24727da279dd37a1de430339a7a0d27d4ccb11db522bc92487ef60857bfd45a
```

**2026-09-27 JED записан во FLASH HC7000, Erase/Program/Verify прошли.**
После переконфигурации загрузился RT-11XM V05.03, доступны 2 МиБ SRAM,
22-битная адресация MMU и каталог SD. Образ SD не переписывался.
Журналы находятся в `hardware/flash/`.

Программа `FPCHK.SAV`, собранная DEC MACRO/LINK и загруженная через HG
без записи на SD, выполнила `SETF` и получила `?MON-F-Trap to 10 001010`.
Строка после FP-инструкции не исполнилась; RT-11 вернулся к приглашению,
последующий `SHOW MEMORY` завершился штатно. Это прямая аппаратная проверка
отсутствия FPP; исходник и листинг сохранены в `hardware/probe-source/`,
сеанс — в `hardware/instruction-probe/`.

`SHOW CONFIGURATION` этой RT-11 всё ещё выводит `Floating Point Microcode`
и `Floating Instruction Set (FIS)`. Эти строки не подтверждают наличие
FPP в отключённой конфигурации. Причина строки о микрокодном FPP установлена
по `RESORC.SAV`: после `MFPT=5` утилита безусловно устанавливает признак
микрокодного FPP. Бит 8 (`000400`) в `MAINT` только выбирает надпись об
ускорителе FPA вместо микрокода. У нас `MAINT=000031`, этот бит уже равен
нулю, а тип CPU остаётся J11/11-73A. Утилита не предусматривает такой J11
с выключенным микрокодным FPP; на этом пути она не проверяет бит HWFPU$
монитора. Разбор сохранён в `validation/identification/RESORC-analysis.txt`.
Причина отдельной строки FIS этим разбором не установлена.
Идентификация CPU и `RESORC.SAV` не менялись.
После проверки HG выгружен, HG-демон остановлен, JTAGENB отпущен с проверкой
высокого уровня, прежний UART-терминал продолжен.

Отчёты содержат исходные
пути Linux-стенда; они сохранены как свидетельство сборки. Повторная сборка
выполняется командами из [описания профиля](../../../docs/hc7000-mmu.md).

## Проверки

- CPU без FPP: 120 проверок, включая vector `010`, кадр PC/PSW, отсутствие
  побочного изменения операнда, возврат `RTI`, MMU K/S/U, ODT и IRQ.
- Логическая ROM и модели EBR Lattice: адресация всех трёх логических банков,
  включая постоянное значение отсутствующего третьего банка, и удержание CE.
- 786432 случая трансляции MMU и 3375 проверок транзакций.
- Обратное включение: 66 проверок CPU и 263704 проверки арифметического блока FP.
- `make BOARD=hc7000-lcd-sram CPU=mmu FPP=off test` проходит полностью,
  включая неизменность исходников HC1200 и 60949 проверок SERV/SD/DMA.
- Холодный запуск опубликованного RT-11XM SD-комплекта без изменения образа:
  3355 проверок, 227840185 тактов, 113818 слов DMA и 6783196 выборок через MMU.
  Проверены запуск XM, каталог и `SHOW MEMORY`. Это проверка RTL, не платы.
- Физическая плата: FLASH Verify, новая загрузка XM, `SHOW MEMORY`, чтение
  каталога SD и прямой `SETF` с ожидаемой ловушкой `010`.

Логи и манифесты находятся в `validation/`. Статический текст `HELLO.TXT`
существующего SD-комплекта упоминает FPP независимо от конфигурации FPGA;
он не является результатом определения аппаратных возможностей.
