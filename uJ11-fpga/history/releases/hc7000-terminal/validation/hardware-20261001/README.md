# Аппаратная установка терминала PAL, JED 3428

> Историческая запись: `releases/hc7000-terminal/validation/hardware-20261001/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../../../README.md).


2026-10-01. HC7000 / LCMXO2-7000HC-4TG144C, генератор 12 МГц,
SRAM IS61WV102416BLL-10T. CPU 50 МГц, PAL 64 МГц.
Установлена финальная сборка `terminal-pal-50-06` с MMU, SERV storage,
FPP off / FIS, diagnostics и зеркалом консоли PAL 640×240 / 80×30.

SHA-256 JED:
`2c1691d770ec3e3508abbc7a203cd9ce72c892f2c433ff5e83337b599434a5e1`.
Перед записью проверены все входные файлы manifest, отчёты синтеза/размещения,
прохождение временных ограничений и SHA-256 JED.

До прошивки работало автономное PAL-демо. Команда `Q` остановила его в ODT,
PC `020522`; операций с SD до прошивки не выполнялось.
`hgfsd --jtag-only` освободил JTAGENB и подтвердил высокий уровень.
Diamond 3.14 выполнил **FLASH Erase,Program,Verify**, `Operation: successful`,
без ошибок, за 58 секунд. Отчёты — в `session-02/programmer*.log`.

После прошивки получено новое меню SD, обнаружены RK/RH/XP/RQ/RL.
Таймер автозагрузки отменён, выбраны RL0 и `rl(0,0)rlunix`.
2.9BSD определила `mem = 1864384`, подключила XP0 и RL0, затем через Ctrl+D
перешла в multiuser, смонтировала `/usr` на `/dev/xp0h` и выполнила вход root.
На плате проверены `stty nl0 cr0`, `ls /usr`, `cat /etc/fstab` и `sync`.
Плата оставлена работающей на приглашении root `#`.

Пользователь подтвердил PAL на стадии меню / `70Boot`: **«Текст виден нормально»**.
Текст ядра и команд проверен через UART. Аналоговые уровни не измерялись;
отдельного подтверждения изображения позднего сеанса root этот прогон не содержит.
Терминалы DZ оставлены в BSD для будущего подключения; штатные сообщения
`init: /dev/tty00..tty07: cannot open` не препятствуют входу на консоли.

Прогон сохраняет промежуточные затруднения, а не скрывает их:

- `session-01`: пустая строка ODT не возвращает приглашение, поэтому первый
  предохранительный тест остановился **до записи FPGA**. Проверка заменена
  свежим чтением PC; оно вернуло `020522` и приглашение ODT.
- `session-02`: запись и загрузка ядра успешны. Старый дескриптор UART на Linux
  вернул EIO при попытке отправить Ctrl+D; восстановление termios также вернуло EIO.
- `session-03`: UART переоткрыт, включён ISTRIP для программного бита чётности BSD.
  Без повторной прошивки, RESET или отключения питания продолжена та же загрузка;
  multiuser, вход root и команды прошли. Итог этого сеанса — `passed: true`.

UART после теста закрыт и свободен. Старому picocom отправлен SIGCONT;
процесс остался фоновой остановленной задачей уже без UART-дескриптора.
Для дальнейшей работы его нужно вернуть в терминал через `fg` и открыть
picocom заново, если прежний экземпляр завершится. BSD при этом продолжает работать.
Для приёма BSD необходим ISTRIP на UART Linux (`stty -F /dev/ttyUSB1 istrip`).

`uart.bin` сохраняет исходные байты каждого сеанса; `uart.txt` — читаемая копия
с удалённым старшим битом чётности, CR, DEL-заполнением и NUL.
`result.json` объединяет успешную запись и последующую проверку BSD.
Сценарии и использованные помощники сохранены рядом; все файлы включены
в общий `SHA256SUMS` checkpoint.
