# Запуск PAL-демо на HC7000, 2026-09-30

> Историческая запись: `releases/hc7000-pal-fast/validation/hardware-20260930/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../../../README.md).


Стенд `sash@192.168.1.108`, UART `/dev/ttyUSB1`, 115200 8N1.
Перед прошивкой подтверждено приглашение простаивающей RT-11. Picocom
временно приостанавливался; после запуска демо он возобновлён и остаётся
единственным владельцем UART. SD не переписывалась.

## Результат

- JED **2AAE** записана и проверена Lattice Programmer; JTAG ID соответствует
  LCMXO2-7000HC. SHA-256 JED и все входы синтеза проверены перед операцией.
- Автозагрузка RL0 отменена; меню показало RK/RH/XP/RQ/RL. Пользователь
  короткой кнопкой остановил CPU в ODT, PC `102326`, PSW `000004`.
- PALDEM: **3798 байт**, адрес/старт **020000**. Каждое записанное слово
  проверено; затем выполнено отдельное полное обратное чтение.
  SHA-256 совпал с исходным бинарником:
  `338ad523a4f12a734707721bb8f011e3c2431783786dc0e3ae40db038f144573`.
- Получена строка `PAL demo: 1=640x200 2=320x200 S=scroll P=page B=bars Q=halt`.
  Программа оставлена работающей в **640×200, 4 bpp, текст 80×25**.

Это подтверждает запуск программы и завершение применения видеоконфигурации.
После повторного запуска пользователь сообщил «работает», подтвердив работу
изображения. Захват и измерения аналогового сигнала не выполнялись.
Это не аппаратный замер скорости ОС или испытание дисковой нагрузки с PAL.

Клавиши в picocom, без Enter: `1` — 640×200, `2` — 320×200,
`S` — прокрутка, `P` — другая страница, `B` — цветовая таблица,
`Q` — выключить изображение и выполнить HALT. Длинный RESET возвращает
обычную загрузку с SD; демо само после reset не запускается.

## Ограничение ODT в 2AAE

После входа кнопкой на байтовой инструкции ODT наследует `byte_instruction`:
`byte_operation` в CPU не исключает `console_active`. Это влияет на переносы
при разборе восьмеричных чисел. Например, `P 20000` возвращал `?`, а запросы
с меньшими числами могли отображать другой физический адрес.
Замедление UART до 20 мс/символ не меняло результат.

Диагностический RTL-прогон с сохранённым IR=`TSTB` воспроизвёл ошибку;
тот же стенд с IR=`HALT` обработал `P 20000` и `P 17777572` правильно.
Для запуска использован обход **только в остановленном свежем boot menu**:
по физическому адресу 0 записан HALT, PC установлен в 0, выполнено `C`.
CPU вернулся в ODT с PC=2, PSW=000340. После этого чтение MMR0 подтвердило
выключенную MMU, загрузка и полное чтение демо прошли.

Ошибка не исправлена в установленной 2AAE. Следующая правка CPU должна
исключить байтовую ширину гостевой инструкции из операций консоли;
нужна регрессия входа кнопкой после байтовой инструкции, а не только после HALT.
Этот обход нельзя применять к работающей ОС: он изменяет её память и PC.
