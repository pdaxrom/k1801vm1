# HC7000 MMU: база с общим микрокодом FPP

> Историческая запись: `releases/hc7000-mmu-microcoded/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../README.md).


Эта исходная база сохраняется для воспроизведения сбоя BASIC.
На плате теперь [исправление режима TRAP](../hc7000-mmu-trap-fix/README.md):
деление на ноль возвращает READY, проверки single/double прошли.

Экспериментальная конфигурация на основе `ff11711`, ветка `uJ11-hc7000`.
LCMXO2-7000HC-4TG144C, hardware-lcd, SRAM IS61WV102416BLL-10T 2 МиБ.
Генератор платы 12 МГц, система 24 МГц. **Прошита и проверена на физической
плате 2026-09-27.** На установленной SD загрузка переключена с FB на XM;
подтверждены холодный старт, 22-битная адресация и определение 2 МиБ.
Обнаружен открытый сбой возврата из обработчика ошибки BASIC, описанный ниже.

MMU K/S/U, 18/22 бита, I/D, PAR/PDR/MMR0–3; микрокодные ODT и полный
FPP F/D/I/L. VM2 HALT/USER ABI отсутствует. RK611/SERV сохраняется отдельным
устройством, DMA расширен до 18 бит. Выбор: `CPU=mmuless|mmu`; HC1200
остаётся `mmuless`. См. [описание и сборку](../../../docs/hc7000-mmu.md).

## Синтез и JED

5587 LUT4 / 6864, 1407 FF, 25 EBR / 26. Microstore 3072×54,
1883 слова занято. Diamond 3.14 MAP/PAR/TRACE: полностью разведено,
24 МГц проходят, Fmax **24.732 МГц**, SRAM setup/hold/output constraints
проверены. Все входы и отчёты сверены по SHA-256.

JED: mmu-fpp-final-06_impl1.jed (`releases/hc7000-mmu-microcoded/synthesis/impl1/mmu-fpp-final-06_impl1.jed`).
SHA-256: `58b4358bb77d820eb95e7b4c6dbd931d2a9d6fffd9731d712c81285e8bce1d01`.
JEDEC checksum: `3C19`. Этот JED записан во FLASH FPGA с проверкой Programmer.

`synthesis/source.tgz` сохраняет входы синтеза, микрокод и тесты для
воспроизведения в этом репозитории с соответствующими инструментами.
Проект `.ldf` сохраняет абсолютные пути Linux-окружения; для другой машины
следует сгенерировать новый проект через `make ... CPU=mmu synthesis`.
Файлы `checksums.json` и `synthesis/inputs.json` фиксируют артефакты и входы.

## Проверки

- `validation/cpu-vendor`: модели Diamond DP8KC; все 3072 слова ROM,
  786432 трансляции, 3375 проверок транзакций, 56 проверок CPU/ODT,
  включая User I/D и FPP restart после MMU abort; 263704 проверки wide datapath.
- `validation/fpp`: реальные команды CPU, 444420 случаев и 17601544
  сравнений с общим адаптированным DCJ11 oracle. Округление, границы,
  исключения, все адресации и инъекции ошибок памяти; ограничения и
  ручные DEC-ожидания эталона задокументированы в его исходниках.
- `validation/bus`, `validation/disk`: SRAM/I/O decode; SERV, SD по выводам,
  60949 проверок, 55405 конкурирующих CPU-транзакций, 3855 DMA-слов.
- `validation/xm`: CPU/SERV/SD/SRAM/UART; пользовательский RT-11XM,
  определение 2 МиБ, копирование RT11XM.SYS на VM: и BINCOM без различий.
  Образ SD открывается только для чтения. 4879 проверок, 238243 DMA-слова.
- `validation/mmuless-test.log`, `mmuless-unchanged.json`: полный прежний
  `make test CPU=mmuless` прошёл; 170 исходных и генерируемых файлов
  HC1200/HC7000 не изменились.

## Физическая плата и SD

Журналы UART, команды, результаты и Programmer сохранены в `hardware/`:

- `preflight`: исходный FB; на SD уже находились RT11XM.SYS и DMX.SYS.
  STARTF.COM и STARTX.COM содержат `SET TT SCOPE,NOCRLF` и `SET SL ON`.
- `flash`: FLASH Erase/Program/Verify и первый запуск FB с MMU и 2048KB.
- `xm-trial`: `BOOT RT11XM`, `SHOW CONFIGURATION`, `SHOW MEMORY`;
  копирование RT11XM.SYS в VM:MMUTST.SYS и `DIFFERENCES/BINARY` без различий.
  VM: — RAM-диск; пользовательские файлы SD не перезаписывались.
- `xm-persistent`: `COPY/BOOT SY:RT11XM.SYS SY:`, затем `BOOT SY:`;
  загрузка `DM0:RT11XM` из обновлённых загрузочных блоков SD.
- `xm-cold`: повторная конфигурация тем же JED, свежий старт XM,
  `22 bit addressing is on`, 2048KB, MEMTOP=10000000₈.
- `xm-basic`: B81FPU/B81TST — 29 сравнений, 0 ошибок. Следующий
  `PRINT 1/0` печатает `?DIVISION BY ZERO`, затем CPU входит в ODT вместо
  READY. **Весь этот сеанс отмечен как неуспешный**, обработка FP-ошибок
  на плате не квалифицирована.
- `xm-inspect`, `xm-inspect-memory`: состояние останова после ошибки:
  PC=116452₈, PSW=000344₈, KSP=154750₈; FPS=003404₈,
  FEC=000004₈, FEA=006322₈; MMR0/MMR3=0, MMR2=116450₈.
  По адресу 116450₈ находится HALT, за ним BR обратно на HALT.
  Причина остановки пока не установлена; это не доказанный дефект делителя.
- `xm-double-02`: после восстановления B81FPD/B81TST — 29 сравнений,
  0 ошибок; B81DBL — `CP81 DOUBLE PASS`; BYE и SHOW CONFIGURATION прошли.
  Ошибочные FP-операции в этом сеансе не повторялись.

Контрольный запуск в SIMH 3.12-3 с CPU **11/73**, 2 МиБ, 50 Гц прошёл
на отдельной копии исходного FB-диска `lsi11-fpga/images/rt11v503.dsk`.
Сначала проверены B81FPU и B81FPD в FB, затем выполнены
`COPY/BOOT SY:RT11XM.SYS SY:` и `BOOT SY:`. Новый процесс SIMH загрузил
XM из изменённых загрузочных блоков; в нём повторены оба BASIC.
В каждом из четырёх сеансов: 29 сравнений без ошибок, деление на ноль
(включая повторное), отрицательный SQR и overflow возвращают READY,
после каждого исключения `PRINT 2+2` даёт 4. Оба сеанса double прошли
также B81DBL. **Останов на делении на ноль в SIMH 11/73 не воспроизводится.**

`SHOW CONFIGURATION` подтверждает `PDP 11/73A Processor`, 2048KB,
`Floating Point Microcode`, EIS, MMU и 50 Cycle System Clock.
SIMH дополнительно сообщает Cache Memory; в XM также загружены DU/MU,
отсутствующие на плате. Контроллер RK611 (`HK`) явно включён после выбора
11/73, который по умолчанию выключает его. Это не побайтовый клон SD платы.
Исходный FB-образ и файлы FB/XM/DM/DMX/STARTF/STARTX сохранены неизменными.
Программы BASIC совпадают с опубликованными SAV; BAS переведены в CRLF.

Воспроизведение: `python3 tools/test_mmu_basic_simh.py --out build/xm-basic-new`.
Сценарий требует новый каталог. Логи, boot blocks, конфигурация и хэши:
`validation/basic-xm-1173/`. Полученный рабочий диск остаётся в
`build/xm-basic-1173-01/fb-to-xm.dsk`. Более ранний контроль 11/70
сохранён в `validation/basic-xm-reference/` и также возвращал READY.

Плата оставлена в XM, picocom возобновлён. FB/SJ и оба startup-файла на SD
сохранены. Для возврата загрузочных блоков FB из RT-11:
`COPY/BOOT SY:RT11FB.SYS SY:`. Это не меняет прошивку FPGA.

Текущий FPP имеет отдельный арифметический datapath, которым управляет
общий микрокод uJ11. Собственный микросеквенсор FPU и более узкий ROM
рассматриваются как следующий вариант внутри HC7000. Эта база нужна для
сравнения точности, задержек, LUT/EBR и timing; отдельный FPU пока не добавлен.

Не заявляется полная совместимость со всеми особенностями DCJ11:
остаются найденный сбой BASIC, стековые ограничения, редкие сочетания trace/IRQ.
