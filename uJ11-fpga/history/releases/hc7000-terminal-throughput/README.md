# HC7000: полный непрерывный вывод терминала, JED C3DA

> Историческая запись: `releases/hc7000-terminal-throughput/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../README.md).


2026-10-01. Сборка `terminal-throughput-50-03`, MMU / SERV storage / FPP off /
FIS / diagnostics / PAL / terminal. CPU 50 МГц, PAL 64 МГц от генератора 12 МГц.
LCMXO2-7000HC-4TG144C, SRAM IS61WV102416BLL-10T; PAL 640×240 / 80×30.
Установлена на физическую плату: Flash Erase/Program/Verify прошли без ошибок.

После JED 54D2 пользователь сообщил, что числа блоков и даты каталога `DIR`
появляются только после остановки вывода. CR/TAB помечали путь курсора для
перерисовки; физический порядок рисования также откладывал текущую строку.
Старые тесты давали дополнительное время для дорисовки и пропускали этот дефект.

Теперь изменяются только нужные ячейки и действительно нарисованный курсор.
Текущая строка имеет приоритет и дорисовывается перед чтением следующего байта.
Курсор рисуется один раз после опустошения очереди/dirty. Маски шрифта заранее
развёрнуты в 3072 байта SRAM `0x1E6580..0x1E717F`, внутри прежнего резерва.
После обхода дисковых контроллеров SERV выполняет до восьми шагов терминала.
Каждый пиксельный ряд проверяет события I/O, полный обход busy-контроллеров
выполняется в начале порции и после события. Дисковая команда прерывает порцию.
Физический UART и очередь сохраняют каждый байт; при заполнении вывод ждёт.

## Ресурсы и память

RTL аппаратного тракта не менялся относительно 54D2. Размещение финальной
прошивки повторно прошло все ограничения CPU 50 / PAL 64 МГц, SRAM и CDC.

| Показатель | Результат |
|---|---:|
| LUT | **5897 / 6864**, свободно 967 |
| FF | 2020 / 7209 |
| EBR / PLL | 26 / 26; 2 / 2 |
| Приращение к 54D2 | **0 LUT, 0 FF, 0 EBR** |
| Fmax CPU / PAL | 50,633 / 64,927 МГц |
| Код/константы SERV | 15067 байт |
| BSS | 1072 байта |
| Запас перед стеком / cold bank | 1652 / 512 байт |
| Резерв стека | 640 байт |

Кеш шрифта не увеличивает резерв SRAM 112 КиБ и не уменьшает гостевые
1936 КиБ. Адреса холодного банка в startup загружаются без GP-релаксации:
старый вариант мог ошибочно выбирать обращение за пределами ±2 КиБ при
изменении размера кода. Оба варианта SERV без терминала сохранили двоичные
прошивки побайтно: PAL 11219 байт, без PAL 11211 байт.

## Проверки

- Хостовый тест воспроизводит пропуск числа блоков на старом коде. Новый код
  проверяет строку с двумя колонками, TAB, блоками и датой после каждого LF,
  без дополнительной паузы. Сохранены проверки цветов, VT52, графики,
  cursor/dirty, порядка прокрутки и автоматического переноса.
- Реальный SERV / UART / PAL / SRAM: **157928 проверок, 2187 байт провода**,
  35 строк каталога. Все 80×8 пикселей предыдущей строки сравниваются с
  независимой маской шрифта при чтении CR реальным SERV, пока поток продолжается.
  Проверяются очистка, поворот кольца, 12 отдельных сдвигов, ≤20 мс ACK,
  гостевой RESET и отсутствие underrun. Стек **240 / 640 байт**.
- Тот же RTL тест на прошивке 54D2 завершился ожидаемой ошибкой
  `incomplete continuous DIR` в колонке числа блоков.
- DMA / резерв: **7236 проверок**, восстановление после NXM, исходный SD-образ
  не изменён. RL NOP: ожидание сдвига 22097 тактов (0,442 мс), очистка строки
  27383 (0,548 мс), обычная проверка 29637 (0,593 мс). Стек **336 / 640 байт**.
- Production HC1200 прошла: RTL/EBR, три ROM, BASIC и JED сохранены.
- PAL без терминала использует неизменённый RTL относительно 54D2;
  сохранён прежний прошедший тест 13 кадров / 11507200 пикселей.

В RTL поток из 35 строк занимает **51160906 тактов / 1,023218 с** вместо
143232653 / 2,864653 с в корректном промежуточном варианте до оптимизации
порций: **2,8 раза быстрее**. Это сравнение с промежуточным вариантом `-02`,
а не со старой 54D2, которая не проходит проверку полной строки в потоке.
Начальный framebuffer побайтно совпал с проверенным изображением 54D2.

На плате RT-11 XM V05.03 загрузилась с RH0. Полный DIR занимает **7,416 с**
вместо **16,033 с** на 54D2: **в 2,16 раза быстрее**. Второй запуск повторил
результат; каждый вывод побайтно совпал со старым: 214 файлов, 5346 блоков,
48310 свободных блоков. Замеры включают одинаковые задержки ввода команды
и ожидания после приглашения. CPU остаётся на 50 МГц, ресурсы не увеличились.
UART освобождён, плата оставлена на приглашении RT-11.
Визуальное подтверждение полноты полей на физическом PAL пока ожидается.
[Логи прошивки и аппаратного сравнения](validation/hardware-20261001/README.md).
Повторные загрузки BSD / RSX / RT-11 V4 на этой версии ещё не запускались.
