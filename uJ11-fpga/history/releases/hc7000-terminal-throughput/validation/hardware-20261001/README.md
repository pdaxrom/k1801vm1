# HC7000: установка C3DA и аппаратное сравнение DIR

> Историческая запись: `releases/hc7000-terminal-throughput/validation/hardware-20261001/README.md`, Git `31549d1`.
> Прошивки и полные снимки исходников удалены из рабочего дерева; [восстановление](../../../README.md).


2026-10-01, Linux `sash@192.168.1.108`, UART `/dev/ttyUSB1`, 115200 8N1.
Пользователь закрыл picocom и разрешил прошивку. UART удерживал один проверочный
процесс; в конце он закрыл порт. Проверка `fuser` после закрытия не обнаружила владельцев.

На исходной JED 54D2 выполнен полный DIR загрузочного тома RT-11 XM.
Поздняя проверка состояния показала приглашение RT-11, а не ODT: `R 7`
получила `?KMON-F-File not found SY:7.SAV`, программа не запускалась.
Перед прошивкой выполнен ещё один свежий read-only DIR, завершившийся
приглашением монитора. Flash запрограммирована из этого состояния, без
дополнительного нажатия кнопки. SD-карта и её образы не менялись.

Контроль исходников/отчётов подтвердил сборку `terminal-throughput-50-03`,
генератор 12 МГц, ограничения CPU 50 / PAL 64 МГц и 26 EBR.
JED **C3DA**, SHA-256
`4ece4b79769e475eb0eea458c40343241ee0ee4031798aed32eee2bb48d90659`.
Diamond подтвердил `FLASH Erase,Program,Verify`, `Operation: successful.`
Получено свежее меню SD; таймер автозагрузки BSD отменён пробелом.
Выбраны контроллер 2 и unit 0: RT-11 XM V05.03 загрузилась с RH0.
Выполнены назначения VOL / BAS / PAS / FOR из STARTX.COM.

| Запуск | Полный DIR, с |
|---|---:|
| 54D2, исходный замер | 16,033363 |
| 54D2, непосредственно перед прошивкой | 16,033321 |
| C3DA, после загрузки RH0 | 7,415634 |
| C3DA, повтор | 7,415709 |

Вывод всех четырёх DIR **побайтно совпал**: 214 файлов, 5346 блоков,
48310 свободных блоков. Ускорение первого запуска C3DA — **2,162 раза**.
Замер выполнял одинаковый helper: 0,1 с на каждый вводимый байт команды,
опрос UART, 0,3 с после приглашения. Это время команды целиком при включённом
зеркале PAL, не отдельный замер скорости CPU или рендера.

Плата оставлена на приглашении RT-11, UART освобождён. Физический PAL
недоступен через захват UART: пользователю отправлен запрос проверить
появление чисел блоков/дат во время потока. **Визуальное подтверждение пока
ожидается**; автоматические проверки выше относятся к Flash и UART.
Повторные загрузки BSD / RSX / RT-11 V4 на C3DA не выполнялись.

`session-01` сохраняет исходное измерение и позднюю проверку состояния.
В нём есть одна ошибка декодирования JSON команды управления: неверное
экранирование регулярного выражения; эта команда не отправлялась в UART.
Исходное поле `passed=false` оставлено как значение шаблона UART-класса,
не как результат завершённого DIR. В `session-02` ошибок нет; `passed=true`
ограничено явно записанным `board_validation_scope`.

`uart.bin` — исходные байты UART, `uart.txt` — их читаемое представление.
`session.json` содержит границы/время команд и ответы. `programmer.log`,
`programmer-stdout.log`, `program.xcf`, `approved.json` сохраняют результат
прошивки. `programmer-old.log` — начальный заголовок, автоматически
переименованный Diamond при открытии финального лога.
Сохранены управляющие скрипты и их зависимости; это журнал фактически
выполненного запуска на Linux, с исходными абсолютными путями.

[result.json](result.json) повторно получен из этих файлов read-only
скриптом validate.py (`releases/hc7000-terminal-throughput/validation/hardware-20261001/validate.py`): сверяются JED, ответы команд с байтами
захвата, равенство DIR, завершение процессов и успешная Flash Verify.
