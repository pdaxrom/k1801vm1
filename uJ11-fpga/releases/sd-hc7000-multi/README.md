# HC7000: единая загрузочная SD с BSD, RSX и RT-11

Обновлено 2026-10-02 для установленной **7CBA**:
MMU / FPP off / FIS / SERV storage / PAL VT52 / PS/2, CPU/PAL 50/64 МГц.
Готовый файл — [uj11-hc7000-multi-os.img.gz](uj11-hc7000-multi-os.img.gz).
После распаковки **1 ГиБ**, архив **48 344 475 байт (46,10 МиБ)**.
Это единый воспроизводимый комплект из чистых дистрибутивных дисков;
пользовательские файлы работающей SD в него не включены.
Расположение всех 11 разделов совпадает с картой, установленной на плате.
Разметка ограничена первым 1 ГиБ и подходит для большей SD; это UJ11SD v1,
без MBR/FAT, с основной таблицей в LBA 0 и резервной в LBA 1.

## Состав и загрузка

После RESET меню ждёт пять секунд и загружает **BSD/RL0**.
Enter запускает её сразу; любая другая клавиша отменяет таймер.
Затем вводятся номер контроллера и unit:

| ОС | Контроллер меню | Unit | Дополнительные диски |
|---|---:|---:|---|
| 2.9BSD | **5 — RL11** | **0** | RL1 swap, XP0 `/usr` |
| RT-11 XM V5.03 | **2 — RH11/HK** | **0** | RH1 storage, RK1 BASIC, RK2 Pascal, RK3 FORTRAN |
| RT-11 SJ V04.00C | **1 — RK11/RK05** | **0** | — |
| RSX-11M-PLUS V4.6 BL87 | **4 — RQ/MSCP** | **1** | RQ0 системный том |

RQ0 содержит исходный незагрузочный блок: загружать RSX нужно с **RQ1**.
Для BSD на `70Boot` ввести `rl(0,0)rlunix`; затем Ctrl+D и вход `root`.
Для быстрого вывода консоли выполнить `stty nl0 cr0`.
Гостевой ОС на 7CBA доступны 1936 КиБ SRAM; 112 КиБ резервирует терминал.

| Диск | LBA | Секторов | Содержимое |
|---|---:|---:|---|
| RL0 | 2048 | 20480 | `bsd2.9/2.9BSD-root.rl02`, единственный `bootable` |
| RL1 | 22528 | 20480 | `bsd2.9/swap.rl02` |
| XP0 | 43008 | 500384 | `bsd2.9/2.9BSD-usr.rm05` |
| RQ0 | 1048576 | 311300 | `rsx11/rsxm11sys.dsk` |
| RQ1 | 1361920 | 311232 | `rsx11/rsx11mpbl87.dsk` |
| RK0 | 1673216 | 4872 | `rt11v400.dsk` |
| RH0 | 1679360 | 53790 | `rt11v5.3/system.dsk`, новые назначения и утилиты |
| RH1 | 1734656 | 53790 | `rt11v5.3/storage.dsk` |
| RK1 | 1789952 | 4872 | `rt11v5.3/basic.dsk` |
| RK2 | 1796096 | 4872 | `rt11v5.3/pascal.dsk` |
| RK3 | 1802240 | 4872 | `rt11v5.3/fortran.dsk` |

Все исходные байты BSD, RSX, V4 и дисков компиляторов сохранены;
неполные хвосты фиксированной геометрии дополнены нулями.
В системном диске XM изменены только назначения в трёх START-файлах
и добавлены шесть файлов: HGX.SYS, HGTIME.SAV, TMRATE.SAV, HGSYNC.COM,
XMCHK.COM и SDHELP.TXT. Загрузочные блоки и содержимое прежних файлов
сохранены, драйверы RKX/DMX не патчились.

`SY:` = DM0, `VOL:` = DM1, `BAS:` = RK1, `PAS:` = RK2, `FOR:` = RK3.
После загрузки XM: `TYPE SY:SDHELP.TXT`, `@XMCHK`.
HG и дата/время: запустить хостовый HG daemon, затем `@HGSYNC`;
автоматического обращения к хосту при загрузке нет.
[Подключение HG](../../docs/sd-image-hc7000.md#hg-и-системные-часы).

Для BASIC проверен `RUN BAS:BASIC`, выбор `A`, затем `PRINT 2+3`.
Pascal требует новой компиляции и линковки с `PAS:LIBEIS`:
[команды](../../history/releases/hc7000-sd-compilers/README.md#проверка-программ-без-fpp).
Исходный `SY:ADDER.SAV` требует FPP; после его аварийного запуска без FPP
нужно перезагрузить RT-11 перед редактором. [Причина KED Trap 4](../../docs/hc7000-terminal.md#rt-11-xm-ked-после-аварийного-pascal).

## Проверки

[Манифест](manifest.json) содержит исходные и итоговые SHA-256,
положение/размер каждого раздела и размеры нулевых хвостов.
`compiler_preparation` описывает промежуточные пять дисков до добавления
утилит; окончательные хэши находятся в `partitions`.

- Обе таблицы разделов совпали; CRC32 таблиц и CRC16 меню проверены.
  Меню **84ce** побайтно совпало с проверенным меню
  [SERV 19 КиБ](../../history/releases/hc7000-serv-19k/menu/result.json).
- Все 11 разделов прочитаны обратно и сравнены с исходными/подготовленными
  дисками. Дистрибутивные исходники не изменились.
- [Настоящий C-декодер SERV](validation/sd-label.json) принял обе таблицы
  для карты 1 ГиБ и большей карты; позиции разделов совпали с прежней физической SD.
- [Две независимые сборки](validation/reproducible.json) дали одинаковые
  raw-образ и gzip. Распаковка gzip дала исходный SHA-256.
- [SIMH на дисках, извлечённых из этого образа](validation/simh/result.json):
  RT-11 XM и V4 на **11/40 с FIS, без FPP**; RSX/RQ1 и BSD/RL0 на
  **11/70 без FPP**. В XM проверены назначения, HG-файлы, справка,
  BASIC `2+3=5` и новая компиляция Pascal с LIBEIS, также `2+3=5`.
  V4 прочитала каталог и V4USER.TXT; RSX прошла STARTUP и прочитала
  RSX11M.SYS (1026 блоков); BSD перешла в multiuser/root, смонтировала `/usr`
  и прочитала каталог и fstab. Общий SD-образ остался неизменным.

Модели SIMH имеют собственную память и периферию; это проверка содержимого
образа, а не новый прогон FPGA/PAL. Сам новый образ на физическую SD пока
не записывался. [Аппаратные проверки 7CBA на установленной карте](../hc7000-ps2-idle/README.md).
Первый сценарий ошибочно послал `SET SL OFF` в V4, где нет SL.SYS;
он сохранён как [неуспешная попытка](validation/attempt-v4-sl/result.json).
После исправления сценария полный повтор всех четырёх ОС прошёл.

## Распаковка, запись и воспроизведение

В каталоге этого релиза:

```sh
gzip -dk uj11-hc7000-multi-os.img.gz
shasum -a 256 -c SHA256SUMS
```

Записывается весь `.img` с сектора 0 на выбранную карту размером не меньше
1 ГиБ. Такая запись заменяет её прежнюю разметку и диски; сначала сохранить
нужные данные. Например, на Linux с проверенным именем устройства:

```sh
sudo dd if=uj11-hc7000-multi-os.img of=/dev/SD_DEVICE bs=4M conv=fsync status=progress
```

`/dev/SD_DEVICE` — заполнитель. Исходники сборщика обращаются только к новым
обычным файлам и не записывают физические устройства.
Прошивка SERV находится в FPGA; обновление JED не требует перезаписи этой SD.

Из `uJ11-fpga`, с новыми каталогами результатов:

```sh
python3 tools/build_sd_suite.py --out build/sd-suite-new
python3 tools/test_sd_suite_simh.py --image build/sd-suite-new/uj11-hc7000-multi-os.img \
  --out build/sd-suite-new/validation/simh
```

Нужны Python 3, C-компилятор для меню, готовый `lsi11/rt11tool` и исходные
диски в `lsi11/disks`. HG-файлы берутся из проверенного релиза с проверкой
хэшей и соответствия исходникам. Для проверки загрузок дополнительно нужен
SIMH `pdp11`. Сборщики HC1200 и прежнего raw XM-комплекта сохранены отдельно.
