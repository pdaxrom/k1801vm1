# uJ11 HC7000 — RT-11XM SD kit

2026-09-27. Готовый образ для `hc7000-lcd-sram`, профиль `CPU=mmu`,
SRAM 2 МиБ, система 24 МГц. Требуется исправленная прошивка
[`mmu-trap-modes-08`](../../history/releases/hc7000-mmu-trap-fix/README.md) или совместимая новая.

Файл: [`uj11-hc7000-rt11xm.img.gz`](uj11-hc7000-rt11xm.img.gz), 559 657 байт.
Распакованный raw RK07 — 27 540 480 байт / 53 790 секторов. Загружается
`DM0:RT11XM (S) V05.03`, 22-битная адресация, MEMTOP=10000000₈.

gzip -dk uj11-hc7000-rt11xm.img.gz
sha256sum -c SHA256SUMS

## Состав и использование

HGX для XM, HGTIME с установкой системных даты/времени, TMRATE, BASIC
single/double, числовые тесты и исходники утилит. DEC-файлы, инструменты и
библиотеки исходной V5.03 сохранены. `STARTX.COM` выводит приветствие;
справка доступна через `TYPE README.TXT` и восемь тематических `.TXT`.

Для HG запустить Linux-сервис `hgfsd --directory /path/to/shared --jtag-enable-adbus7`.
В RT-11 выполнить `@HGSYNC`: это `LOAD HG` и `RUN HGTIME`.
`DIR HG:` и `COPY` работают с каталогом хоста. Автозагрузка не ждёт HG-сервис.

[Полная инструкция, сборка и запись SD](../../docs/sd-image-hc7000.md).
`manifest.json` описывает состав и SHA-256, `directory.txt` — каталог,
`software/` — оригинальные результаты MACRO/LINK, листинги и XM boot blocks.

## Проверки

- Две независимые нативные сборки дают побайтно одинаковые raw/gzip.
- Геометрия, каталог, извлечение всех добавленных файлов, неизменность
  исходного FB-диска, DEC-файлов, home block и резервных 66 секторов проверены.
- SIMH 11/73, 2 МиБ, 50 Гц: холодная загрузка XM из конечного образа,
  чтение всех руководств, BASIC single/double (29 проверок и double-тест),
  восстановление после division by zero, negative square root и overflow,
  TMRATE/Q, запись/чтение/сравнение/удаление файла на SD и VM:.
- Полная RTL-модель CPU/SERV/SD/SRAM/UART исполняет этот же образ:
  загрузка XM, справка, LOAD/UNLOAD HGX, TMRATE/Q, SD/VM round trips,
  оба BASIC и возврат в READY после ошибок. Проверяется фактический доступ
  VM: к RAM выше 256 КиБ и UART по сигналам.
- HGX/HGTIME под реальным XM в SIMH: проверены `@HGSYNC`, повторный LOAD,
  успешный ответ и шесть ошибок — status, checksum, timeout, invalid date,
  day limit, high ticks. При ошибке системные дата/время не меняются.
  Только GPIO handshake/byte I/O подменены явно; службы отображения буфера
  монитора, обработка запросов, контрольная сумма и `.SDTTM` — настоящие.
- Физическая HC7000, прошивка 08, RT-11XM: HGX установлен, время/дата получены
  через настоящий FT2232; расхождение с хостом в проверке — 0 секунд.
  Текст прочитан с HG, файл 17 021 байт прошёл HG → SD → HG. Все байты совпали;
  до 17 408 байт добавлено только штатное нулевое дополнение RT-11.
  Тестовый файл с SD удалён, плата оставлена в XM, UART возвращён picocom,
  HG-сервис остановлен, JTAGENB освобождён с проверкой высокого уровня.
- Хостовый HG: 23 808 календарных случаев, 50/60 Гц, протокол и дисковая
  регрессия. Изоляция профилей: 8 тестов, 170 прежних файлов неизменны,
  старые образ FB и HG.SYS сохраняют контрольные суммы.

Журналы и результаты — `validation/`, сводка — `validation.json`.
`checksums.json` включает весь архив проверки. Образ физической SD целиком
не заменялся: на плате проверены именно выпущенные HGX/HGTIME, их SHA-256
совпадают с файлами конечного образа. Загрузка полного нового комплекта
проверена в SIMH и RTL.

RTL завершился с PASS: 28 552 проверки, 585 902 155 тактов, 592 344 DMA-слова.
Python-обёртка после этого остановилась на проверке собственного SHA-256:
во время прогона в неё были добавлены проверки UART-журнала. Исполненная
версия сохранена в `validation/rtl/executed-runner.py`; новые проверки
выполнены отдельно по готовому журналу. Хэши FPGA/ROM/IOP сверены с записью
начала сборки, образ не менялся. Это один завершённый RTL-прогон, а не
повторный запуск; причина и восстановление отчёта явно записаны в JSON.
Будущие запуски сохраняют входные хэши и копию скрипта до компиляции.
