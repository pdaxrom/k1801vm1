# CP68: управляющая часть FP11

Тестовый пакет для CP67b без MMU. **Арифметики FP11 пока нет**; поддержаны
CFCC, SETF/SETD, SETI/SETL, LDFPS R0–R7, STFPS R0–R7. Остальные FP opcode
формируют FEC=2 с учётом FID. [Полный контракт](../../../../docs/fp11-firmware-cp68.md).
На физическую плату этот пакет пока не установлен.

| Файл | Назначение |
|---|---|
| FP11.BIN | Самоинициализирующийся модуль ABI3, BASE 040000 |
| FP11.MAC | DEC MACRO-11 исходник модуля |
| FPTST.SAV / FPTST.MAC | RT-11 программа для STEP проверки SETD/SETL/STFPS |
| release.json | SHA256 и граница реализованной ISA |

Используется прежний [UJMOD.SAV CP67](../cp67/UJMOD.SAV). FP11 занимает
HALT `040000..041233`, включая данные и stack; образы абсолютные. Другие
модули не должны занимать этот диапазон, хотя checksum покрывает только код.

После копирования FP11.BIN на системный диск RT-11:

```text
.RUN UJMOD
UJMOD> STATUS
.RUN UJMOD
UJMOD> FP11
```

Длинный RESET без UART ESC проверяет checksum и активирует модуль.
В таблице после успешного cold init статус записи становится `140407`.
ODT и SDBOOT сохраняются; FPS и все AC инициализируются нулями при каждом
cold reset. В проверенном сценарии ODT/SDBOOT/FP11 заняли записи 0/1/2;
на существующей установке номер нужно брать из STATUS.

Чтобы выключить прототип, выполнить `OFFn` через UJMOD для его номера и
сделать длинный RESET. При неисправном модуле UART ESC в начальном окне
выбирает встроенный bootstrap и пропускает всю таблицу FRAM.

FPTST после сообщения CONTROL TEST останавливается в программном BR loop.
Войти в ODT коротким RESET, выполнить `R 7 1012`, затем три `S`: FPS проходит
значения `200`, `300`, а R1 получает `300`. Продолжение: `R 7 1022`, затем
`C` — программа печатает RETURNED TO RT11 и завершает работу. Это адреса
именно данного связанного FPTST.SAV, проверенные по MAP и UART regression.
FP disassembly ещё не добавлен в ODT: эти opcode отображаются как `.WORD`.
